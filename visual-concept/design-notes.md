# Coflow 官网设计整理

## 基本定位

- 产品：Coflow
- 类别：游戏数据配置工作流
- Slogan：高效无摩擦的数据配置工作流
- 核心特性：无摩擦、数据可信、深度 AI 融合

## 首页结构

### 首屏

- Coflow Logo 与导航
- Slogan
- 程序、策划、AI 三个角色汇入 Coflow，再交付到 Runtime 的工作流图
- 快速开始
- 下载 Release
- 支持浅色和深色模式

首屏不设计新的 Slogan，也不增加额外的品牌叙事。产品说明和链接以当前官网内容为准。

### 特性顺序

特性按实际工作流顺序排列，每项使用一张完整宽度的卡片介绍：

1. 三种入口汇入统一模型
   - 程序使用 CFT 精准定义类型、字段、引用、默认值和维度。
   - 策划使用 Excel、CSV 和 CFD 维护不同形态的数据。
   - AI 通过 CLI 和 Skills 查询、修改与检查配置。
2. 使用 `check` 约束数据
   - 在数据定义旁描述取值范围、集合关系和跨字段业务条件。
   - 规则统一作用于编辑、检查和构建流程。
3. 精准诊断
   - 诊断包含 code、stage、文件、工作表、单元格、记录 key 和字段路径。
   - 编辑器、人和 AI 使用同一套定位信息继续处理。
4. 多视图编辑器
   - 文件树、文档标签、表格、记录、关系图和详情检查器共享同一个项目模型。
   - 表格适合批量编辑，记录视图适合复杂结构，关系图适合追踪引用。
5. 实时检查与快速迭代
   - 编辑器将诊断投影到具体记录和字段，并在底部诊断面板汇总。
   - CFT 和 CFD 通过 LSP 获得一致的实时反馈。
6. 导出多种目标
   - 输出 JSON、MessagePack 和 C# 加载代码。
   - 完整构建成功后统一发布，失败不影响当前运行时产物。
7. 自定义前端插件
   - 接入团队自己的检查面板、可视化和批处理工具。
   - 支持项目级与全局安装，以及启用、禁用和移除。

快速开始和下载已经位于首屏，不再作为独立特性重复介绍。

## 三个角色的分工

| 角色 | 主要入口 | 主要职责 |
| --- | --- | --- |
| 程序 | CFT、`check` | 定义数据结构与业务约束 |
| 策划 | Excel、CSV、CFD | 维护游戏配置内容 |
| AI | CLI、Skills | 查询、修改、检查并参与配置协作 |

CFT、数据源和 AI 是同一个输入阶段的三个组成部分，不拆成互不相关的特性。

## 视觉语言

### 关键词

- 流动
- 汇聚
- 无摩擦
- 低阻力
- 务实、克制、可信

水流感来自连续、平滑、有方向的流动关系，不使用大量细线、装饰曲线或夸张液态效果强行表达。

### 主题色

- 程序：清水青，用于 CFT、`check` 和工程入口。
- 策划：柔和珊瑚，用于 Excel、CSV、CFD 和内容入口。
- AI：草木黄绿，用于 CLI、Skills 和自动化入口。
- Coflow：汇流青绿，用于统一模型、主操作、页面管道和交付状态。
- Diagnostic：独立诊断色，仅用于错误和阻塞。

三种角色色用于标明来源和分工。进入 Coflow 后收束为统一青绿，主题色需要贯穿导航、按钮、工作流、卡片状态、编辑器示意和交付结果，而不是只出现在 Logo 或首屏。

### Logo

- 表达三种角色的流动与汇聚。
- 三种颜色在汇聚处需要自然过渡，避免生硬碰撞。
- 减少细而锐利的线条，避免视觉扎眼。
- 小尺寸下仍应能辨认三路输入和统一输出。
- 不依赖额外装饰说明概念。

### 工作流管道

- 首屏必须清楚显示三条独立输入流，不能在进入 Coflow 前过早合并成两条或一条。
- 三条输入分别连接 Coflow 的三个入口，再由统一输出连接 Runtime。
- 动画应连续、缓慢、低对比，不能突然出现、跳回或在汇流处突变。
- 页面向下延伸的管道放在卡片侧面，只承担串联工作流的作用。
- 管道不能挤压卡片，所有特性卡片必须完整显示。
- 移动端同样需要保留三路输入的辨识度。

## 卡片与编辑器示意

- 每个特性使用一张完整卡片，桌面端可采用“说明 + 示例”双栏，移动端改为单栏。
- 卡片正文需要说明具体解决的问题、使用方式和结果，不能只有概念标题。
- 编辑器相关卡片复现真实 CFD Editor 的组件结构，而不是画抽象占位图。
- 多视图卡片包含文件树、文档标签、视图切换、数据表格和记录详情检查器。
- 实时检查卡片包含单元格诊断标记、底部诊断面板、错误 code 和跳转入口。
- 插件卡片包含扩展列表、名称、描述、来源、启用状态和移除操作。

## 排版与布局

- 控制标题尺寸，不使用过大的营销式字号。
- 标题、说明、代码和工具界面建立稳定且一致的层级。
- 正文保持适合中文阅读的行长和行高。
- 工具界面的缩略文字可以更紧凑，但必须可辨认，不能成为装饰纹理。
- 保持足够留白，同时减少没有信息作用的大面积空区。
- 卡片圆角克制，避免卡片嵌套卡片和无意义阴影。
- 桌面与移动端都不能出现文字、控件、卡片或管道重叠与横向溢出。

## 明确不采用的方向

- 不修改现有官网，示例独立放在 `visual-concept` 文件夹。
- 不新增 Slogan，固定使用“高效无摩擦的数据配置工作流”。
- 不单独制作官网大纲、目标、叙事等冗余页面内容。
- 不使用大量细线模拟水流。
- 不使用无实际信息的装饰元素。
- 不把卡片做成左右交错的半宽布局。
- 不让侧边管道占据卡片主要内容区域。
- 不使用概念化编辑器占位图代替真实产品组件。
