# 新 VM 布局、执行与快照测量（2026-09-20）

## 环境与口径

Windows，Intel Core i5-13600KF（14 核、20 逻辑处理器），rustc 1.96.0，.NET SDK 10.0.102，Lua 5.5.0，LuaJIT 2.1.1779665312。Rust 使用 Release、thin LTO、单 codegen unit。测量顺序执行，无并行构建或基准；吞吐负载保存 7 个样本，表内取中位数。

生产吞吐与测试分配观测分开：`vm_perf_probe` 不包含分配/派发计数；内部原生探针启用当前线程分配计数和 GC 时钟，因此它的构建时间与暂停包含观测成本，不作为生产吞吐结果。计数依赖只进入测试构建，生产无观测开销。固定专化、内联和临时值消除可能移走源码中的操作，不能将微基准结果泛化到全部动态计算。

## 实际固定布局与候选

65,536 行、每行 8 个 u32、128 轮；同一字段批量读取与每行读取全部字段分别测量。生产行包含身份、实际布局查找、类型解码；理想 AoS/SoA 直接读取 u32，因此绝对时间不能解释为仅切换行列布局的收益。通用引用候选包含 u64 标签单元与 usize 间接索引。

| 布局 | 单字段批量（ms） | 每行全部字段（ms） |
| --- | ---: | ---: |
| production_typed_rows | 54.4255 | 437.7884 |
| aos_u32 | 4.8395 | 28.1870 |
| soa_u32 | 3.4677 | 28.1365 |
| tagged_reference_u64 | 13.9256 | 35.6659 |

生产字段载荷 2,097,152 bytes，包含身份、布局及对象描述的分区容量合计 6,292,016 bytes；通用标签+引用候选载荷为 8,388,608 bytes。共享布局不包含逐行字段名副本。实际生产解码存在可见成本，不能用理想 AoS 数值宣称生产读取同样快。

| 可选 i32 候选 | 读取中位数（ms） | 载荷 bytes |
| --- | ---: | ---: |
| 生产独立标记 | 7.6209 | 327,680 |
| 独立位图候选 | 5.4192 | 270,336 |

首版冻结采用共享行布局、4 字节固定引用、独立可选标记和 8 字节执行槽。位图候选在纯读取探针更小且更快，但本探针未包含位图追加、删除、Host 混合字段及冻结路径；不将其当作完整替换方案已验证。独立标记让固定/动态可选数值共用保留完整位模式的载荷，实现无 NaN 哨兵、无数值 GC 边的统一读取与构造。原生数值和可选数值的空间分别为 4/4/1 与 5/5/2 字节；全 None 数组只存长度。

64 位定长指令与紧凑扩展编码的当轮完整程序体积、扩展比例和解码成本见 bytecode 原始表；首版采用定长编码。该对照改变指令存储，不改变附表、派发次数或语言操作，不能用解码耗时推导业务倍率。

16 组场景均断言释放结果并收集后动态存活值为零。实例保留空闲槽和索引容量用于复用，仍计入预算；实例释放才归还这些容量。GC 阈值为 `max(1024, 2 × 存活节点)`；集合和执行草稿扩容按至少两倍容量增长，增长前使用共享预算预留。循环预算批次 256，owner 专化和标量内联各采用每映像 65,536 条额外指令上限。这些是本轮压力验证的首版参数，不宣称对所有负载最优。

Debug/Release 差异代表整条优化流水线的组合效果，不能归因到某一 pass。禁止融合、逃逸或无法证明无 fault 的场景保留分配/派发；边界与代码预算见实现状态中的优化表。当前字符串累积和通用字段解码有明显成本，没有宣称达到 Lua/LuaJIT 的通用吞吐水平。

1,000 条相同 Hero 记录及 RuntimeSettings。普通属性预热后读取 1,000,000 次；结果、FFI 和分配计数均由探针断言。

原生测量直接加载同一生成 Contract、构建相同源数据；Contract、映像与实例释放后实测字节净值归零。native+managed 是两次匹配数据实验的存活量相加，不包含 FFI 句柄/传输缓冲、JIT、运行库和分配器驻留；进程 private bytes 才是进程层观测，不能据其差值精确拆分原生堆。UTF-8 转换包含在投影总耗时和托管分配中，未将其独立耗时伪报为零。释放后普通数据可读，Runtime 弱引用确认回收。
