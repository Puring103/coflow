# 新 VM 优化验收规格

本规格细化 [新 VM 实施计划](new-vm-and-csharp-snapshot.zh-CN.md) 第 8–11 节，冲突时以主计划为准。所有必需模式在本次交付中实现，以下范围构成可验证的优化完成标准。

## 统一判定规则

每项优化提供独立正例、拒绝反例及组合回归。正例在充足优化预算下必须触发；未知 effect、可能溢出、身份外泄和预算耗尽只有在确实存在对应条件时才构成合法拒绝理由。未实现所需分析、始终返回未知或关闭 pass 不满足验收。

测试使用同一新 VM 的 Debug、完整 Release，以及测试专用的单 pass 禁用/启用对照；测试开关不成为用户兼容入口。基础 lowering 始终执行。每项测试以独立语义 oracle 校验成功值、计算 fault 与 Host 轨迹，再检查 IR/程序结构和实际成本。不能只比较耗时或断言 pass 被调用。

测试构建提供优化命中及跳过原因、目标操作派发数、动态对象分配次数/字节的观测。成本断言针对目标表达式或指定对象类别，区分输出物化、参数导入和执行框架自身开销。各用例保留输入、profile、预算、测量范围及预期变化；正式性能报告另用无观测开销构建测量。

## 必需模式与拒绝反例

| 优化 | 必需支持模式 | 结构或成本断言 | 必需拒绝反例 |
| --- | --- | --- | --- |
| 常量/复制传播 | 类型化标量常量链、局部复制、各前驱提供相同常量的 phi | 使用点改为常量或原值；无多余 Move 和对应算术派发 | checked 中间溢出；按位不同的浮点常量；动态 Host 值 |
| 死赋值与 CFG 简化 | 被覆盖且无可观察行为的赋值、静态条件、不可达基本块 | 删除对应指令/块，重建全部跳转和附表 | 未使用但可能 fault、不终止或有 Host effect 的计算 |
| CSE | 基本块内输入 SSA 值相同的纯标量表达式；第一次成功后重复的 checked 表达式 | 同一表达式仅一次计算，第二处复用结果 | 输入重赋值；跨不支配路径；模板读取和身份创建 |
| effect 与调用删除 | 有限非递归直接调用图固定点；返回值未使用且无 fault/effect 的调用 | 可证明无可观察行为的调用消失 | 递归不终止、未知间接目标、HostRead、内容比较读取模板 |
| 去间接调用 | 已知函数字段、局部函数别名、合流后相同目标且绑定布局可确定 | 使用 CallDirect 与参数窗口，无动态函数查找 | 合流目标不同；owner/捕获不同而无法保持绑定 |
| owner 专化与固定折叠 | 固定 self 标量字段、多级固定记录路径、有效常量数组索引/字典 key、固定维度选择 | 指令使用立即数或固定引用，目标通用读取派发为零；不同映像专化独立 | 动态 Host 字段、动态 owner、无效索引、显式 None 被错误回退 |
| 部分求值 | 有限纯标量直接调用、固定输入的标量分支和有界循环 | 固定结果进入常量，运行时不执行目标计算 | 求值预算触顶；运行期 fault 提前；闭包身份被共享 |
| 内联 | 非递归直接标量函数，包含简单条件分支和多个返回点 | 目标调用消失，参数仅求值一次；返回/源码映射正确 | 代码预算触顶、递归、无法保持清理和捕获布局 |
| 范围分析与循环外提 | 单入口循环内，由常量界限或支配守卫证明安全的标量不变量 | 目标表达式每次调用最多执行一次，循环内无该表达式派发 | 零次循环中的潜在除零；checked 溢出；Host/模板读取 |
| 数组与 data 标量替换 | 固定形状局部 data/数组，只作已知字段/常量索引读取或更新，无身份或存储外泄 | 目标对象零动态堆分配，读取/更新改为标量操作 | 动态索引、返回/Host/捕获逃逸、无法保持自绑定及模板 effect |
| 闭包消除 | 局部创建并直接调用的标量闭包，捕获标量、无身份观察或逃逸 | 零闭包对象分配，捕获作为直接参数或标量使用 | 函数比较、返回、存储外泄、未知调用用途 |
| 静态模板与混合格式化 | 全静态文本、连续静态片段、动态标量插值、直线连接链 | Release 静态读取不进入 VM；动态格式化使用单一输出，无逐片段临时串 | 提前执行 fault 或越过 Host 调用；重复求值插值 |
| 循环文本累积 | 仅作为累积变量使用的局部字符串，循环中追加标量/文本片段，最终返回 | 循环不产生每轮完整前缀副本；使用可增长输出缓冲 | 中途保留旧前缀、捕获/Host 观察累积变量或未知别名 |
| 集合融合 | 纯、有限且无计算 fault 的相邻 map/map、map/filter、filter/map、filter/filter；纯 fold 终结这些流水线 | 中间集合零分配，最终物化至多一个结果缓冲；fold 无中间结果缓冲 | Host/模板 effect、checked fault 顺序变化、闭包身份观察、any/all 短路改变调用轨迹 |
| 尾调用 | 直接自递归尾调用及返回链，无待执行的 builder 清理 | Release 实际帧深度有界，不随递归次数增长 | 调用后仍需计算或构造清理；Debug 需要保留逻辑帧 |

表中分配消除允许保持语义所需的标量表示和元数据；不得以隐藏的逐值通用包装代替被消除对象。静态模板零 VM 与零目标分配属于 Release 性能要求；Debug 仍遵循关闭可选优化的规则。

## 组合、预算与验收

- 常量传播、CSE 和内联之后重建控制流与活跃信息，验证跳转到融合区域、多目的写入、寄存器重用及精确 GC 根。
- 固定 owner 专化与闭包消除组合验证多映像、不同 owner 和不同捕获；不得只按代码编号共享函数身份。
- 集合融合使用不会溢出的明确有界标量正例，另用 checked 算术故障与模板计数 Host 检查拒绝条件。fold 保持逐项左折叠顺序，浮点不重新结合。
- 正常预算用例与强制触顶用例分开；触顶须稳定停止该优化、保留合法计算并给出原因。有限预算外的任意程序不要求完成全程序最优优化。
- 单 pass 成本断言之外，再运行整条 Release 的语义差分和 GC/重入压力用例。每行正例、反例、结构/成本断言及组合验证全部满足才算完成，最终映射到主计划 V24。
