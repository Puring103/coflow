## 1. 目标与规范适用范围

固定配置在映像构建期完成解析、链接和可证明安全的计算。执行器只处理动态输入、必要计算、动态结果和外部交互。

语言采用不可变共享数据、可变局部绑定、受控局部构造和显式 Host 边界。保留单一 `var` 声明、循环、赋值和提前返回，不引入 `let`、Monad、惰性求值或通用借用系统。

本计划定义完整实现目标与统一验收要求。实施时以 `docs/1-语言/` 的现行语义为基础，按本计划提供局部构造能力及新 C# API；内部架构文档与本计划同步。

新 VM 的设计与验收以本计划为准。配套的局部构造、C# 快照 API 和优化验收规格细化本计划；语言及架构文档与本计划存在冲突时，采用本计划的规则，并在同一次交付中同步相关文档。

最终性能契约：

- 固定字段不逐值分配 `Arc<Value>`，固定读取不借用动态堆。
- 静态调用直接访问程序编号，不查动态函数对象。
- 已知标量使用立即数，固定复合值使用数据区引用。
- Release 全静态模板不执行格式化，混合模板合并静态片段并直接输出；Debug 按第 14 节保留调试执行语义。
- 满足 [优化验收规格](new-vm-optimization-acceptance.zh-CN.md) 必需模式及证明条件的临时对象、闭包和集合不分配。
- 普通 C# 配置读取不跨 FFI。
- 私有已验证映像在执行期不重复验证程序结构。

交付内容包括类型化 Contract IR、CFG/SSA 与 effect 分析、独立且不可伪造的执行映像、紧凑类型化固定区、专用调用协议、局部构造语义、格式化计划、集合融合、精确引用映射、C# 数据投影与配套生命周期。

直接删除被替换的执行器、接口、格式读写和依赖代码；产物通过新工具重新生成。交付仅包含新体系，不设置旧版本兼容分支、转换适配层、双执行路径或切换开关，计划内工作全部完成，不遗留临时实现、待清理代码或推迟到后续版本的缺项。

## 3. 语言语义与不变量

### 3.1 类型、数值与相等

- `int` 为 checked i32，`float` 为 IEEE binary32；保留现行 int 到 float 提升及显式转换规则。
- 编译期求值与 VM 使用相同的数值、枚举、字符串和转换语义。
- 不使用改变浮点结合顺序、NaN、正负零等结果的 fast-math。
- 整数重排不得绕过中间溢出。例如 `(x + 1) - 1` 不因最终数学结果相同而自动化为 `x`。
- 数组按顺序比较；字典按 key/value 比较，枚举仍保持声明顺序。
- data 按实际类型与字段内容比较；记录按实例身份与记录编号比较。
- 函数复制保留身份；同一闭包表达式每次实际创建产生不同身份。
- data/集合比较如会读取 fstring，必须传播模板 effect；不能因引用相同就省略可能有动态行为的内容比较。
- None 与零、false、空集合不同。类型化可选布局不能损失这个区别。

### 3.2 局部赋值与共享不可变性

`var` 允许重新赋值，类型固定；参数、self、捕获绑定只读。闭包捕获创建时的值，不捕获可变变量单元。局部赋值不改变输入对象，不自动使函数成为外部有副作用的函数。

table/singleton 只能在映像构建阶段建立，执行期禁止创建、删除、改 key 或改字段。普通 singleton 遵循数据完整性规则；Host singleton 是绑定能力，不能由用户 CFD 构造。数据可由 CFD 或核心内存构建 API 提供，不强制所有记录手写于文件。

data、数组、字典可动态构造；发布后的普通值传递性不可变。局部构造只创建已声明类型的实例，不支持运行时增加类型或字段。

### 3.3 局部构造作用域

增加面向用户的局部 data/数组/字典构造能力，采用显式构造作用域，正常结束时自动冻结并产生普通不可变值。拼写为 `build Type as b { ... }` 与 `build (value) as b { ... }`，通过字段/索引赋值、`append` 和 `remove` 修改；完整文法见 [局部构造语法](local-build-syntax.zh-CN.md)。builder 是内部能力类型，不是用户泛型系统。

- 可创建空集合、初始化对象，或从已有不可变值创建修改版本。
- 支持类型正确的字段写入、元素更新、追加和删除。
- 可写能力不能复制、捕获、返回、传给普通函数或 Host，也不能存入普通对象/集合。
- 禁止可写别名及通过赋值转移 builder 绑定，由类型检查保证；普通不可变值仍可自由复制和传递。
- 构造能力限制在一个构造作用域内，不支持跨函数 builder 参数和返回值。
- 必填字段在所有到达冻结点的路径上完成初始化；未初始化字段不可读。
- 冻结消费 builder；后续不能写入，也不能通过旧别名访问可写缓冲。
- 外层 builder 不赋予嵌套普通值写权限；嵌套修改显式构造并替换子值。
- 修改记录引用字段只替换引用，不修改记录。
- fault、return、break、continue 穿过作用域时执行资源清理。

从共享连续数组产生可写版本可能需要 O(n) 复制；对象可复制字段并共享不可变子对象。只有证明独占的动态存储可以复用，固定区永不转成可写缓冲。冻结应转移缓冲所有权，通常 O(1)，不强制缩容。

对象内函数或模板字面量可以在构造期建立新对象 self 绑定，但完整初始化并冻结后才允许执行，构造期间不得调用或向外暴露这些绑定。绑定闭包形成的引用环由发布流程和 GC 正确处理，不能笼统假定动态值无环。

`build Type` 在进入构造体前应用声明默认值，无默认值的可选字段初始化为 None，无默认值的数组和字典初始化为空集合，其余字段保持未初始化；集合构造目标从空集合开始。`build (value)` 对输入求值一次，保留实际类型及已有函数/模板身份和绑定。向 data builder 字段直接写入的新函数/模板字面量绑定正在构造的新对象，普通右值表达式仍使用外层作用域。初始化分析、未发布绑定隔离、复制与正反例完整规则见 [局部构造语法](local-build-syntax.zh-CN.md)。

## 4. 三分区和核心对象

```text
CFT → Contract（类型、声明、类型化 IR）
                          + CFD / 内存输入
                          ↓
             数据构建、链接、专化、优化、验证
                          ↓
                    RuntimeImage
                  ┌───────┴───────┐
                数据区          程序区
                不可变          不可变
                  └───────┬───────┘
                          ↓
                   RuntimeInstance
           Host、动态堆、外部句柄、实例身份
                          ↓
                       Execution
             寄存器、帧、预算、显式上下文
```

| 对象 | 所有权与职责 |
| --- | --- |
| Contract | 可复用语义产物；不含当前 CFD 的地址、记录实例或最终 VM 程序 |
| RuntimeImage | 拥有固定数据和已验证程序；发布后不变；可被多个实例共享 |
| RuntimeInstance | 拥有 Host 绑定、动态值、句柄表；提供实际执行边界 |
| Execution | 一次顶层调用及同步重入链；拥有帧、寄存器、临时根和共享预算 |
| C# DataSnapshot | 同一映像的托管只读投影；不解释语言、不编译或解析 CFD |

静态定义用类型安全的 TypeId、FieldId、FunctionId、LayoutId 等区分，不能混用裸整数。固定引用只在所属映像内有效；动态句柄属于实例。内部标量/引用与外部带身份的句柄分层。

实例固定在创建线程执行，支持同线程同步重入，不支持线程迁移或不同线程轮流执行。不可变映像可跨实例共享；`!Sync` 只限制共享访问，不等同于创建线程亲和性。C ABI/C# 层必须独立校验线程和管理重入，不能依赖 Rust 类型约束保护外部调用。纯托管不可变数据的读取不受执行线程限制。

## 5. Contract 与构建流水线

### 5.1 Contract 编译

完成声明、类型、继承、函数签名、函数体、模板和 check 的语义检查，生成类型化 IR、绑定符号和源码映射。无效且未使用的 CFT 函数仍报错；未使用只影响最终代码生成，不影响合法性。

保留创建位置 owner、原始函数身份、捕获信息和 fstring 声明类型。原始源码用于工具，执行只依赖 IR 和必要映射。Contract 格式版本化，但不携带可执行字节码。

### 5.2 映像构建

1. 验证 Contract 格式、资源界限及解码后 IR 的结构不变量。
2. 加载 CFD，补齐默认值并检查类型。
3. 先分配所有记录身份，再连接引用，允许配置引用环。
4. 分析 CFD 函数、模板，选择覆盖或默认实现。
5. 建立实际类型布局、记录查询索引和维度存储。
6. 链接全部静态引用，包括未执行分支内必须合法的引用。
7. 完成调用图和 effect 分析，进行部分求值及优化。
8. 生成程序、常量、格式化计划、调用描述、GC 和诊断映射。
9. 验证整个映像，一次性发布。

构建不调用 Host，不运行 check，不读取动态模板。可证明纯且安全的模板部分可以求值。缺失 Host 绑定允许构建，实际使用时报错。

相同 Contract 支持多个不同 CFD 快照，任何数据绑定不得写回 Contract。缓存键包含契约身份、完整数据依赖、编译器/布局版本和 profile。旧快照保持可用，新构建失败不能污染旧快照。

### 5.3 加载和产物边界

默认宿主入口仍可通过 Contract + CFD 构建映像，不以本计划自动新增公开二进制数据导出命令。C# 的批量投影是运行时传输协议，不是新的用户数据格式。

可序列化 RuntimeImage 或离线缓存属于可选扩展，另行确认交付范围。摘要用于完整性/缓存，不证明输入可信或内存安全；无论来源，进入执行器的私有映像都必须满足验证不变量。

## 6. 固定数据布局

采用类型化记录表、对象区、集合区、字符串区及独立身份/查询索引。固定区整体拥有，不逐字段引用计数。

| 内容 | 布局 |
| --- | --- |
| i32/f32/bool/enum | 原生紧凑载荷，类型来自布局 |
| string | 共享 UTF-8 区的范围或编号 |
| 记录 | 实际类型表编号和行号，或等价紧凑记录索引 |
| data | 实际布局与字段载荷，递归内容使用间接引用 |
| 数组 | 类型化元素缓冲的起点、长度 |
| 字典 | 有序条目加查询索引，索引不复制 value |
| 可选值 | 有效性位图/标记及类型化载荷 |
| 函数 | 原始身份描述、程序编号、必要 owner/环境 |
| fstring | 原模板绑定及静态文本/格式化计划 |
| Host | 服务/成员描述，不存可折叠的实时返回值 |

AoS/SoA/混合布局通过单记录多字段和批量单字段基准选择。按类型紧凑存储是目标，全部列式不是预设结论。bool 位图、短索引压缩也需证明整体收益。

类型提供解释方式，引用提供位置。FieldId 在实际 LayoutId 下映射到偏移或列；已知实际类型时消除映射。不能假定不同列式子类型有统一字节偏移。

记录 key 唯一性和父类型查询域沿用继承规则。静态引用按声明作用域解析，不因实际 self 子类型重新绑定。记录身份不按内容去重；普通内容共享需考虑 NaN、模板读取和函数身份语义。

## 7. 维度与模板值语义

维度保存在业务字段中，含 default 和显式变体映射，不创建辅助配置记录。未知或缺失变体回退 default；可选字段的显式 None 是有效覆盖，不回退。投影保留“缺失”和“存在且 None”的区别。

变体目录按现行规则从全数据模型汇总、排序。需要查询显式覆盖时保留存在性元数据，不能仅保存回退后的结果。固定选择可以折叠，动态变体名保留选择操作；不引入隐式可变的全局语言选择器。

fstring 保持两种操作：获取原模板与普通读取为文本。期望 fstring 的传递、返回和保存不求值；普通读取按语义执行。编译器在 IR 中明确区分，GC、复制和 C# 投影只走原始存储，不触发模板。

filter 判定读取模板但结果保留原模板；map 依回调返回类型保存文本或模板；any/all 保持短路。保持 owner、捕获、读取次数和左到右插值顺序。

## 8. IR 与优化证明

类型化语义 IR 降低为 CFG/SSA，局部赋值转为版本值和循环 phi。语义 ID 与布局/寄存器编号分开，先优化后分配寄存器。

分析属性不是互斥的单一 Pure 枚举，而是可组合信息：HostRead、HostEffect、上下文依赖、MayFault、MayDiverge、Allocates、IdentityObservable，以及读写局部构造区。

通过调用图固定点传播，递归强连通分量保守处理。未知函数参数调用采用保守 effect；确定目标后细化。局部 builder 写入不自动等同于外部副作用。结构比较可能调用模板，必须纳入分析。

实施优化：常量传播、复制传播、死赋值消除、不可达代码与 CFG 简化、安全 CSE、内联、去间接调用、循环不变量外提、范围分析、标量替换、闭包消除、尾调用及集合融合。

必要约束：

- 不把可能 fault 的表达式外提到原本不执行的路径。
- 不删除可能不终止的计算，仅因结果未使用不足以证明可删除。
- 不改变 HostRead 的次数或与其他 effect 的顺序。
- 不改变 checked 中间溢出及浮点运算次序。
- 不合并可观察的闭包创建身份；无捕获不等于可以全局共享身份。
- GC、结构比较、字典语义与调用绑定不得因常量化而改变。

优化预算耗尽时停止该优化并保留合法动态计算；实际发现的语法/类型/链接错误仍必须报错。静态求值遇到运行期 fault 时，保留原执行位置的计算或 trap，不把不可达表达式的 fault 提前变成构建错误。

每项优化必须满足 [优化验收规格](new-vm-optimization-acceptance.zh-CN.md) 中的必需模式、拒绝条件、结构或成本断言以及语义反例。预算充足的必需模式不能以未实现分析或保守处理代替实现；优化预算触顶须给出可观测的原因。

## 9. 部分求值与可达性

固定记录、固定 self 字段、引用链、标量运算、集合长度/索引、字典固定 key、静态分支及符合条件的纯调用可提前计算。

标量内嵌到指令；字符串放共享数据区；不可变复合结果放固定区；字节码只计算剩余动态部分。代码不可变本身不能证明输入固定，动态参数和调用上下文仍需保留。

函数特化按函数、固定参数、owner、profile 等缓存，设置数量、代码体积和编译成本限制。公共泛化实现服务动态参数，避免每条记录都复制全部函数。

可达根包括宿主可调用函数、数据内一等函数、模板、check 和所有可能的间接目标。先完成全部语义和必要引用合法性检查，再裁剪最终机器无关程序；不能误删宿主入口。

## 10. 字符串与集合降低

### 10.1 格式化计划

全静态模板产生固定文本；混合模板生成合并后的 Text/Int/Float/Enum 等片段计划。复杂插值先生成必要计算。每处插值只求值一次，格式转换可能 fault 时不能延后越过后续 Host 调用。

直接向一个输出缓冲格式化，静态长度提前计算、动态长度用于容量预留；避免每个数值先创建临时字符串。长度计算检查溢出并服从内存上限。编译期与执行期使用相同文本格式规则。

普通连接链使用同一输出机制，循环累积仅在别名、使用和 effect 条件满足时转为字符串 builder。模板折叠不改变声明类型、公开 API 和原始模板工具信息。

### 10.2 集合处理

map/filter/fold 降为类型化循环，安全时融合。最终需要物化的结果使用预分配 builder，未知长度采用受限增长策略。临时集合可标量替换或彻底消除。

`map(f).any(p)` 融合会减少 f 的调用；`map(f).sum()` 融合会把累加 fault 与后续 f 交错。因此无 Host 也不能直接视为安全，必须满足终止、fault 和身份条件。

字典保持插入/声明顺序和键相等规则。builder 写入不存在的 key 时追加到末尾；写入已有 key 时覆盖 value 并保留原位置；删除后重新插入放到末尾。字面量重复 key 仍按现行规则报错。

## 11. 程序区、字节码与调用

程序区拥有函数表、指令、操作数/调用附表、布局访问描述、格式化计划、捕获布局、GC maps 和 source maps。没有宿主地址、当前实例句柄或未解析的记录名称。

原型编码采用 64 位定长字，逻辑格式为 opcode:8、flags:8、A/B/C 各 16 位；不同操作解释 BC 为 32 位立即数或索引。完整三操作数加 32 位立即数使用描述表或扩展形式，不能硬塞不够的位宽。编码内部化，不作为 C ABI；最终编码在测量派发、代码体积和解码成本后冻结。

原型寄存器采用统一 64 位槽；标量直接存值，复合值存引用。可选标量等需要独立有效性位或多槽布局，不能占用合法数值充当 None。类型来自验证信息，不重复保存通用 Value 标签；未知的固定/动态来源及实际多态类型仍要可区分。最终槽位、引用标签与扩展形式和指令编码一起实测冻结。

| 类别 | 指令能力 |
| --- | --- |
| 标量 | 常量、Move、类型化数值/位运算、显式转换、立即数运算 |
| 控制流 | Jump、条件/比较跳转、Option 分支、Return、Trap |
| 固定数据 | LoadFixedRef、类型化列/字段访问 |
| 动态数据 | 类型化对象/元素读取、长度、字典查询 |
| 调用 | CallDirect、CallClosure、CallHost、TailCall |
| 构造 | Begin/Write/Append/Remove/Freeze，仅接受 builder 能力 |
| 字符串 | FormatParts、ConcatParts |
| 外部依赖 | ReadHost、明确维度选择 |

CallDirect 使用 FunctionId 与参数窗口，owner/环境布局由调用描述确定。参数直接放连续窗口，处理递归、重叠参数移动和返回值布局；不得以扩容后失效的裸地址跨调用持有窗口。

函数值的语言身份与代码目标分开；同一程序绑定不同 owner 不是同一函数。静态调用不必物化函数值，只有实际作为一等值使用时才建立必要表示。

新增 superinstruction 以 profiling 和派发计数为依据。不要为所有类型、存储来源和操作数形式展开笛卡尔积指令集。

## 12. 私有验证器与安全边界

编译中间表示与最终 ValidatedImage 使用不同类型，后者不能被外部构造或修改。验证：控制流、寄存器初始化与类型、参数/返回布局、附表边界、固定引用、闭包捕获、构造器完整初始化与不逃逸、GC maps、诊断映射及无未解析符号。

寄存器重用后 GC map 必须按 safepoint 描述真实引用槽。不能按整函数静态寄存器类型猜测。无效 opcode、静态槽位、签名和附表检查可以前移，但外部动态输入校验不能取消。

进行指令删除/融合时由 CFG 重新线性化，统一重建所有跳转与附表目标。若需要 unsafe 读取，先写清验证不变量并进行畸形输入与边界测试；不以去检查为理由扩大未定义行为面。

## 13. 动态堆、逃逸与 GC

固定区/程序区整体释放，不参与 tracing。标量和可消除的局部对象放寄存器。builder 独占资源按作用域清理，其持有的动态引用仍必须进入 GC 根。

逃逸指对象可在创建函数返回后被访问，包括返回、嵌入返回对象、返回闭包捕获及 Host 保留。普通局部赋值不构成逃逸。返回固定引用不需要复制固定数据。

采用精确非移动标记清扫动态堆及稳定句柄，支持可能形成的对象/闭包环。内部布局区分引用与标量；纯数值数组无需逐元素扫描，固定引用不继续追踪。

GC 根包含活跃寄存器、暂停帧、owner、捕获、构造缓冲、Host 调用临时根和外部保活句柄。分配、回调及重入使用明确 safepoint。根发布优化必须证明重入和新增临时值不会漏根。

不逃逸不代表无需回收：长循环中反复生成的字符串仍可能在动态堆中，不能把全部临时值积累到请求结束。只对生命周期有界且内存上限可证明的部分采用临时区，其余正常 GC。

通过消除分配、类型化载荷、缓冲转移和精确根扫描降低 GC 成本，完整实现精确非移动标记清扫与稳定句柄。

## 14. Host、预算、fault 与 check

Host 是外部能力接口，不引入 Monad。编译器推导 effect，不要求用户标注 IO 类型。HostData 每次按语义读取，除非未来显式声明并定义快照协议，否则不缓存或常量折叠。

Host 调用验证服务、参数、返回类型及实例归属，转换异常；同步重入共享外层预算和保活根。Host 阻塞无法由 VM 计数器强制中止，预算只限制 VM 可控制的工作。

算术/索引等计算 fault、Host fault 和资源 fault 分类。预期缺失用已有 Option，不引入 Result 或语言内异常捕获。

Debug 保留精确求值位置和逻辑栈；Release 保留错误类别、函数和必要范围，允许压缩映射。诊断精度降低不授权改变成功结果或 Host 轨迹。保持计算 fault 顺序。

Debug 关闭可选优化，包括内联、部分求值、融合、CSE 和尾调用消帧，保留源码求值顺序与逻辑调用帧；类型检查、必要降低、符号链接、布局生成和映像验证仍执行。Release 启用已通过语义验证的优化。两个 profile 使用同一数值与基础操作实现，避免形成两套语言语义。

预算按循环/集合元素、调用和分配等工作量批量结算，初始循环批次可用 256。明确容差适用对象：多帧/重入必须共享或边界结算，不能把每帧 255 次超额错误描述为全请求 255 次。HostRead 也可能重入，不能只在 CallHost 结算。

内存、寄存器和深度硬限制在分配/入栈前检查；优化前后预算失败点不要求一致。尾调用和内联会改变实际帧成本，需要把深度定义为执行资源上限，不作为优化无关语言计数。

check 显式执行、不参与映像可用性、不缓存结果。require 通过普通 Host 边界报告；单个 check fault 后继续其他规则，总预算耗尽报告未完成。消息参数遵循原求值规则，不因条件为真就跳过。

## 15. C# 只读数据快照

### 15.1 权威性与批量投影

Rust 负责解析、类型检查、默认值、引用、维度和优化。C# 从已验证映像批量接收固定原始数据，建立类型化只读图，不解析 CFD、不复制语言执行器。

投影可以在映像构建后立即进行。使用长度明确、版本化、具备 schema/映像身份的类型化批量协议；不能把 Rust 内存布局或裸指针直接当作托管 ABI。检查长度、范围、类型编号、UTF-8 和总体分配上限。

先建立所有记录身份，再连接字段，支持循环引用和实际子类型。字符串一次转换为托管文本；字典顺序、enum 位值、None、浮点值和维度存在性完整保留。

投影读取原存储，不执行 getter、模板、Host 或内容比较。C# 内部数组不得作为可强转的可写数组暴露；只读接口必须配合实际不可写封装。

### 15.2 公开 API 形态

公开 API 采用普通数据属性、函数方法、显式 Render 和独立的一等函数值入口。以下展示目标形态，具体生成名称及冲突消解规则见 [C# 快照 API](csharp-snapshot-api.zh-CN.md)。API 按 schema 声明稳定，不依赖某次折叠是否成功。

```csharp
using var config = GameConfig.Build(contractBytes, sources, hostBindings);
var sword = config.Weapons["sword"];
int damage = sword.Damage;                       // 本地数据
string material = sword.Material.Name;          // 本地记录连接
bool found = config.Weapons.TryGet("axe", out var axe);
foreach (var weapon in config.Weapons) { /* 本地遍历 */ }
int gold = config.GameSettings.StartingGold;
int result = sword.CalculateDamage(level: 10);    // VM 调用
string label = sword.RenderDescription();       // 显式模板执行
string localized = sword.NameByLanguage.For("ja");
```

表提供 Count、索引器、TryGet 和稳定遍历；查找失败与执行 fault 区分。singleton 为入口属性。数组/字典为真正只读的类型化集合，data 使用生成不可变类型，`@struct` 保留只读值类型映射。

函数字段生成便利方法；需要取得函数值时另有明确入口，保留一等函数的复制/比较/传递能力，不能因方法化丢失。可选函数、函数数组、fstring?、fstring 集合、维度化模板和函数均需要生成明确包装。

C# 模板使用 Render 方法或模板包装的 Render；Coflow 源码普通 fstring 读取仍按原语言自动求值，两者是不同层的接口约定。纯静态模板内部直接返回缓存文本，但保留同一方法形态。

维度 Default/For 提供与 Rust 一致的回退；TryGetVariant（若公开）表示显式覆盖存在性，存在且 None 返回成功。模板维度选择不提前 Render。

Host 生成类型化接口和静态适配器，无反射、动态代码生成或用户填写成员编号。未绑定行为沿用延迟错误规则。

### 15.3 身份、动态结果与释放

记录包装携带隐藏实例身份及 RecordId，语言/宿主记录相等保留实例边界。即使两个实例共享映像，也不默认允许记录/函数跨实例混用。普通属性可离线读取不代表该记录可以传给任意实例。

GameConfig 作为生命周期门面：Dispose 后已完整物化的普通 C# 数据可继续读取，VM 调用、动态模板、依赖 VM 的内容比较和函数包装明确失败。纯托管投影不可持有会在释放后被读取的原生裸地址。

普通动态 data/集合/字符串返回值可物化为托管只读结果并释放临时保活；但包含闭包、动态模板或绑定 self 的函数时必须保留相应 native 环境。按返回图分类，不能无条件释放整张 native 返回图。

生成的不可变 data 类型提供公开构造入口，允许 C# 创建 data 和类型化只读集合，并作为 VM 参数或匹配签名的 Host 返回值。构造时复制或取得安全的独占缓冲，不保留外部可变集合别名；完整初始化后发布。记录、函数和动态模板执行能力只能来自实例，不能用公开构造器伪造。

托管 data/集合传入 VM 时使用生成的类型化导入协议，既支持新建值也支持 VM 返回结果回传。按声明校验实际类型、必填字段、可选值、集合内容及资源限制，递归验证记录/函数引用的实例归属和有效性；纯内容值可在不同实例重新构建，包含执行能力或记录引用的图受实例约束。不接受绕过生成协议的任意对象或反射导入，不允许创建 table/singleton。

函数/模板包装共享实例生命周期及内部拥有型 lease，不向用户提供逐值 Dispose。包装存活且实例未显式释放时，保活实例和自身所需的动态环境；包装不可达后允许回收相应外部根。实例显式 Dispose 统一使所有执行能力失效并释放原生执行资源，不等待包装全部消失。普通记录和纯数据无需逐个 Dispose。

全部原生资源归创建线程所有，包含 Contract、Builder、Runtime、声明编译器、缓冲和 lease。拥有型资源由创建线程显式释放。动态投影通过弱引用登记，托管 GC 后的下一次请求在创建线程回收 lease；Dispose 和 Shutdown 统一释放其余资源。

#### 15.3.1 显式释放与活动调用

实例状态为 Open、Executing、Disposed；Executing 包括外层暂停帧、Host 回调、同步重入及依赖实例的参数导入和结果投影。最外层边界在所有正常或错误清理完成后恢复 Open。显式 Dispose 仅允许创建线程在 Open 状态执行；Executing 状态返回 RuntimeBusy，保持实例、句柄和托管门面完整，不排队、不提前标记失效。Host 可以处理该错误后继续回调；未处理时按 Host fault 传播。Rust 和 C ABI 独立检查，C# 将 RuntimeBusy 映射为 InvalidOperationException，只有原生释放成功后才能清空托管句柄。成功释放后再次 Dispose 为无操作；未释放实例的异线程 Dispose 返回线程错误。

活动边界强保活门面、Host 适配器和本次使用的 lease。执行边界退出和资源释放均在创建线程串行完成。

#### 15.3.2 创建线程资源域

线程本地句柄表登记全部原生资源，唯一句柄身份由全局原子计数分配。资源状态、登记和释放无需锁。

- `RuntimeThread.Shutdown()` 要求没有活动边界，否则返回 RuntimeBusy 且不改变状态。成功时阻止重入登记并释放全部资源，旧托管句柄通过线程域代次判定失效。
- 重复关闭为无操作；再次创建实例使用新代次。创建线程退出清理本地登记。释放与 Host 上下文清理在句柄表借用之外完成。
- Contract、Builder 和 Runtime 均由创建线程通过 `using` 或 `Dispose()` 释放；Unity 和其他宿主在正常退出及域重载前显式 Shutdown。
- Runtime 弱引用跟踪动态投影；托管 GC 后的下一次 Runtime 请求回收不可达投影的 lease，Dispose 和 Shutdown 释放剩余 lease。

验收覆盖全部句柄的异线程拒绝、创建线程退出、重复释放、关闭后旧句柄失效、关闭期间析构重入登记拒绝，以及活动执行中的 Dispose/Shutdown 拒绝。

不把可能执行模板的语言内容相等隐式放入 C# GetHashCode。记录相等/哈希可本地使用身份；data 的纯本地相等与需要 VM 的语言内容相等必须区分并文档化。

### 15.4 更新与线程

新 Rust 映像和 C# 投影均成功后成对发布；投影失败释放候选资源，不替换旧门面。旧托管数据继续可读，旧执行能力在旧实例释放前继续有效。跨代调用必须拒绝。

不可变且纯托管的属性可支持跨线程读取；VM 方法仍服从实例执行线程规则。包装不得含无同步惰性缓存，发布需使用宿主正确的内存可见性机制。

本地投影增加托管堆、加载成本和双份数据；不承诺零复制或所有场景更快。测量 IL2CPP/Mono 可用目标上的本地访问、构建、UTF-8 转换、跨边界调用和峰值内存。本计划采用完整托管只读投影。

## 21. 完成交付的判定

架构成立的基础是不变量分层：Contract 保证语义类型，映像验证器保证静态执行布局，运行边界保证动态输入和资源约束，C# 投影保证相同快照的只读数据一致性。

正确性验收必须覆盖固定/动态存储区别、实例身份、模板读取 effect、闭包身份、维度显式 None、builder 根、重入、短路、数值 fault 和托管结果中的执行能力。上述条件必须成为实现验收，不得仅作为注释。

实现不依赖通用逃逸分析完全成功、不依赖动态图无环、不依赖所有局部值请求结束统一释放、不依赖无捕获闭包可共享身份，也不依赖摘要能证明字节码安全。

全部实现须通过工作区 Rust 门禁、V01–V24 语义/生命周期与优化反例、C# 类型化投影、Unity Mono/IL2CPP 独立播放器及原生分配/GC 探针验收。builder 文法、C# API 与优化验收遵循配套规格；参数依据和性能报告须反映实际成本与优化适用边界。旧代码、兼容入口和失效依赖全部清理，生成物、示例和文档全部同步后，方可认定完成交付。
