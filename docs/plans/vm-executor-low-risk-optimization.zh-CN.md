# VM 执行器低风险优化计划

## 目标与边界

本计划继续缩小新 VM 与原生执行及 Lua 解释器在标量循环、集合读取上的固定开销。实施范围限于执行器内部表示、已验证程序的读取方式和预算扣减方式，不改变语言语义、错误顺序、预算口径、公开句柄身份、GC 根规则、Host 重入规则或 Debug/Release 的结果。

每项独立落地并保留可单独测量的基准。实现不引入组合多种语言操作的巨型指令；字节码继续表达语言级操作，执行器优化其读取和派发成本。

## 实施顺序

### 已落实的执行基础

类型化数组索引从连续标量负载直接读取槽，字典索引借用键内容并查询冻结后的专用索引；通用索引和字符串索引在可能物化新值前发布 GC 根。程序发布阶段统一验证寄存器、附表和跳转目标，执行期不重复校验已证明的分支目标。循环迭代费用使用局部倒计数分批结算，并在 Host 副作用、返回和执行结束前同步共享预算。

固定调用借用映像绑定和程序，动态闭包共享捕获绑定；调用、返回和模板帧切换时刷新局部程序视图。同帧附表读取借用该视图，捕获值读取借用捕获数组。构造器清理状态按需分配。类型化索引分别调用数组、字典和字符串入口，动态堆使用槽位与代数直接定位。存储与身份约束见 [运行时数据结构](../2-架构/02-运行时数据结构.md)。

执行缓冲容量足够时直接复用，已预留容量持续计入共享内存预算；仅在需要扩容时计算新增容量并预留内存。每次调用仍检查深度和寄存器预算，扩容失败时退回本次调用预留。

### 1. 缓存当前帧与程序计数器

执行循环在局部变量中持有当前帧基址、程序计数器和程序句柄。同一执行函数内完成调用、返回和模板帧切换，切换后重新取得当前帧窗口。无 Host 调用的标量指令延迟写回程序计数器，其余指令执行前同步；标量故障出口统一补写实际位置。区间循环与集合迭代附表直接借用局部程序句柄。调用及返回测试覆盖递归、闭包、Host 重入和源码位置，确保故障栈与现有行为一致。

验收指标是标量整数循环的每轮通用状态访问减少，指令数和预算消耗保持不变。

### 2. 扩展验证后的直接读取

程序发布阶段保证指令、寄存器和各附表索引合法。执行器为已验证程序提供集中读取接口，继续减少附表读取中的重复 `get` 与错误构造。所有外部输入、动态集合索引和 Host 返回值继续执行运行期检查。

验收覆盖损坏程序拒绝、分支目标、调用附表、构造附表、索引附表和寄存器重映射；执行期不得接受未通过发布验证的程序。

### 3. 类型化标量寄存器读取

整数、浮点和布尔专用操作直接读取紧凑槽位的已验证标量表示，避免重复执行通用值分类。类型证明来自发布后的寄存器类型表，合流点和参数入口必须先完成一致性验证。

验收覆盖整数溢出、浮点位模式、布尔分支、参数类型错误和寄存器复用。错误类型及发生顺序保持不变。

### 4. 紧凑区间循环描述

将 `ForPrep`、`ForLoop` 的热字段组织为连续、一次索引可读的描述，执行循环缓存当前区间的 limit 槽和值。循环变量被写入、闭包捕获或 Host 重入后，仍按当前语言规则读取和发布根。

验收覆盖开区间、闭区间、空区间、正负边界、`break`、`continue`、嵌套循环和循环体内调用。循环迭代预算逐次计费，不合并为单次预扣。

### 5. 扩展预算倒计数

循环回边已经使用局部倒计数承担迭代费用。后续只对具有相同超额约束的常规费用扩展倒计数，并在达到补充阈值、发生调用、返回、Host 操作、可能按数据量计费的操作或故障时与共享预算同步。同步规则保持现有允许的有限批次超额，不改变 Host 副作用边界。

验收采用从零到多个阈值边界的逐值差分测试，比较结果、故障位置、Host 轨迹和已消耗预算。无法保持精确失败点的费用不得批量化。

### 6. 分离无分配标量派发路径

把不访问动态堆且不产生新身份的标量指令放入紧凑派发路径，减少每条指令对根发布和堆借用条件的重复判断。进入调用、集合、字符串、闭包、构造、Host 或其他可能分配的操作前统一发布活跃根。

验收覆盖标量循环中穿插动态分配、GC、闭包捕获及 Host 重入，确认活跃值不会提前回收，纯标量循环不产生根集合更新。

## 统一验收

- 每项先运行语义差分测试，再对整数循环、数组索引和字典索引分别测量派发数、预算消耗及耗时。
- 所有错误信息、源码区间、Host 调用顺序、GC 可达性和公开值身份保持一致。
- 实现完成后运行 `cargo check --workspace` 与 `cargo test --workspace`。
- 若某项需要改变语言规则、公开 API、字节码语义或预算口径，则退出本计划并单独形成设计方案。
