# 核心精简：性能与功能验证

基线为 `06a3ac49c73f291b50fa0f87422498e07d5df2bc`。对照使用同一份 Rust 基准源码和 CLI 驱动、锁定依赖、独立 release 构建及固定二进制；正式采样不启动编辑器，也不与构建或测试并行。计时结果对应归档的核心精简冻结源码；后续 0.17.0 发布版本同步、格式与 Clippy 整理不在该计时快照内。

## 测量口径

- 五轮串行轮换，顺序 AB／BA／AB／BA／AB；每个进程预热一次，再测三次，每项每版共十五个样本。报告算术中位数及最小—最大范围，不推断 P95/P99。
- Rust 只计公共 API 或解析、编译、构建调用；夹具、输入准备、返回结果析构和结果复核在计时外，内部临时对象释放及磁盘发布在计时内。
- CLI 从独立进程启动计至退出并收齐输出；夹具复原、JSON 解码及独立查询复核在计时外。
- 新会话加载保留操作系统文件缓存；它不代表机器冷启动。此次没有采集峰值内存，也不声称内存改善。
- 所有原始样本均保留，不删除较慢样本。局部压力场景不换算为桌面应用整体速度。

## 最终结果

主要核心耗时采用固定 P 核的 [controlled 结果](controlled/README.md)：Windows `GetSystemCpuSetInformation` 报告逻辑 CPU 0–11 的 EfficiencyClass=1、12–19 为 0；测量进程固定在逻辑 CPU 2（CoreIndex=2、mask=0x4）。每个子进程启动后均通过 `GetProcessAffinityMask` 验证继承 mask=0x4。此约束仅作用于基准进程及其子进程。

表中负数表示耗时减少；“更快轮数”比较同轮两版的三个样本中位数。范围覆盖全部十五个样本，变化百分比是描述性统计。

## 证据与运行环境

环境为 Windows 10.0.26300、Intel Core i5-13600KF（14 核／20 逻辑处理器）、rustc/cargo 1.99.1、Windows mimalloc；CLI 关闭日志。依赖锁和驱动摘要见 [environment.json](final/environment.json)。两版从独立源码目录、独立 target 目录构建 release，最终二进制 SHA-256 见 [artifacts.json](final/artifacts.json)，源码见 [after.patch](final/after.patch) 与 [after-source-overlay.zip](final/after-source-overlay.zip)。测量冻结时，覆盖包中的 71 个源码文件与当时工作区逐字节一致且无缺失。

- [controlled](controlled/README.md)：最终源码、固定 P 核的核心 API 主结果。十个进程全部退出成功，所有语义断言通过。
- [final](final/README.md)：最终源码、默认调度的完整配对，二十个进程全部通过。核心 API 部分基线样本整体抬升，作为完整观察保留；主结论使用固定核结果。
- [intermediate](intermediate/README.md)：中间实现的完整配对，保留普通字段编译、数组默认值和连续插入的回退证据。

通用基准源码为 [core_simplification_perf.rs](core_simplification_perf.rs)，CLI 驱动为 [cli-matrix.mjs](cli-matrix.mjs)。各组保存原始 stdout/stderr、逐进程命令及状态、fixture 摘要和可重算的汇总脚本。所有慢样本与失败的早期共享 target 构建日志均保留；正式样本使用成功完成的独立 release 构建。基线及最终构建日志分别为 [build-baseline-final-harness.log](build-baseline-final-harness.log) 与 [final/build-after.log](final/build-after.log)。

## 功能验证范围

基准逐次检查全部目标与非目标记录的预期值、插入数量和内容、维度值，并与独立完整重载逐记录对照。默认值三组对所有记录断言，并核对两版首记录字段序列化摘要相同。CLI 每个样本复核操作状态和独立语义查询，场景结束执行完整 `check --rules`。

实现保留普通字段和删除折叠、pending 引用上下文、批次原始错误顺序、中间节点预算、发布冲突检测和失败恢复；这些行为由现有 Rust 工作区测试及新增回归覆盖。

`data.id` 是原有语言规范允许的业务字段，本次将输入解析与该规范对齐；table/singleton 的记录身份限制继续验证。声明默认值回归覆盖 flag 组合字典键、创建草稿中模板源码预览，以及 EditableShape 对省略必填字段的类型初值补齐。基础值与维度值中的嵌套 Option 引用改名同样有回归。

模型默认集合按每个元素计入节点预算；基线在该路径遗漏逐元素计数，最终版本修正了拒绝边界。这一有意的模型规则修正由节点预算回归测试覆盖，不属于下述 1,337 项语言诊断对照的覆盖范围。

最新 `cargo check --workspace` 与 `cargo test --workspace` 均通过，测试共 861 项通过、0 失败、0 忽略；日志为 [workspace-check.log](workspace-check.log) 和 [workspace-tests.log](workspace-tests.log)。

语言诊断使用 [language_regression_probe.rs](language_regression_probe.rs) 的 1,337 个定向用例对照：1,260 个非 panic 结果完全相同，60 个仅模板内部 Debug 表示变化；4 个诊断 span 缩小、4 个尾注释合法输入新接受、2 个额外字段或记录非法输入新拒绝、3 个非法输入保持拒绝但消息更新。未发现未解释的新回归。另有 `abstract`、`abstract `、`sealed`、`sealed ` 四个不完整输入在基线和最终版本都发生既有 EOF panic，它们不计入成功语义比较。完整统计见 [language-summary.json](language-summary.json)，逐例结果见 [language-baseline.jsonl](language-baseline.jsonl) 与 [language-after.jsonl](language-after.jsonl)。定向语料和工作区测试说明已覆盖的行为，不构成对全部输入的穷尽证明。

## 复算与复测

在仓库根目录复算已保存的统计，无需重新构建：

```powershell
python docs/archive/benchmarks/core-simplification-2026-11-06/controlled/summarize.py
python docs/archive/benchmarks/core-simplification-2026-11-06/final/summarize.py
```

重新采样时，将整个证据目录复制到新的输出目录，保留本目录的原始样本。分别将基线提交解包到两个独立源码目录，在 after 目录应用 `final/after.patch` 并展开 `final/after-source-overlay.zip`；将本目录两份 Rust 基准源码复制到两版 `crates/coflow-runtime/examples/`。两版分别执行相同命令，使用独立 target 目录：

```powershell
cargo build --release --locked -p coflow-runtime --example core_simplification_perf --example language_regression_probe -p coflow --bin coflow
```

将成功构建的三个 exe 固定复制到两版各自的二进制目录，更新新证据目录 `final/artifacts.json` 的路径、字节数和 SHA-256，并更新 `final/setup.json` 的隔离工作目录。先运行默认调度 `final/run-paired.py`；固定核复测运行 `controlled/run-paired.py`，其拓扑断言要求所选 CPU 属于较高 EfficiencyClass。更换机器时应按真实拓扑选择 CPU，并在新证据中记录选择。采样期间串行运行，不与构建、测试或其他基准并行；完成后运行对应 `summarize.py`。
