## 下一轮建议优先级

以下为尚未实施的建议，结合 [剩余实现分析](../remaining-work-rust-cli.md) 和 [现有 R4 目标表](../final-r4/target-status.md)。R4 表中的 CLI 与部分维度证据仍不完整，最终串行验收结果应作为后续计划的更新依据，不能把缺少配对的观测值写作达标或回退。

| 优先项 | 当前依据与下一步 | 必须保持的验收 |
| --- | --- | --- |
| 1. 跨文件写入的来源及候选复用 | R4 交错 1000 操作约 4,896 ms，目标 1,500 ms；同文件批次约 121 ms，目标 100 ms。文件分组已经实现。先拆分读取、解析/降低、暂存、检查、提交成本，复用跨阶段已经验证的原文和候选；不重复实现分组，也不把现有两次完整解析误写为三次。 | 每个实际文件的验证次数和读取字节下降；重叠路径、顺序屏障、中间预算、全局最早失败、成功前缀及多文件原子发布与顺序参照一致。 |
| 2. 模板和维度成员变化的增量身份 | R4 含模板的增删改名迁移约 1,741–1,800 ms，目标 500 ms；无模板对应操作约 377–423 ms 已达该绝对目标。用稳定坐标重映射模板依赖、成员引用入边和维度宿主，只重算可证明受影响的根。 | 保持旧句柄代次隔离、来源迁移、继承与 singleton、虚拟 `id`、显式引用类型、循环/缺失目标、空变体和完整规则集合读。以完整构建比较每个上下文及全部诊断。 |
| 3. CLI 基线/候选共用不可变输入与差异集合 | 当前候选复制到临时目录，基线和最终会话仍分别建立，语义 diff 仍遍历完整记录/字段/上下文。先测阶段占比，再让候选派生自共享输入代次，并让 diff 接收成员、来源、模板依赖和上下文变化集合。当前证据不足以声明具体 CLI 加速倍数。 | 最终冲突检查继续重新发现完整输入范围；同值、预览、拒绝与冲突不改字节；删除/上下文删除显式表示；完整 JSON diff、首错、恢复回执及 revision 与现有行为一致。 |
| 4. 健康加载的阶段时间与中间表示生命周期 | R4 十万条无规则加载约 4,130 ms，目标 3,000 ms；带规则约 6,101 ms，目标 6,000 ms。先定位 AST、降低输入、值树、来源索引和规则执行的时间/分配/峰值占比，再缩短存活重叠并共享不可变字符串/schema 元数据。 | 验证阶段职责不减少；宽字段、复杂值、继承、模板、引用、维度及错误数据的诊断代码、顺序、跨度和预算相同。新会话与缓存刷新分别验收。 |
| 5. 热写入和密集覆盖的局部工作 | R4 热标量约 29.9 ms 已达 35 ms 绝对目标，但优化/基线比约 1.007，尚未达到 0.75 的改善目标。密集覆盖 Writer 仍为首个非 trivia 扫描完整后缀；输入索引按变化批次重新登记。先采用共享流式词法入口，再按证据推进字段/上下文粒度更新。 | 头/中/尾修改与清除逐字节保留逗号、注释、CRLF、Unicode、空记录/空变体；来源位移必须刷新，显式同值、`None`/Missing、默认物化及旧投影保持。用总 API 时间和文件字节证明收益，不能只引用模型工作计数。 |

下一轮正式性能验收继续使用冻结二进制、相同夹具、独立配对轮次与原始样本。阶段剖析安排在正式采样之外；保留已有绝对目标和相对目标，不通过减少能力、弱化预算或改变统计口径取得达标。
