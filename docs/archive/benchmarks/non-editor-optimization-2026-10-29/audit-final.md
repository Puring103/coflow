# 最终成对测量独立审计

最终 [JSON 审计](audit-final.json)包含 291 个独立进程：282 个完整成功、3 个包含局部成功及命令超时的 CLI 进程、6 个整体超时的 Rust 进程，无语义／执行失败和证据匹配问题。优化侧 147 个进程均完整成功；基线超时原样保留。数值目标验收与本审计分别判定。

审计入口为 `scripts/performance/audit-optimization.mjs`。脚本只读取计划、执行元数据和原始结果，不启动基准、构建或测试，也不重新读取大型二进制做摘要。执行：

```powershell
node scripts/performance/audit-optimization.mjs docs/archive/benchmarks/non-editor-optimization-2026-10-29/final-results
```

JSON 结果分别保存 `process_status` 和操作证据的 `status`。操作证据区分 `pending`、`completed`、`partial`、`censored` 和 `failed`。只有已经保存 `.meta.json` 的运行才进入审计；未退出进程的部分文件不纳入结果。完整 CLI 运行还必须具有报告结束标记、`success=true`、全部计划指标通过验证以及进程退出成功。`audit_status=incomplete` 表示证据仍未完成；`complete_with_censored_or_failed_runs` 表示所有运行均已结束但包含部分完成、超时或失败；`issues` 列出匹配或验证缺口。审计结果对应执行时刻的归档内容，后续新增测量需要重新审计。

`final-results/` 的输入由 R4 Rust／模型／CLI、R6 .NET／Mono 以及 R4 CLI 扩展操作三组已结束证据按字节复制形成。`evidence-provenance.json` 保存原目录、文件 SHA256 与字节数，原始规格和时间不重写。Rust 同夹具稳定性补测与直接 CLI 内存分别保存在 `stability-r4/` 和 `cli-memory-r4/`，不混入主测耗时中位数。

CLI 的 `--continue-on-error` 允许失败后继续测量其他操作，因此进程状态不能代替每项操作状态。明确记录 `timed_out=true`，或记录驱动的标准 `CLI timeout: <command>` 异常且耗时达到配置阈值的操作，归类为 `censored_timeout`。报告保留超时命令、阈值、错误与已采样但未完成验收的样本数；这些样本不进入成功指标或成对比较。其他失败归类为 `semantic_or_execution_failure` 并列入 `issues`。

含明确超时且另有已验证指标的 CLI 运行记为 `partial`；所有操作均未通过且只有明确超时证据时记为 `censored`。其余已完成全部正确性验证的指标可以进入 `partial_pairs`，该字段只包含两边都通过验证的操作。`completed_pairs` 仅包含两边完整成功的运行。`operation_failures` 逐项输出失败分类，`process_counts` 与 `counts` 分别统计进程状态和操作证据状态。任何缺失指标均单独列出，不推定为通过。

## 核验范围

- 计划 ID 与场景、轮次、版本坐标的唯一性；执行元数据与计划一致。
- 已记录的执行载荷 SHA256 与计划一致；CLI 结果中的实际 CLI 与驱动摘要一致；配对双方共有宿主文件摘要一致。
- 配对运行参数、报告配置、夹具规模与字节数一致；CLI 的逐项夹具 SHA256 一致。
- 计划指定的指标完整、没有重复，原始样本有限且非负，样本数量符合参数，配对操作批量相同。
- CLI 的全报告结束和成功标记、每项正确性状态及明确超时证据；.NET 的独立语义预检和完整结束标记；结构变更基准的全量重载标记。
- 归档进程的开始时间与运行时长没有重叠。此检查只覆盖已归档进程，不能证明系统中没有其他负载。

计划中保留的库摘要与本次测量绑定；执行后当前文件内容和源快照摘要的核验属于单独的冻结源审计。Rust 与 .NET 夹具使用固定生成逻辑，本次结果通过配置和字节数配对；它们没有输出逐夹具内容 SHA256。相同基准源码与夹具源码的确认需结合源快照。

## 正确性证据的边界

Rust 结构变更基准在计时结束后断言记录数量、目标记录存在性、重命名身份、目标文件以及预期字段。随后执行逆操作恢复夹具，再独立完整重载并逐字段核对会话结果。因此 `fresh_reload_all_fields_and_no_diagnostics` 指向恢复后的夹具状态，不能替代对每个变更状态的完整重载对照。

功能回归由三层证据共同支持：基准内的变更状态断言、恢复后的完整重载、专门回归测试中的多代次模型与检查器 oracle。CLI 基准则在每次操作后执行新的语义查询，并在该指标结束前完成 `check --rules`；不发布的操作还核对完整输入文件集合与内容指纹。.NET 基准先执行独立语义预检，各测量操作在计时外验证结果。

## 比较口径

各场景使用三轮独立进程交替测量，实际完成状态以计划与 `audit-final.json` 为准。重操作的一次样本仅提供描述性结果，不能表示稳定尾延迟或统计显著性；查询的批量样本分位数也不能解释为单次 API 调用的尾延迟。中间版本与最终产物按载荷摘要分别保存。

通用汇总器会读取尚未退出 CLI 进程已经保存的成功指标；通用比较器也不强制检查计划、夹具和完整运行状态。最终结果应使用本审计确认的完整运行，或明确标记来自失败进程中已完成的单项证据。缺失和超时操作不能当作成功或实际耗时。

进程超时包括夹具、准备、验证与计时，因此超时阈值不能直接作为某个 API 的运行耗时。进程峰值内存包括夹具、预热、验证与分配器保留；CLI 驱动的内存不代表 CLI 子进程。所有文件系统缓存均未强制清空。
