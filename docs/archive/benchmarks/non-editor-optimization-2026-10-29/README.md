# 0.14.0 基线后的非编辑器性能优化验证

本次实现覆盖 Rust Runtime、独立 CLI 和 C# Loader，保留原语言、数据格式、校验时机、结构预算及事务契约。桌面编辑器和前端渲染不在耗时范围。基线为 `3742bf1e9dc8d3a22a263f1db48be32412b1b3a4`；测量使用 `codex/non-editor-performance` 工作区的冻结产物，测量时生产版本号为 `0.14.0`。

本次优化纳入 0.15.0 发布。归档中的 0.14.0 基线、测量产物版本、源码快照及审计收据保持测量时状态；发布版本更新及发布门禁另行验证。

### CLI 常见操作覆盖

千条基础矩阵覆盖全部 39 项操作。万条基础矩阵由 8 项常用操作和 [31 项扩展操作](cli-expanded-r4/comparison.md)组成，配置均为 10 文件、20 字段、语言／平台各一变体；批次实际修改 1,000 项。扩展矩阵的六个独立进程全部完成，逐项结果校验与[证据审计](verification/cli-expanded-r4-audit.json)通过。十万条、100 字段和每维 10 变体另有专项；本轮没有穷举规模、字段、拓扑、覆盖率及操作的全部组合。

万条基础数据的数组、字典、成员增删／迁移和维度覆盖等常见修改，从约 22 秒降至约 2.3 秒；重命名为 2.504 秒，新变体为 2.829 秒。非法输入拒绝／修复从约 11 秒降至 1.24—1.38 秒。普通列表、筛选、搜索和统计仍主要承担加载成本，前后变化较小。

条件批次 `set_where` 实改 1,000 条由 49.615 秒降至 **28.584 秒**，仍明显超过 5 秒目标，也尚未获得安全 `apply` 批次的同级收益。该路径与完整事务共享、差异局部化一起列入下一阶段，不能以较快的 `batch_same_file` 代替它通过。

千条夹具的修订冲突拒绝由 85.113 ms 增至 97.378 ms，增加 14.4%，未通过 5% 稳定性边界；万条对应操作为 134.489 →133.661 ms。两个规模分别保留，不能用万条结果替代千条的回退判定。

- [独立证据审计](audit-final.md)核对完成标志、夹具与参数、样本完整性和进程不重叠；[.NET 驱动静态审计](verification/csharp-harness-audit-r6.json)核对 PDB 文档摘要和方法 IL，区分测量方法与编译元数据差异。

- [最终样本汇总](final-results/summary.json)、[逐项比较](final-results/comparison.md)与[可计算比较](final-results/comparison.json)保留耗时、分配、保留内存及每轮配对比例。原始样本未被均值或图表替代。

所有正式基准串行执行，编译、测试与 Player 构建均在采样之外。旧版与优化版每轮交替执行，共三轮；第二轮交换执行顺序。慢操作每进程一个计时样本，热修改每进程 100 个样本，C# 查询每进程 100 个调用批次。汇总采用各进程中位数的算术中位数；分位数仅在样本量足够时报告，不把批次均值视为单次调用尾延迟。

Windows 调度、CPU 亲和性、后台负载和功耗状态未固定。部分轮次的新旧版本同时明显变快，已核对输入规模、工作量计数与产物摘要一致。绝对耗时按本机三轮样本判定，并同时保留每轮范围及配对比例；临界达标不代表稳定尾延迟或其他设备的性能保证。

## 已落地的机制

### Rust 错误处理

同一 CFD 来源共享一次行索引，语法错误、值转换错误及健康记录来源都使用一致的 UTF-16 定位。错误恢复流式消费无损 token，只保留记录候选偏移，避免为预算拒绝另分配完整 token 数组。默认结构上限、错误数量、消息、顺序和健康记录保留规则不变。

基础模板阻断错误根据实际身份读取关系逐轮传播剔除，只重新求值受影响根。虚拟 ID、显式类型引用、嵌套值和默认值的读取均纳入依赖；最终普通构建仍检查健康记录、引用和维度。输入诊断、身份歧义及 singleton 使用完整编译阶段。工作量统计累计失败轮、闭包计算及最终构建。

### Rust 修改与维度

既有维度文件按覆盖坐标和值计算真正变化，来源重排通过独立的来源更新处理。完整维度投影从原始基础模型组合选择，仅重建显式覆盖及模板依赖闭包，未影响记录共享值树。相同选择继续直接复用；schema、预算或健康前提不满足时完整重验证。投影的引用索引只包含当前视图的基础引用边。

基础模型成员变化按原始草稿证明未变记录的可复用性，重新建立新句柄顺序下的身份、表和引用索引。未变化且无模板、引用目标实际类型稳定的记录共享值树；模板记录及受目标身份变化影响的宿主完整重算。维度成员变化继续完整构建。该优化减少值验证和物化，仍包含全局索引和必要检查成本。

成员变化后的规则检查按实际读取关系重新规划。字段读取索引按记录分桶，桶内仍按完整记录和字段排序；整条记录变化只查询一个桶的精确前缀，批量失效不再逐记录查询全部桶。`records(Type)` 的空集和短路读取仍登记依赖，新增或全部字段变化的宿主执行自身及嵌套数据规则；目标删除、恢复或实际类型变化通过基础和维度引用入边传播。规则排序、去重、预算中断后的完整重验证和旧快照保持有效；不会因缺失目标暂时不存在而丢失后续恢复依赖。

### 独立 CLI

候选配置、源根、路径身份和展示路径按配置代次及唯一文件缓存；schema 和操作语法树复用，配置或输入范围变化时同步失效。连续、记录身份唯一的字段请求按文件合并，每个文件保留原请求顺序并检查全部中间节点预算。重复记录或非字段操作形成边界。准备或验证失败时恢复临时状态并原序执行，保留首错和成功候选前缀。

语义差异使用类型化字段状态，避免 JSON 往返及查询专用的位置对象；基础字段只保存一份，各维度保存相对差异。已存在上下文比较基础变化和维度差异的并集，变体增删仍展开全部有效字段。显式同值覆盖、默认值来源、模板间接渲染和完整差异计数保持一致。

发布前的完整输入修订核对及 all-or-nothing staging 保持有效。发布失败只有在恢复回执明确且逐文件字节证实原样时才重放；无法证明完整恢复时保留错误与恢复回执。候选仍使用独立临时目录，基线与最终数据模型分别构建；真正共享不可变输入及候选数据代次尚未实现。

### C# 与 Unity

Loader 使用字段槽位索引、加载范围内的名称池、共享不可变源及按实际 CLR 类型分桶建表。基础字段、Option、集合、内联对象、枚举、默认值、模板和继承表继续保留；引用与父子表内对象身份保持一致。上下文无关结果只在可证明安全时复用，所有声明单变体仍在 Load 完成前验证。

缓存的维度转换和变体元数据避免重复创建选择字典与包装对象；视图构造仍由同一锁保护，失败清除完整组合缓存。深依赖使用有界调用栈和显式构造帧，保留 256 层逻辑限制、循环身份、DFS 错误顺序和诊断来源，集合暂停恢复不会重复构造已完成元素。

暂停帧通过返回 false 的异常筛选器按内到外登记，由调度器统一接收，避免每层重新抛出；原生调用段保持 32 层。记录状态仅保存类型、ID、位置与来源路径，字段槽位建立后不再长期保留根语法字段包装。非限定 ID 索引只保存唯一记录或持续歧义状态；限定类型和继承根索引继续独立维护。字段校验仍在身份、单例与覆盖验证后执行，错误优先级不变。

普通引用及其 Option／Dimension 包装在当前字段处使用显式记录栈执行 DFS，不依靠异常切段；逻辑深度、正在求值标记和循环身份仍累计并保留。模板、内联对象与集合的复杂读取继续使用 32 层保护，并与显式父帧共用恢复协议。表查询直接访问内部具体字典，键和值保持只读视图；名称池按成对 UTF-16 码元计算随机哈希，碰撞后仍比较完整名称。

成员检查专项覆盖空集合读取、新增／重命名／重排／删除、引用目标实际类型替换、跨维度引用入边，以及保留宿主时目标反复删除和恢复。每个代次与独立完整检查对照；256 条记录夹具的新增、重命名、纯重排和删除分别只执行 3、3、0、1 个必要检查根。
