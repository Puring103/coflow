# 编辑热路径与界面帧间隔测量

环境：Windows、引擎 Release/mimalloc、前端 Vite 生产构建与无头 Chromium。原始结果见 [完整样本](engine-editing-2026-10-26.json)。前端采用本轮之前算法的源码快照作为对照，保留同期界面功能变更，通过构建覆盖读取快照，不替换工作区文件。引擎基线为本轮开始时保存的 Release 二进制。

## 工作量与正确性

健康增量直接借用源文件批次，不再建立两层逐记录输入引用表。十万条项目的局部修改中，`draft_records_collected` 从 100,000 变为 0；单条更新仍验证和物化 1 条、复用 99,999 条、更新 2 条引用边、执行 4 个检查根。身份和来源核对仍有全量扫描。完整容错重建继续使用候选表，诊断坐标按需构造。

普通表格与维度表稳定虚拟行键回调，避免滚动使全量测量缓存失效。普通表格复用不可变且位置不变的行对象；导航与批量清空复用索引，导航数据合并遍历。维度分组建立来源级成员索引，保留首次命中优先级及来源隔离。

验证结果：`cargo check --workspace`、`cargo test --workspace` 通过，730 项 Rust 测试通过；359 项前端单元测试、33 项无头表格交互测试通过；前端类型检查及生产构建通过。构建仍提示较大的 JS chunk。新增对照覆盖混合输入批次、分页边界、来源移动、旧快照、表格排序筛选、成员变化和访问器缓存失效。端到端基准执行独立完整重载对照。

## 前端生产构建

固定视窗 1280×800。两个方向串行对照，先基线后当前、再当前后基线。每个场景编辑 5 次；每轮中位数列为范围，不将其解释为稳定 P95。编辑包含 Playwright 输入、真实组件提交、内存快照更新与两次动画帧等待，不包含磁盘和后端检查。

| 场景 | 基线编辑中位数 ms | 当前编辑中位数 ms |
| --- | ---: | ---: |
| 1,000 行 × 6 列（反向轮） | 43 | 44 |
| 10,000 行 × 6 列 | 73–74 | 59–65 |
| 100,000 行 × 6 列 | 541–562 | 241–315 |
| 10,000 行 × 60 列，含属性面板 | 128–141 | 107–109 |

十万行滚动在每轮 88 个帧间隔中，基线超过 33.4 ms 的帧为 9/7 个，当前为 1/0 个；帧间隔 P95 从 33 ms 到 33/17 ms。滚动脚本总耗时从 1,618/1,648 ms 到 1,090/1,016 ms。编辑后实际挂载 27 行，与总记录数量无关。所有成功场景无页面异常，提交后的值均经过验证。

一万行的首轮当前滚动曾出现 3 个长帧，反向复测为 0；原始波动全部保留。小表编辑未显示明确收益。当前测试支持大表热路径改善，不构成所有硬件、项目与操作均零掉帧的保证。

## 后端测量与剩余边界

十万条、100 文件、20 字段的首轮对照中，单条更新中位数 50.005 → 47.639 ms；同文件 1,000 次更新 93.909 → 93.732 ms；跨文件 1,000 次更新 3,884.281 → 3,733.679 ms；完整加载 6,309.848 → 6,263.934 ms。该轮基线启动阶段与浏览器回归短暂重叠，完整加载数据仅作辅助；另有无并行测试的反向对照，完整保留于原始样本。

无并行测试的反向轮中，当前加载 10,826.849 ms、单条 80.975 ms，基线加载 6,437.919 ms、单条 45.610 ms。十万条 ABBA 交错复测得到当前加载 10,716.82/6,299.26 ms、单条 70.56/44.26 ms，基线加载 11,144.17/11,124.92 ms、单条 88.31/48.06 ms。一万条 ABBA 中两版本单条更新均在约 33–38 ms。相同二进制也有明显波动，不能把某个方向的单轮差异判为稳定收益或稳定回退；当前环境不支持严格的后端延迟保证。

最终代码保留拥有态草稿逐条释放的生命周期。最终二进制十万条对照中，加载单样本为基线 11,116.239 ms、当前 11,114.176 ms；单条修改 3 次中位数为 82.501 → 82.150 ms，候选验证 79.620 → 80.254 ms。该轮未显示明确的时间收益或回退；确定的收益是健康增量取消全项目输入引用表收集。最终完整重载对照与两项必需 Rust 检查均通过。

8,000 条引用拓扑模型基准中，环形更新 1.070 → 1.038 ms，集中引用 0.891 → 0.850 ms，完整模型及旧快照对照通过。

单文件十万行的编辑仍有数百毫秒延迟；完整数据加载、跨文件批次、变更文件的整份解析、成员变化完整构建、身份和来源全量扫描仍是剩余成本。前端行模型复用要求不可变快照保留未变记录身份；全量反序列化的新对象不能直接获得相同复用收益。后续端到端优化应覆盖快照差量传输、来源局部维护和解析成本，不以组件基准替代真实桌面链路。
