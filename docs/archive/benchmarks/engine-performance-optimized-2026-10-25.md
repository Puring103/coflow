# 引擎核心优化验收：2026-10-25

十万条记录下，连续单字段提交的 P50 为 **50.29 ms**、P95 为 **54.09 ms**；每次只验证和物化 1 条记录，复用 99,999 条记录。局部源码校验 P95 为 **48.29 ms**。完整工作区检查通过，测试共 **712 项**。

全量加载中位数为 6.55 s，跨 100 文件的 1,000 次修改为 3.81 s，分别高于 5 s 和 3 s 目标。单字段 P50 略高于 50 ms 目标；P95 已低于 100 ms。当前结果与后续目标分别记录，不将未达标项计作完成。

## 1. 测量条件

- 基线提交：`7e9d4fdebabda2c440ed80d1b1f39651801f1387`；优化代码为该提交上的未提交工作区变更。
- 同一台 i5-13600KF、32 GiB、Windows 11 机器；Rust/Cargo 1.99.1，Release 构建。
- Windows CLI、桌面宿主和本基准使用 mimalloc 0.1.52；核心库不设置全局分配器。其他平台保持系统分配器。
- 主夹具为 100,000 个唯一 ID、100 个文件、20 个字段、200,000 条引用边和 400,001 个 check 根任务，源文本约 54.3 MB。
- 夹具含标量、字符串、数组、字典、嵌套对象、Option 和跨记录引用；模板与维度另外通过微基准及差分测试覆盖。
- 构建、测试、测量串行执行，未启动或停止 CFD 编辑器。结果是无头运行时数据，不包含前端、IPC、渲染及用户交互队列。
- 每项预热一次；表中的全量加载是在文件系统缓存已热时重新构建完整会话，包含解析、模型、索引和 check。机器冷启动耗时未单独测量。
- 计时包含操作内部临时对象释放、请求构造和结果断言；返回结果自身的释放不计入该次计时，前次返回结果在下一次计时前释放。
- 连续修改使用每次不同的真实值；草稿校验固定基于修改前快照，反复验证同一份实际变化的文本。每组末尾执行独立完整重载并核对全部记录的修改字段及诊断。

[原始数据与源码/二进制 SHA-256](engine-performance-optimized-2026-10-25.json)保留逐次耗时、实际工作量、进程采样峰值、机器信息及检查结果。[原始基线](engine-performance-2026-10-25.md)和其 JSON 保持独立。

原基线的单条提交同样只执行 4 个检查根，但会重建全部 100,000 条记录及 200,000 条引用边。当前计数证明减少了模型工作量。草稿引用表仍按全部记录汇总，模型身份与来源核对仍有线性成本；这些扫描不计作记录重新验证或物化。

万条稀疏引用夹具修改目标 `value` 时，原基线执行 40,000 个根，当前仅执行直接变化者及其实际读取者的 **8 个根**。整条规则仍保持 4 个根的执行边界。

## 5. 功能与增量边界

`cargo check --workspace`、`cargo test --workspace` 均通过，后者 712 项。新增回归覆盖完整/增量模型、模板传播、维度覆盖增删、来源移动、浮点符号零、引用顺序、被拒绝记录、语法与读取错误恢复、发现诊断保留、完整/增量检查、有限预算、规则分支和错误传播、批次与顺序写入等价、失败原子性、外部冲突、编辑器过期候选以及 LSP 草稿与定义索引。

局部模型重建适用于 schema、限制、记录身份、顺序和变体集合稳定的代次；成员/顺序/变体集合变化及需要重新归并模型诊断的状态执行完整构建。规则保持整条规则失效、原有求值顺序、错误传播和预算，不通过提高上限或改变 `any` 语义获取性能。新诊断按最新来源定位，旧代次仍可独立读取。

模型工作量计数来自成功返回的构建轮次；诊断触发的完整重试成本包含在端到端耗时中。错误场景用等价测试验收，不以健康夹具的局部复用比率推断错误状态下的性能。

## 6. 复现与后续指标

```powershell
cargo build --release -p coflow-runtime --example engine_perf
$env:ENGINE_MODE = 'pipeline'
```

批量组使用 `ENGINE_SAMPLES=1`、`ENGINE_VALIDATION_SAMPLES=3`、`ENGINE_UPDATE_SAMPLES=7`、`ENGINE_BATCHES=1000`。微基准使用 `ENGINE_MODE=model`、`ENGINE_RECORDS=2000`、`ENGINE_DIMENSION_RECORDS=1000`、`ENGINE_SAMPLES=7`。系统分配器对照构建加 `--features engine-perf-system`。

后续重点是完整加载的解析/降低/规则执行成本，以及跨文件批次仍需处理的完整文件内容和发布成本；局部编辑还包含全记录指针表与身份/来源核对。成员变化的局部维护、连续字段槽和宿主导航统计的增量更新继续按[优化方案](../../development/engine-performance-plan.zh-CN.md)验证。完整加载、跨文件批次和严格 P50 目标保持原阈值。
