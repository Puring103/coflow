## 采样与配对

环境为 Windows 11 10.0.26300、Intel Core i5-13600KF、约 32 GiB 内存，.NET SDK 8.0.426、Microsoft.NETCore.App 8.0.32、net8.0、Release，`DOTNET_TieredCompilation=0`。命令为 `--suite all --records 500 --samples 7 --warmups 2`。先完成基线全矩阵，再完成优化版全矩阵；采样期间没有并行构建或测试。

每项先预热 2 次，再采集 7 个样本。每个样本在准备对象保持存活时请求 GC，计时使用 `Stopwatch.GetTimestamp`，分配使用 `GC.GetAllocatedBytesForCurrentThread`。文本生成、schema 创建、阶段准备、结果缓冲数组、正确性断言和 JSON 输出均排除在计时之外。

48 对结果的套件、夹具、阶段说明、记录/字段/类型/变体数量、覆盖规模、来源文本哈希与长度、操作数和采样配置全部匹配。`boundLoader` 是内部 `CfdData` 构造签名的条件编译选择，优化前为 false，优化后为 true；业务读取回调均为 `Get<T>(string)`。

wide 和 variants 套件各自测量了“128 字段、3 个稀疏变体”的 construction 与 full-load，故 48 个结果项对应 46 个不同输入与阶段组合。下表保留所有原始结果项，不把重复项合并，也不计算跨场景的“整体平均加速”。

## 阶段和夹具

| 阶段 | 计时范围 |
| --- | --- |
| parser-only | 已有文本到语法文档，不含 schema 绑定、业务构造或表注册。 |
| construction | 已解析文档到业务数据；包括输入发现、绑定、基础构造、已声明单维度变体验证和表注册。 |
| full-load | 公共加载入口的解析、绑定、构造、变体验证和表注册。 |
| first-for | 每个样本重新加载，计时内对 500 条记录各选择一次 language[v0]；循环引用可能共同构造对象图，后续记录可命中该图的缓存。 |
| cached-for | 预先加载并建立全部目标视图后，重复 50,000 次 For 调用；计时包含选择和缓存查询。 |
| table-registration | 预先完成 LoadContext.Build 后，只计量 CfdData 的类型表注册。 |

宽表有 32/128/512 个绑定 language 维度的 int 字段，基础值均为 1；稀疏变体仅覆盖 r0.f0，密集变体覆盖每条记录的每个字段，覆盖值为 2。默认 wide 套件沿用原输入的 0/3 个变体，variants 套件使用 128 字段和 3/12 个变体。

现实夹具包含 9 个业务字段和一个内联 data 类型：中文字符串、转义字符串、Option、列表、字典、跨文件循环引用、跨记录插值、内联对象插值和列表中的插值。相邻记录配对引用；基础记录分到两个文件，维度文件先于基础文件。稀疏变体只覆盖 r0.name，密集变体覆盖全部记录的 name，派生模板仍按选择的上下文求值。

多类型夹具将 500 条记录均匀分配到 1/16/64 个不同 CLR 类型，每条记录一个 int 字段。封闭泛型类型和反射调用只用于计时外的夹具准备，计时内使用强类型构造回调。

解析结果在计时外校验文档、记录、字段及覆盖数量；加载结果校验全部基础值，现实夹具还校验引用身份、插值和嵌套值；视图结果校验覆盖、基础对象隔离和重复调用身份。语言语义和错误诊断由独立的 Loader 测试及生成代码集成测试覆盖。

## 结果解释与适用范围

本轮保留类型明确的生成代码和共享 Loader 边界，优化普通标量和字符串解析、绑定后的字段读取、变体验证、来源传递、维度选择缓存及按类型注册。宽表纯解析中位数减少 51.7%–75.1%，现实夹具纯解析减少 11.1%–15.1%；后者仍包含模板解析、字符串解码和嵌套节点构造，不能把宽表比例推广到全部输入。其样本范围也有重叠。

128 字段、12 个密集变体的完整加载仍需约 533.683 ms、302.906 MB 线程累计分配。密集覆盖文本的解析和各变体的字段验证仍是实在工作量。该矩阵没有测量更高记录数、更多维度组合或真实项目的访问分布，不能据此推算任意规模的延迟或容量。

共有的字符串 Get API 用于公平比较，因此结果没有包含生成代码改用字段序号 API 的额外收益。表注册的局部改善同时包含工作向上下文准备阶段的移动，应结合 construction 和 full-load 判断总成本。完整加载和构造阶段分别采样，不能直接用两个中位数相减得出精确的解析占比。

线程累计分配不等于进程峰值、存活堆大小或 GC 暂停时间。每次测量前的强制 GC 仅统一采样起点，不模拟游戏或应用中的收集时序；缓存视图的生命周期和大量维度组合的长期内存尚未由该指标刻画。

每项只有 7 个样本，报告中位数及观测范围，不报告稳定 P95 或统计显著性。两版整组顺序运行，没有随机交错或跨进程重复；无法完全排除温度、系统调度和背景负载漂移。3 个范围重叠项为现实稀疏 parser-only、现实密集 parser-only 和单类型 table-registration。

本次没有 Unity、Mono、IL2CPP、移动设备或真实游戏工程实测，也不把 Loader 收益换算为编辑器整体性能。此前报告使用不同基线和采样协议，其耗时不与本报告拼接或计算累计提速。

## 复现

使用最终版本的同一份 [基准工具](../../../runtimes/csharp/Coflow.Loader.Benchmarks/README.md)，仅切换所链接的 Loader 源码。下面命令从本报告基线提交提取 Loader，分别构建到独立目录；目录示例应使用本机独立临时位置。

~~~powershell
git archive --format=zip --output=C:/temp/coflow-loader-baseline.zip 7854472451e57ff8c4b805fef0cd525ba9c2e393 runtimes/csharp/Coflow.Loader
Expand-Archive -LiteralPath C:/temp/coflow-loader-baseline.zip -DestinationPath C:/temp/coflow-loader-baseline
dotnet build runtimes/csharp/Coflow.Loader.Benchmarks --configuration Release --no-incremental -p:LoaderSourceRoot=C:/temp/coflow-loader-baseline/runtimes/csharp/Coflow.Loader -p:UseBoundLoader=false -o C:/temp/coflow-loader-before
dotnet build runtimes/csharp/Coflow.Loader.Benchmarks --configuration Release --no-incremental -p:UseBoundLoader=true -o C:/temp/coflow-loader-after
$env:DOTNET_TieredCompilation = '0'
dotnet C:/temp/coflow-loader-before/Coflow.Loader.Benchmarks.dll --suite all --records 500 --samples 7 --warmups 2
dotnet C:/temp/coflow-loader-after/Coflow.Loader.Benchmarks.dll --suite all --records 500 --samples 7 --warmups 2
~~~

两次构建完成后再串行执行，保留原始 NDJSON。核对来源文本哈希、阶段、操作数、构建选项和工具源码哈希；元数据中保存了本次源码及二进制摘要。
