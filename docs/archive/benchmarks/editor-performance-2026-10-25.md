# 编辑器性能测量：2026-10-25

基线：`ac18f330`。优化实现见 [性能约束](../../editor-design/performance.md)。[原始数据](editor-performance-2026-10-25.json)。

## 环境与方法

Windows，Intel Core i5-13600KF，32 GiB 内存。浏览器使用 Playwright Chromium 无头模式，生产构建，1280×800 视窗，表格区域 880×480。基线通过 Vite 源码覆盖加载指定 Git 提交，夹具、视窗和采样流程与优化版相同。两个版本串行测量，采样期间不运行构建或其他回归测试。

每个场景滚动 90 个动画帧，舍弃最初两个帧间隔，报告剩余 88 个样本的中位数与 P95。全选执行三次，计时包含输入派发和两次动画帧等待，不能解释成纯 CPU 时间。首次展示包含浏览器导航和合成数据构造。夹具复用真实表格、Inspector 和编辑组件，部分不可变测试数据共享引用；这些结果不代表真实 IPC 传输或完整工程内存占用。

## 前端结果

| 行 × 列 | Inspector | 滚动 P50：前 → 后 | 滚动 P95：前 → 后 | 全选中位数：前 → 后 |
| --- | --- | --- | --- | --- |
| 1000 × 6 | 关 | 17 → 17ms | 17 → 17ms | 32 → 41ms |
| 10000 × 6 | 关 | 17 → 17ms | 17 → 17ms | 46 → 38ms |
| 1000 × 60 | 关 | 150 → 17ms | 200 → 17ms | 82 → 33ms |
| 3000 × 60 | 开 | 283 → 17ms | 333 → 17ms | 1254 → 36ms |
| 10000 × 100 | 开 | 467 → 17ms | 550 → 17ms | 3442 → 77ms |

10,000 × 100 场景中，挂载文本编辑器由 2,548 个降至 52 个，首次展示由 1,366ms 降至 399ms。优化版该轮采样没有超过 33.4ms 的滚动帧。该结论限定于合成数据与本机环境；复杂值、插件和差异展开保留挂载，需要分别测量。

## 后端结果

夹具有效性说明：此版 perf_smoke 在不同文件中重复使用 Item ID。100×1,000 配置实际生成 110,000 条草稿，其中 10,000 Item 因重复身份被剔除，最终模型保留 100,000 Entity，加载过程包含失败后的重试。下表保留该夹具的原始观察；健康工程的核心基线见 [引擎性能测量](engine-performance-2026-10-25.md)，两种夹具不能直接作为优化前后对照。

Release 构建，100 个 CFD 文件、每文件 1,000 条记录，每条记录含 20 列及嵌套/引用数据。记录查询读取其中一个文件。基线与当前版使用相同基准程序；30 次样本在同一会话代际连续查询。

| 指标 | 基线 | 优化版 |
| --- | ---: | ---: |
| 记录查询 P50，30 次 | 52.23ms | 52.42ms |
| 记录查询 P95，30 次 | 53.27ms | 53.97ms |
| 工程加载，重复查询基准中的一次测量 | 30.72s | 30.56s |
| 工程加载，完整流程的一次测量 | 36.30s | 36.51s |
| 源码校验，完整流程的一次测量 | 31.67s | 38.56s |
| 图查询，1,000 节点/3,952 边，一次测量 | 71.62ms | 67.94ms |

记录查询重复样本基本持平，本轮不宣称后端查询吞吐提升。新增列统计把前端全量估宽工作转移到后端；共享 Schema 缓存减少重复构造。大工程加载与源码校验尚未达到交互级延迟；源码校验优化版的单次实测更慢，尚无重复样本支持归因或收益判断。

## 功能验证

- `cargo check --workspace`、`cargo test --workspace`。
- 前端生产构建、355 项单元测试。
- 30 项浏览器交互测试，包含横向滚动期间的编辑草稿与焦点保护。
- 百万单元格选区惰性遍历、排序后的目标身份、只读批量聚合、不兼容类型提前退出、旧版本缓存释放均有回归覆盖。

## 复现

```powershell
node editors/cfd-editor/frontend/tests/browser/performance.mjs --baseline
node editors/cfd-editor/frontend/tests/browser/performance.mjs
$env:PERF_FILES = '100'
$env:PERF_RECORDS = '1000'
$env:PERF_RECORD_SAMPLES = '30'
$env:PERF_SNAPSHOT_ONLY = '1'
cargo run --release -p cfd-editor-core --example perf_smoke
```

`PERF_BASELINE_REF` 可指定前端基线提交，默认 `ac18f330`。后端对照使用独立源码快照构建，并保留各自的可执行文件；运行前核对文件哈希，避免共用 Cargo 输出目录时误测同一个程序。移除 `PERF_SNAPSHOT_ONLY` 可测量完整流程。

## 当前边界

宽表滚动和大选区的收益已经测量。全工程模型构建、源码项目级校验、复杂图布局和百万单元格实际批量写入不在此次已解决范围内。大工程整体无卡顿的目标尚未达到，后续应围绕这些实际瓶颈建立独立基准，并在保留跨文件引用、检查规则和事务行为的前提下实施增量计算。
