## 采样范围

夹具为 500 条记录，分别使用 32、128、512 个 int 字段，所有字段绑定 language 维度；变体数量为 0 或 3。每个变体只覆盖 r0.f0，加载仍校验所有记录的每个已声明单维度变体。每项预热 1 次、在同一进程中执行 5 次，baseline 与 optimized 整组串行运行，采样期间无并行构建或浏览器性能测试。每次先请求 GC，计时使用与生成代码一致的 `CfdField[]`，每次验证记录数量与基础值。

构造阶段从已解析文档开始，包含发现输入、字段验证、对象构造、全部单维度变体验证和表注册；完整加载通过 `CfdLoader.Load` 额外包含解析。两阶段均排除输入文本生成与一次性类型描述符创建。表格为中位数（最小值–最大值），不将 5 次样本解释为稳定 P95。分配量采用当前线程分配字节数的中位数，不代表进程峰值内存。

原始样本：[baseline NDJSON](csharp-loader-2026-10-30-baseline.ndjson)、[optimized NDJSON](csharp-loader-2026-10-30-optimized.ndjson)。

## 工作量与验证

字段描述符在 `CfdType` 创建时复制一次并建立名称索引，记录和维度视图共享布局。字段存在性校验、覆盖绑定、读取和模板路径解析使用该索引；维度视图共享已校验源字典与覆盖索引，只创建自身的求值缓存。变体名称列表在发现输入后统一冻结。

独立计数容器记录调用方提供的描述符集合被读取的次数，见[工作量原始计数](csharp-loader-2026-10-30-work-counts.json)。500 条无变体记录的基线读数分别为 544,032、8,320,128、131,584,512；优化版在描述符创建时读取 32、128、512 次，后续加载不再读取调用方容器。这表示输入布局已被快照复用，不能解释成加载期间没有字段遍历或字典查询。计数容器的耗时不用于上表。

`@idAsEnum` 收集结果复用同一 ID 集合，验证后按已用编号的有序列表单向分配。10 万个新编号的回归用例要求恰好 10 万次候选检查；已有 5 万连续编号后再分配 5 万个编号，也共检查 10 万个候选。稀疏空位复用、flag 位宽、冲突锁文件拒绝和失败不发布均有回归覆盖。该计数仅证明编号候选扫描的线性工作量，生成全流程仍包含有序映射、模型遍历和文件输出。

每个枚举仅生成一份 enum→id 映射，继承树内的表扩展共享独立静态容器；映射按枚举查询初始化。合法的 Types、Constants、Table、Load、Singleton、Ids 等业务枚举使用完整类型名，集成夹具覆盖实际生成与 C# 编译加载。

上述结果适用于本报告的 Loader 夹具。真实项目中的字符串、引用、插值、嵌套集合和不同变体数量会改变成本；没有将局部结果换算为桌面编辑器整体收益。Loader 仍完整校验基础值与所有已声明单维度变体，复杂宽表的解析与对象分配仍是后续测量方向。

## 复现

工具：[Coflow.Loader.Benchmarks](../../../runtimes/csharp/Coflow.Loader.Benchmarks/Program.cs)。默认加载当前 Loader 源码；`LoaderSourceRoot` 可指定基线提交提取出的 Loader 源码目录，目录内保留根目录 `.cs` 与 `Cfd/` 下的 `.cs`。使用相同工具程序将两版分别以 Release、`--no-incremental` 构建到不同目录，再设置 `DOTNET_TieredCompilation=0` 串行执行各自的 `Coflow.Loader.Benchmarks.dll 500 5`。

当前版本可运行：

```powershell
$env:DOTNET_TieredCompilation = '0'
dotnet run --project runtimes/csharp/Coflow.Loader.Benchmarks/Coflow.Loader.Benchmarks.csproj --configuration Release -- 500 5
```

附加第三个参数 `count-descriptors` 启用独立来源集合计数。计数运行与正式时间采样分开保存。完整语义、诊断与身份验证由 Loader 单元测试和 C# 生成集成夹具完成；本工具用于性能观测，不增加常规发布门禁。
