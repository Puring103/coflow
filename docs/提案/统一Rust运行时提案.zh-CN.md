# 统一 Rust 运行时提案

> 状态：待评审提案
>
> 范围：CFT/CFD 语言、运行时契约、Rust 加载执行组件、C# API 与项目架构。

## 1. 目标

- 运行时保持轻量，加载、数据访问和函数执行具备可验证的性能。
- CFT 与 CFD 共用一致的词法、类型和值语义。
- 只保留一套 Rust 运行时实现，C# 仅提供与生成代码配合的 API。
- CFT 编译为可独立交付的契约，供运行时和目标语言代码生成器使用。
- CFD 由运行时根据契约加载、校验、链接和执行。
- CLI、编辑器、LSP 和业务项目依赖同一套 Rust 运行时。

## 2. 总体架构

```text
CFT -> Rust 契约编译组件 -> 不可变契约 -> 目标语言生成代码
                                  |
CFD -> Rust 加载执行组件 <---------+
          ^
          |
       C# API + 生成代码 -> 业务程序
```

Rust 运行时在能力上分为两个组件：

1. 契约编译组件：解析 CFT，完成名称解析、类型检查和布局规划，产出契约。
2. 加载执行组件：接收契约和 CFD，完成数据加载、校验、函数编译、链接、check 和执行。

组件内部的 crate 划分按职责确定，不以拆分文件数量作为目标。项目服务层继续负责配置、路径、文件发现、源码写回、编辑器命令和产物发布，并调用两个运行时组件。

## 3. 契约内容

契约是运行时的稳定输入，应包含：

- 类型、字段、函数、枚举和继承关系的稳定身份。
- 集合、引用、Option、Result 和默认值规则。
- 声明类型、函数参数和返回值的布局描述。
- 常量、默认函数实现、Host 签名和 check 定义。
- 维度、诊断和代码生成所需的元数据。

CFT 编译阶段确定声明及签名涉及的布局；CFD 函数编译阶段补全函数体引入的组合类型、闭包和寄存器布局。执行阶段不得重新推导布局或按字符串发现字段。

契约应支持独立文件交付或嵌入生成产物。具体格式、身份校验和版本规则需要在详细设计中确定。

## 4. 加载执行组件

加载执行组件按以下顺序工作：

1. 解析 CFD，依据契约完成类型检查和默认值物化。
2. 建立记录目录，解析引用、继承和维度数据。
3. 对 CFD 函数进行类型检查、编译和链接。
4. 执行数据校验和 check。
5. 验证并发布不可变快照。
6. 提供查询、函数调用、诊断和执行预算控制。

加载或编译失败时保留最近一次成功快照。快照、句柄、Host 回调和跨语言返回值的生命周期必须统一定义。

check 与 CFD 函数共用类型系统和执行基础，同时保留各自的访问权限、预算和诊断规则。

## 5. CFT 与 CFD 统一

CFT 继续负责类型、布局、默认值和规则声明；CFD 继续负责记录值和函数实现。两者统一使用：

- 词法、标识符、类型引用和 source span。
- 标量、字符串、枚举、集合、对象和引用的值语法。
- Option、Result、函数签名、表达式和函数体的类型规则。
- 默认值与 CFD 字段值的公共解析和校验。
- 诊断和规范格式化规则。

普通 CFD 数据字段允许的表达式范围需要单独确定；若允许加载期求值，必须定义确定性、调用能力和预算。

## 6. C# API 与代码生成

Rust 与 C# 通过稳定的跨语言 ABI 连接。C# API 负责原生资源管理、错误转换和调用生命周期；生成代码负责强类型声明、契约映射、数据转换和函数调用入口。

CFD 解析、语义校验、函数编译和执行统一由 Rust 提供。生成代码不得各自实现一套 CFD 加载器。

数据访问方式需要基准验证：可以批量构建托管对象，也可以提供原生数据视图；高频路径应减少逐字段跨语言调用，并支持批量读取。Host 回调需明确异常转换、重入、线程规则和预算传递。

## 7. 性能验证

实施前建立对照基准，覆盖：

- 原生库与 C# API 的发布体积。
- 契约加载、CFD 解析、函数编译、链接和快照发布时间。
- 构建峰值、发布后常驻内存及托管/原生复制成本。
- 字段读取、查询、集合遍历和批量访问。
- 纯函数、集合运算、闭包、Host 调用和重入。
- 编辑器修改后的重新分析、编译和失败恢复。

性能结论必须区分 Rust 核心性能和完整 C# 调用链性能，并在确定目标平台、数据规模和验收阈值后评审。

## 8. 实施顺序

1. 确认平台范围、契约交付方式、数据表达式边界和性能阈值。
2. 定义统一语言语义、契约格式和两个组件的公共接口。
3. 建立代表性基准，选择 C# 数据访问方案。
4. 将函数编译执行能力整合到 Rust，并接入项目服务层。
5. 实现 C# API 和生成绑定，迁移 CLI、编辑器、LSP 与集成测试。
6. 移除重复的 C# CFD 解析、编译和 VM 实现，更新正式设计与用户文档。

## 9. 待确认事项

- C# 目标平台及 Rust 原生库的分发方式。
- 业务端是否直接加载 CFT，或只接收构建期契约。
- 契约采用独立文件、嵌入生成物，还是同时支持两者。
- C# 使用托管对象、原生视图，还是按场景组合。
- 普通 CFD 字段允许的表达式范围。
- check 与 CFD 函数的语义统一边界。
- 代表性数据规模、性能基线和验收阈值。
