# 实现约定

> 状态：实现设计
>
> 范围：语言规范之外的源码工具、宿主包装和工程约定。本文描述目标实现，不代表功能已完成。

## 1. 统一核心

Rust 提供共享前端和执行核心。CFT 编译器产出契约，CFD 加载器使用契约。
crate 按职责划分，具体组件边界以[核心架构](../2-架构/01-核心架构.md)为准。
对象、固定区、动态区和句柄规则见[运行时数据结构](../2-架构/02-运行时数据结构.md)。

CFT 编译完成后契约只读。CFD 只持有自己的编译结果和运行时函数选择，不回写契约。
check 与函数共用执行机制；每次请求实际执行所选检查，不做增量 check 或检查结果缓存。

## 2. 源码与格式化

- 无损词法保留 token、空白、注释和 UTF-8 字节位置。
- 核心格式化由 CLI、LSP 复用；LSP 将字节位置转换为 UTF-16 编辑位置。
- 结构化 writer 根据类型生成 CFD 局部文本，不依赖通用 formatter 补值。
- 字典从 CFT/CFD 解析、编译到加载和写回都保留原始键值项顺序，不能通过排序映射重排。
- fstring writer 保留 f 前缀、插值表达式和模板文本，不写回预览结果。
- 项目格式化只处理配置声明的 .cft/.cfd 源文件，真实路径去重。
- 跳过维度输出目录中的生成文件；检查模式不写文件，写回使用原子暂存。

## 3. 编译和预算

```text
CFT 源码
  -> 收集声明
  -> 解析名称和类型
  -> 检查默认值、函数、fstring 和 check
  -> 生成类型布局并进行有限的常量优化
  -> 只读契约
```

静态结构限制包括最大深度、节点数和分析工作量。
优化尝试有独立预算，失败时保留原计算，不消耗运行时预算。
执行预算覆盖普通函数、fstring 和 Host 同步重入；检查有独立的顶层执行预算。

解析和编译结果可以复用。检查报告不复用，也不维护增量 check 的字段依赖索引。

## 4. 维度生成

生成类型的身份包含原始类型完整限定名、字段名和维度名。
输出文件名和目标语言名称必须避免命名空间、下划线等造成的碰撞。

工具根据基础记录生成或更新维度 CFD，保留用户填写的覆盖值。
覆盖记录和业务记录共享 key，加载器建立相互引用。
基础值保存在业务记录的内部存储中，生成记录只保存关联和覆盖。
未提供覆盖文件的维度字段也创建对应生成记录，先分配记录身份，再连接引用。

## 5. C# 包装

- Rust 持有权威数据；C# 生成强类型访问包装、codec 和句柄。
- 常规字段访问使用生成的类型和布局信息，不依赖反射。
- 包装不维护另一份完整对象图，也不提供第二套函数执行器。
- 普通函数使用函数包装调用；fstring 字段生成为读取时计算的 string 属性。
- 对象和集合包装保留所属 Runtime 信息；依赖 Runtime 的访问在释放后报错。
- 独立复制出的数字、布尔和普通字符串可以脱离 Runtime 使用。
- 更新创建新 Runtime 并切换入口，不在同一实例中维护多版本快照。

## 6. 编辑与分析

解析和编译失败仍返回诊断、源码树及可用分析结果。
编辑器和 LSP 据此提供显示、补全和修改；成功 Runtime 只用于执行、预览和检查。
原始 fstring 模板与预览文本分别保存，Host 预览显式触发。
CFD 修改复用共享解析器和无损源码树，由项目工具生成局部源码修改。
源码树的保留、编辑分层和预览更新见[编辑与共享语法树](../2-架构/03-编辑与共享语法树.md)。

## 7. 诊断和性能

诊断统一保留错误码、级别、消息、必要源码位置和相关调用位置。
详细追踪可按构建选项关闭，基本错误定位保留。

对象使用固定字段槽，同类型数组连续存储，字典保存有序项并按需建立查询索引。
执行采用寄存器 VM，代码与绑定分开保存；动态值使用稳定句柄和支持引用环的可达性回收。
虚拟机始终解释执行，不引入 JIT。寄存器、存活信息和编码评估见[寄存器与字节码](../2-架构/04-寄存器与字节码.md)。
具体布局遵循[运行时数据结构](../2-架构/02-运行时数据结构.md)。

性能验证覆盖以下场景：

| 场景 | 主要指标 |
| --- | --- |
| 不同规模的记录、引用和维度加载 | 契约体积、编译加载时间、峰值内存 |
| 字段读取、循环、函数、闭包和 fstring | 耗时、吞吐量、分配次数和分配量 |
| C# 集合遍历、批量字段访问和 Host 回调 | 跨语言调用次数、转换和复制成本 |
| 长时间创建字符串、集合及循环引用 | 内存能否趋于稳定、回收耗时及最长停顿 |
| CFD 连续编辑与预览重建 | 修改到预览的延迟、过时构建开销 |

测试同时记录平均耗时、较慢请求和最长停顿。性能目标依据实际配置规模、每帧读取量和更新频率确定。
优先检查跨语言调用和 fstring 分配成本；批量读取接口、字段拆分、压缩布局等优化由测量结果决定。
优化不改变读取次数、声明顺序或对象身份，也不建立第二套执行数据。

先打通共享核心加载、C# 读取、编辑器修改源码并重建预览的完整流程，再用代表性项目建立性能基线。
