# 语言实现细节

> 状态：实现记录
>
> 范围：`docs/1-语言` 纯设计之外的实现选择、宿主接入和工程细节。待实现或决定后移除对应条目。

## 1. 执行核心实现

- 只保留一套语言前端和执行核心，由 Rust 提供。
- 核心在能力上分为两个组件：
  - 契约编译组件：解析 CFT，完成名称解析、类型检查和布局规划，产出契约。
  - 加载执行组件：接收契约和 CFD，完成数据加载、校验、函数编译、链接、check 和执行。
- crate 划分按职责确定，不以拆分文件数量为目标。
- CLI、编辑器、LSP 和 C# 宿主共享同一套核心。

## 2. 契约

- 契约是运行时的稳定输入，包含：
  - 类型、字段、函数、枚举和继承关系的稳定身份。
  - 集合、引用、可选类型和默认值规则。
  - 声明类型、函数参数和返回值的布局描述。
  - 常量、默认函数实现、Host 签名和 check 定义。
  - 维度、诊断和代码生成所需的元数据。
- CFT 编译阶段确定声明及签名涉及的布局；CFD 函数编译阶段补全函数体引入的组合类型、闭包和寄存器
  布局。
- 契约支持独立文件交付或嵌入生成产物。
- 业务端只接收构建期契约，运行时不解析 CFT。
- 契约携带身份与版本信息，加载时校验；不匹配则拒绝。
- Rust ABI、目标平台支持和 C# 资源句柄实现待实现确定。

## 3. 词法与格式化设施

- `coflow-language` 提供保留 trivia 与 byte span 的无损 token 流，CFT/CFD/函数体共享底层扫描原语。
- `coflow-format` 持有 `format_cft` 与 `format_cfd`，CLI 与 LSP 直接复用。
- 单文件宿主直接调用格式化核心；LSP 负责把结果转换为 UTF-16 位置正确的 `TextEdit`。
- runtime writer 生成 schema-guided CFD 局部文本，不调用通用 formatter。
- 项目级 `coflow format [CONFIG_OR_DIR] [--check]`：
  - 只处理目标 `coflow.yaml` 配置的 schema 和 data 路径，以及小写 `.cft`/`.cfd`。
  - 重叠路径解析为真实路径后去重。
  - 跳过 `dimensions.*.out_dir` 下的生成文件。
  - 默认模式原子替换变化文件；`--check` 不写文件。

## 4. 结构限制

```rust
pub struct StructuralLimits {
    pub max_depth: u64,
    pub max_nodes: u64,
    pub max_analysis_steps: u64,
}
```

- `max_depth` 与 `max_nodes` 限制解析和编译的输入结构规模。
- `max_analysis_steps` 限制继承链、check 索引、值依赖等静态图分析。
- 检查器执行预算使用独立的 `EvaluationLimits`。

## 5. schema 编译流水线

```text
CftModuleSet
  -> collect_symbols -> SymbolTable
  -> resolve_types -> ResolvedTypes
  -> resolve_values -> ResolvedValues
  -> validate_checks -> ValidatedSchema
  -> lower_schema -> CftSchema
```

- 每个阶段接收不可变输入和上一阶段产物，返回下一阶段产物及诊断。
- 名称解析、类型推导、常量求值和依赖提取实现为输入决定输出的函数。
- `AnalysisBudget` 作为显式参数传入静态图分析阶段。

## 6. 字节位置与 UTF-16

- 语言层的 span 使用 UTF-8 byte offset。
- 宿主负责把 byte offset 转换为 UTF-16 position；语言层不混用两套坐标。

## 7. 维度数据文件

- 维度数据以字段为单位记录，记录 key 与基础记录一致。
- 现有实现使用辅助记录名 `__coflow_<维度名>_<声明类型名>_<字段名>`；目标生成类型名为
  `原始类型_字段_维度名称`。
- 普通类型文件位于维度目录中的 `<声明类型名>_<字段名>.cfd`，singleton 使用 `<类型名>.cfd`。
- `coflow build` 生成或更新维度文件，`default` 展示基础字段值。
- C# 侧包装类型提供 `Default` 和 `For(variant)` 访问。

## 8. C# API 与代码生成

- 生成代码只包含特定 schema 的强类型声明、schema 描述和 runtime codec。
- `Coflow` 维护工作状态和最近一次成功发布的快照；`Compile()` 完成数据实体化、函数编译和全局链接。
- 生成 class 和 struct 携带内部值 ID；旧快照值可读但不可用于当前实例执行。
- 函数值统一生成为 `CoflowFunction<...>`，应用和 Host 调用时必须显式传入 `Coflow`。
- Host 由应用提供，每种 Host 类型在工作状态中最多有一个当前绑定。
- VM 使用寄存器、Arena 和 program，不在执行阶段推导布局或按字符串发现字段。
- 执行预算由 `CoflowOptions` 按实例配置。

## 9. 诊断身份

- 每条诊断和 fault 在实现中具有稳定的错误码。
- 错误码、严重级别和消息模板由诊断模块集中维护；条件清单见 `docs/1-语言/11-错误与诊断.md`。

## 10. 增量分析

- 名称绑定依赖失效：复用前以当前候选符号目录重新验证依赖；解析结果仍唯一且指向同一声明时复用
  模板，声明新增、移除、歧义或类型迁移时重新分析对应单元。
- 跨记录依赖索引：
  - 同一宿主记录的字段修改只重查该记录。
  - 跨类型引用字段变化保守重查依赖规则的全部宿主记录。
  - `records(Type)` 的新增、删除、重命名或类型迁移使相关规则失效。
  - 数组 index、dict key 和内联 object path 归一化到其顶层存储字段，不按实际读取路径缩小依赖。
- 系统保留 Host 类型的完整清单在实现时按需确定；当前唯一确定的是 `std::Check`（提供 `require`）。
