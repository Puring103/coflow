# 非编辑器性能优化方案

## 范围与验收原则

本方案覆盖 Rust 共享 Runtime 的加载、查询、修改与校验，独立 CLI 的完整命令事务，以及 C# Loader 的加载、查询和维度视图。桌面编辑器、前端渲染和 LSP 不在本方案的耗时口径内。基准协议见[非编辑器性能基准](non-editor-benchmarks.md)，现有约束见[性能验证](performance-validation.md)与[增量代次](../runtime-design/incremental-generations.md)。

Rust 热会话、CLI 新进程事务、C# 已有文本加载承担不同工作，分别建立目标。C# Loader 接收已解码的 CFD 文本及生成类型，不执行 CFT 编译、Rust 业务规则检查或文件发布；文件读取加加载另行计量。三个入口的绝对耗时不能直接作为语言实现之间的性能对比。

优化以保持语义为前提，包括有效值、显式来源、诊断代码与顺序、源码位置、引用身份、维度回退、旧快照独立性、执行预算、冲突检测和失败恢复。算法工作量减少、端到端时延达标、内存达标分别验收。不得通过省略校验、提高执行上限、缩小实际批次数量或丢弃失败样本满足目标。

本文给出实施目标与验证路径，源码分析不代替实测。新增绝对时延及内存预算以本轮归档报告中的目标表为准；报告未给出的项目标记为待定预算，不视为已达标。既有性能目标继续有效。

## 已实现的优化机制

实现状态与性能目标达标状态分别登记。目标数值仍以基线报告的预算为准，正式前后测量、宿主范围与剩余工作见[优化验证归档](../archive/benchmarks/non-editor-optimization-2026-10-29/README.md)。[G1—G13 逐项状态](../archive/benchmarks/non-editor-optimization-2026-10-29/goals-status.md)分别列出机制、实测和缺口；当前整体目标尚未全部完成，G7 和 G11 为部分实现，G12 尚缺 IL2CPP 实测。

| 范围 | 实现机制 | 保持的语义与验证 |
| --- | --- | --- |
| 错误来源与恢复 | 同一来源的错误和健康记录共享行索引；恢复使用流式无损词法扫描，保留记录候选偏移 | 字节跨度、UTF-16 列、CRLF、非 BMP 字符、节点预算与诊断顺序 |
| 模板错误级联 | 按实际读取身份传播剔除；累计失败轮、依赖探测与最终构建工作量 | 保留原输入句柄和逐轮顺序；受影响根完整执行预算；健康记录、引用及维度仍最终完整校验 |
| CLI 候选与报告 | 复用配置、源根、路径映射及解析来源；语义快照直接保存字段状态，维度只保存相对基础的差异 | 空变体存在性、显式同值覆盖、默认值、模板间接渲染、成员及上下文增删；完整报告与密集参照对照 |
| CLI 独立批次 | 连续且记录身份唯一的字段修改按文件分组，每个文件一次生成并验证候选 | 重复记录及非字段操作形成边界；中间节点预算、原序首错和成功前缀不变；发布失败仅在明确完整恢复且字节原样时重放 |
| 维度覆盖与投影 | 覆盖按坐标与值比较；完整投影复用未影响值树，只重新求值覆盖和模板依赖闭包 | 来源位置单独刷新；选择组合来自原始基础；schema、预算或健康前提变化时完整重验证；引用索引符合所选视图 |
| 基础模型成员变化 | 原始输入证明未变后共享非模板记录值树；按新句柄顺序重建身份、表与引用索引 | 模板和引用目标类型改变的宿主完整求值；维度成员变化完整构建；检查及来源按稳定坐标重映射；后续字段增量继续正确 |
| 成员变化的精准检查 | 按规则实例保存实际字段与记录集合读取；成员变化只使真实读取者失效，并为新增记录补全本体及拥有子树规则 | 空集合、动态短路、继承、虚拟 ID、引用目标实际类型变化、嵌套及维度对象、删除后恢复、诊断顺序和旧快照；读集不完整时保留静态规划，预算中断后完整恢复 |
| C# 加载 | 描述符字段槽位、名称池、不可变源共享、按 CLR 类型分桶建表；记录状态只留身份元数据，根语法包装可回收；无类型 ID 索引保存唯一／歧义状态 | 继承表与引用身份、复杂值、默认值、根包装回收后的首次组合视图、身份及覆盖诊断顺序、全部声明单变体加载前校验 |
| C# 查询与深依赖 | 表热查询直达具体 Dictionary，Keys／Values 保持只读包装；缓存选择转换和不可变变体元数据；普通引用由显式 DFS 记录栈调度，复杂读取的筛选器在异常第一遍搜索登记暂停帧 | 32 层原生调用段、256 层逻辑边界、循环身份、DFS 错误顺序、混合引用／模板／集合恢复、集合一次构造、上下文隔离 |

模板错误闭包仅复用可证明等价的基础输入；singleton、输入诊断或身份歧义仍由普通编译阶段处理。统计包含首次失败、闭包探测与传播、最终构建，不能仅以最后保留记录的工作量代表整个拒绝过程。

成员变化复用减少重复值验证和物化，仍包含全局身份及引用索引工作，不能按常数复杂度解释。CLI 候选仍使用独立临时目录；基线与最终候选的数据模型分别构建，操作语法树缓存尚未统一到 Runtime 的来源批次。完整事务共享不可变输入与数据代次仍属于后续优化范围。

成员检查复用以规则实例为失效单位，合并同一规则所有根的字段和集合读取，再按稳定坐标恢复当前句柄。字段索引按记录哈希分桶、按完整记录及字段排序；`All` 变化只查询所属桶中的记录坐标前缀，不逐记录扫描全部桶，也不额外常驻一套按记录聚合的读取者。真实桶碰撞、字段和投影区分、同桶连续更新与旧快照共享均有专项回归；集合依赖另建反向索引，空依赖不分配集合。成员增删通过新旧模型的真实入边标记宿主顶层字段及维度坐标，使引用字面量未变而目标实际类型变化的类型判断、虚拟 ID 与字段读取仍重新检查。新增记录以及 `All` 宿主完整枚举本体和拥有子树的全部规则，任务继续使用原有去重、执行顺序与预算。

该路径已与独立完整检查逐代对照，验证空／非空集合增删、短路后读取集合变化、多根规则在前根错误修复后的恢复、父子类型、成员改名和顺序重排、嵌套及维度实例，以及保留裸引用宿主时删除并恢复目标。对照包含诊断内容、顺序、逻辑位置和全部旧快照；空投影、未知维度拒绝、空覆盖及未知变体回退均保持原语义。任务规划或求值预算中断后，下一代仍完整检查。具体工作量与端到端耗时按最终归档判定，不以单个小规模正确性用例推断十万条目标达标。

C# 的 .NET 与 Unity 验证分别记录。[R6 功能收据](../archive/benchmarks/non-editor-optimization-2026-10-29/verification/csharp-r6-build-smoke.json)记录 C# Release 86/86 通过及 Mono 主线程／默认新线程共 30 项深链、循环与恢复契约检查通过。[R6 正式比较](../archive/benchmarks/non-editor-optimization-2026-10-29/managed-r6/comparison.md)已完成两宿主、24 个场景的三轮配对，仍有七项托管性能目标未达，具体结果与后续工作见 [C# 验收](../archive/benchmarks/non-editor-optimization-2026-10-29/remaining-work-csharp.md)。全项目汇总后的耗时、内存和目标状态统一以归档的 `final-results/target-status.json` 与逐项比较为准。IL2CPP 只有实际构建和执行成功后才能登记为已覆盖。性能测试不改变普通开发的 Rust 必需门禁。

## 规模变量与结果分类

| 变量 | 含义 | 必须同时记录的因素 |
| --- | --- | --- |
| N | 基础记录数 | 千条、万条、十万条；实际输入字节数 |
| F | 每条记录的字段数 | 8、20、100 字段，以及标量和复杂值构成 |
| T | 可访问记录类型数量 | 实际类型、继承关系、父表和子表数量 |
| S | CFD 源文本总字节数 | 文件数量、单文件大小、覆盖文件字节数 |
| B | 一次操作实际修改的文件集合 | 修改字节数、实际修改记录与字段数 |
| R | 受影响记录的依赖闭包 | 直接变化、模板传播、引用拓扑、维度上下文 |
| V | 所有维度各自已声明变体数的总和 | 维度数、每维变体数、稀疏或密集覆盖 |
| C | 一次选择中同时生效的维度数 | 首次组合、重复组合、组合顺序 |

必须区分以下结果状态：已完成实测、语义验证通过但未正式采样、超时、预期语义拒绝、工具失败，以及未覆盖。超时值是截止边界，不能当作该操作的实际耗时。未测的峰值、长尾或宿主结果保持空缺。

本轮 C# 的健康 `ring` 是多个最多 64 条记录的独立环，不代表万条递归链。未知变体回退是合法视图操作；超过构造深度上限的长链拒绝属于限制与诊断路径，必须使用独立夹具测量。现有健康环结果不能证明长链拒绝的时间、内存或诊断质量。

| G11 | 稀疏维度校验与首次视图的新增工作随覆盖及依赖闭包增长 | 将必须的基础遍历与上下文求值分开计数；完整验证所有已声明单变体 |

G6—G13 的工作量目标用于判定算法是否改善，不能代替端到端预算。目标登记应包含基线结果标识、夹具摘要、宿主、P50/P95/P99 样本数、分配和保留内存口径、优化后结果标识及通过状态。新增数值预算与相对收益目标统一记录在归档报告，避免在不同文档维护不一致阈值。

G7 当前为部分实现：配置、路径、schema 与操作语法树已按候选代次复用，维度语义快照采用相对基础的稀疏表示，最终差异采集复用最终验证会话。基础字段快照仍分别遍历基线与候选的全部记录；基线与候选尚未共享不可变原始输入树及数据代次，操作缓存、Runtime 加载与差异来源解析也未统一。因此“整笔事务按受影响集合更新”的目标保持待完成，不能由局部缓存命中或维度快照稀疏化推断全部实现。

## 基线瓶颈与优化工作

本节源码定位与瓶颈描述绑定优化前基线 `3742bf1e9dc8d3a22a263f1db48be32412b1b3a4`，用于说明各目标的工作来源。当前已交付机制以上节为准；以下实施项仍须分别登记实现、实测和预算达标状态。

### 1. Rust 结构预算拒绝、错误级联与部分模型构建

#### 单文件节点预算与诊断映射

[`StructuralLimits::default`](../../crates/coflow-language/src/limits/mod.rs) 的 `max_nodes` 为 1,000,000；[`Parser::new`](../../crates/coflow-language/src/cfd/parser.rs) 为每个 CFD 文件建立累计语法节点预算。当前 Runtime 矩阵的 20 字段、8 个数组元素夹具每记录计 59 节点：字段与根值 40、数组元素 8、字典额外节点 3、`Some` 内值 1、内联 `Stats` 额外节点 5、根 block 与记录 2。格式串与对应字面量都计一个值节点，模板开关不改变此计数。计数口径由 [`CfdAst::structural_node_count`](../../crates/coflow-language/src/cfd/structure.rs) 定义。

该夹具单文件完整解析上限为 16,949 条，共 999,991 节点；第 16,950 条触及下一次超限收费。十万条放入一个文件需要 5,900,000 节点，属于预期预算拒绝；分为一百个文件后每文件 59,000 节点，属于健康加载布局。16,949 是该固定夹具的边界，不是所有 CFD 记录的统一数量上限。边界验证已确认 star 引用且关闭模板的 17,000 条输入保留 16,949 条，并报告 51 条具体节点超限诊断；正式耗时以归档样本为准。

[`cfd_loader/mod.rs`](../../crates/coflow-runtime/src/cfd_loader/mod.rs) 为健康记录来源构建了 `LineIndex`。错误路径 [`cfd_error_to_diagnostics`](../../crates/coflow-runtime/src/cfd_loader/diagnostics.rs) 仍对每条诊断调用 `byte_range`，继而由 [`byte_position`](../../crates/coflow-runtime/src/api/diagnostics.rs) 从源码开头扫描到起止偏移。预算耗尽后，解析器继续恢复到后续记录并逐条产生诊断，因此 D 条位于大文件后部的错误可形成 O(D×S) 的重复字符扫描。

节点截断还可能使保留记录的引用或模板目标缺失。该情况可以与下述部分模型重建循环叠加：纯预算拒绝、模板级联、两者组合分别计量，组合超时不能全部归因于行列转换。

P0 实施内容：

1. 在单个来源的加载上下文共享 `LineIndex`，健康来源、语法错误和数据草稿转换错误统一使用该索引。保留现有字节偏移到 UTF-16 行列的定义，避免多阶段重复构建索引或按每条错误扫描文件前缀。
2. 显式识别累计节点预算耗尽状态，使用有界的源码扫描继续定位按契约需要报告的后续错误。后续扫描不再构造无法接纳的完整值树，也不为恢复保留整份无损 token 数组；保留已接纳 AST、必要定位状态及实际需要输出的诊断。节点预算、代码、消息、来源跨度、错误顺序和健康记录保留规则均保持一致，不以直接放弃剩余来源或静默截断诊断替代优化。
3. 增加行索引构建次数与扫描字节、位置转换调用与行内扫描字节、恢复扫描字节、诊断数量和临时 token 峰值计数。与部分构建的累计候选访问、字段求值及边访问分开报告，明确源码拒绝和依赖传播各自的成本。
4. 以 `load_budget_rejected` 记录预算拒绝结果、保留记录数和具体结构诊断，保存样本开始/完成阶段。健康 `load_checks` / `load_no_checks` 仍要求完整记录与无诊断；预算拒绝不进入成功加载中位数。

G13 的验收用例：

- 固定 20 字段、数组长度 8、单文件，覆盖 16,949 / 16,950 / 17,000 / 20,000 条边界；star 且关闭模板时分别验证完整接纳或预期拒绝，17,000 与 20,000 条保留 16,949 条并分别产生 51 / 3,051 条节点诊断。通过后再扩至十万条容量拒绝。
- 同一 20,000 条输入采用 1 / 2 / 10 文件，核对每文件预算边界、完整或部分记录集合、全部诊断与位置；健康时延与拒绝时延分列。模板开关对照验证节点计费不变。
- 单独对固定文本的 100 / 1,000 / 5,000 个首部、中部、尾部跨度映射计数，覆盖 ASCII、中文、非 BMP 字符、CRLF、长行和 EOF。与原位置转换结果逐项一致，并确认索引扫描次数不随 D 增加。
- 覆盖预算耗尽前后的普通语法错误、分组记录、维度块、字符串与注释内分隔符，以及修复后重新加载。采用小节点预算验证精确收费边界和诊断顺序，避免只用大数据耗时测试语义。
- 分别测 star/无模板、ring/无模板、ring/模板及独立健康分量混合；预算拒绝本身满足 G13，模板阻断传播同时满足 G6，接受集合和完整诊断均与独立参照一致。

优化保持默认 1,000,000 节点限制。支持更大的单文件容量属于独立预算决策，不能通过默默提高限制让拒绝夹具成为健康样本。

#### 部分模型构建与模板级联

[`loading/load.rs`](../../crates/coflow-runtime/src/loading/load.rs) 的 `build_partial_model` 从第 898 行开始。每次失败按诊断剔除候选记录，然后重新登记全部剩余记录与维度并调用 `build_partial`。如果模板依赖链每轮只暴露下一个阻断错误，累计候选访问量可接近 N×(N+1)/2。成功返回的统计来自最后一次构建，单看该统计不足以反映失败重试成本。

该风险针对会阻断构建并进入剔除循环的错误。模板引用失败路径见 [`build/resolve.rs`](../../crates/coflow-model/src/build/resolve.rs)；普通缺失引用可在后续阶段产生可编辑诊断，不能把所有引用错误都归类为平方退化。

实施内容：

1. 在 Runtime 汇总所有失败和成功轮次的候选数、来源登记数、字段求值数、依赖边访问数、诊断数和分配峰值。正常加载的计数不引入全量诊断坐标预分配。
2. 将已经判定的记录状态与依赖失败保存在同一构建上下文，用工作队列传播必要的重新判定，避免每剔除一条记录就重建所有无关记录。环依赖按现有语言语义处理；若采用强连通分量，必须证明与现有接受集合及拒绝规则等价。
3. 建立稳定的诊断归并和来源映射。调度顺序变化不能改变可观察诊断顺序，关联标签不能错误剔除其他健康记录。
4. 对纯语法错误、值错误、模板链头部或尾部错误、多个独立失败分量、健康记录与错误链混合、错误修复分别比较完整重载结果。

验收同时要求 G6 和既有健康加载回归边界。独立保存超时样本与最后有效阶段计数；错误链完成处理后，再比较接受记录、所有诊断及其来源。不能通过遇错立即放弃健康数据、截断诊断或增大预算规避级联成本。

### 2. Rust 热写、成员变化与大文件

[`loading/load.rs`](../../crates/coflow-runtime/src/loading/load.rs) 第 772 行尝试字段增量构建。能否复用由 [`build/incremental.rs`](../../crates/coflow-model/src/build/incremental.rs) 第 358 行的 `can_reuse_model` 决定：旧模型不健康、投影模型、schema 或限制变化、数量变化、句柄无效、记录 ID 或实际类型变化都会离开当前增量路径。第 396 行的 `resolve_replacements` 重建受影响记录，并在各已声明变体中重新求值受影响记录。依赖在维度上下文取并集，因此局部变化可能形成较宽的保守失效集合。

[`cfd_loader/writer/batch.rs`](../../crates/coflow-runtime/src/cfd_loader/writer/batch.rs) 第 103 行对候选源进行完整解析。同文件独立字段批次已经能够合并候选；变化文件仍按完整源文本处理。对预算内的大文件，模型求值接近局部并不意味着文本生成、解析、来源调整和写盘接近局部。标准十万条、20 字段夹具的单文件布局按前节登记为预算拒绝；健康布局对照使用各文件均在预算内的相同记录总量。

实施分为三组，分别保留阶段计时：

- **字段与依赖增量：**记录直接变化字段、真实受影响字段、跨记录模板传播及维度上下文。先消除无关来源和身份访问，再评估字段级替换和结果相等时停止传播。相等判断必须保持默认值、显式 `None`、来源变化及预算计费语义。
- **成员与来源增量：**建立可复用的记录身份、类型成员和反向引用索引更新路径，覆盖创建、删除、重命名、迁移及跨文件移动。区分业务身份、代次句柄和文件中的位置；旧代次仍保持一致视图。schema 和输入范围改变时可以保留明确的完整路径，但必须输出原因及工作量。
- **变化文件处理：**先测出候选文本、完整解析、来源映射、文件 staging 和实际发布的占比。优先消除同一事务内的重复解析与复制。若完整解析成为主要成本，再实现按可靠语法边界重解析与来源偏移更新，并验证词法跨界、转义、多行字符串、注释、分组和末尾插入。原子发布成本按真实文件字节数单列。

验收使用同一条修改在单文件、十文件、百文件布局下的对照；固定 B、R 后扩大无关记录数量；另测高扇入导致 R 接近 N 的真实最坏情况。全量校验规则需要访问全体记录时，规则工作量与模型增量工作量分别解释。不得把规则检查、文件发布或目录复制成本隐藏在未计时步骤中。

已有维度覆盖文件单列验收。固定万条基础记录与两维各十个变体，在实际 `variants.cfd` 中修改和清除一个已有覆盖；记录文件字节数、同文件覆盖数、实际检查的维度输入和求值根字段。覆盖文件解析与基础模型/变体求值分开计时，避免用专用小 `bench.cfd` 的结果代表大文件。优先按变化覆盖定位受影响记录与上下文，复用其他覆盖的校验和结果；全量独立重载核对所有基础值、变体值与 Missing 状态。

完整维度投影采用独立专项。[`model/projection.rs`](../../crates/coflow-model/src/model/projection.rs) 第 58 行遍历全部记录并通过 `draft` 重建值，第 109 行重新解析格式串，随后重新构建模型及复制维度元数据。先共享不可变字段、已解析模板和维度元数据，再按当前选择和依赖闭包求值，保留引用、模板上下文、组合顺序与旧投影身份。扩大无关记录及变体数量时分别记录草稿构造、模板解析、字段求值和元数据复制次数。重复相同选择已有共享快路径，优化不得使它重新承担全量工作。

健康加载按来源发现/读取、语法解析、模型构建、规则执行和索引装配保存阶段计时及分配证据。无规则与有规则基线使用相同输入，先减少重复数据表示、共享 schema 元数据及来源索引，再处理占比最高的阶段。规则确实需要全体记录时保留必要扫描与执行预算；加载目标不能依靠关闭既有校验达到。

### 3. CLI 事务与语义差异

[`src/main.rs`](../../src/main.rs) 第 327 行捕获输入快照；[`automation/transaction.rs`](../../crates/coflow-runtime/src/automation/transaction.rs) 第 189 行将捕获文件写入候选，第 204 行建立完整语义基线。第 241 行再次捕获候选输入，第 257 行解析数据来源。第 928 行打开最终候选数据会话。

基础语义快照在 [`automation/semantic_diff.rs`](../../crates/coflow-runtime/src/automation/semantic_diff.rs) 第 153—158 行为每条记录映射来源文件。事务传入的路径回调调用 `unshadow`；该函数在 [`automation/transaction.rs`](../../crates/coflow-runtime/src/automation/transaction.rs) 第 391 行重新取得 `original_view`，后者在第 429—435 行克隆项目、重新解析配置 YAML 并复制配置文本。随后第 392—399 行重新构造候选与原始项目的源根，并依次映射祖先路径。[`project/mod.rs`](../../crates/coflow-runtime/src/project/mod.rs) 第 200—212 行的 `source_roots` 会规范化每个源根；[`project/paths.rs`](../../crates/coflow-runtime/src/project/paths.rs) 第 121—123 行为已存在路径执行文件系统元数据查询与规范化，第 161—164 行的展示路径转换再次规范化目标和根目录。同一文件中的记录重复承担这些工作。

固定源根数量及路径布局时，以上路径映射属于按记录数增长的高常数 O(N) 开销，不能归类为 N²。无变化写入与预览仍生成前后快照，因此也会发生重复配置解析和路径 I/O。源根、非标准扩展名映射数量及祖先层数增长时，逐次映射还会乘上对应扫描量；文件与根目录的实际访问次数需要独立计数。

第 983 行的最终语义快照已经复用校验后的数据会话，不能把它描述为差异阶段再次无条件加载模型。但是 [`automation/semantic_diff.rs`](../../crates/coflow-runtime/src/automation/semantic_diff.rs) 第 153 行仍遍历所有基础记录，第 173 行起对每个已声明单维变体投影并捕获字段语义，局部写入也可能承担完整差异表示的生成成本。

CLI 批次采用逐操作写入链。[`automation/operations.rs`](../../crates/coflow-runtime/src/automation/operations.rs) 第 131 行顺序执行操作，第 149 行为每项新建 Writer；字段修改在第 217 行读取记录及完整文件文本，第 271 行调用 `write_field`，第 285 行立即向临时候选文件发布。[`automation/transaction.rs`](../../crates/coflow-runtime/src/automation/transaction.rs) 第 301 行克隆完整文本；第 346—353 行发布后调用 `refresh_source`，后者在第 331 行再次完整解析，并在第 103—118 行移除和重建该文件的记录索引。单项 `write_field` 在 [`cfd_loader/writer.rs`](../../crates/coflow-runtime/src/cfd_loader/writer.rs) 第 338 行把长度为一的请求交给批次 Writer；[`writer/batch.rs`](../../crates/coflow-runtime/src/cfd_loader/writer/batch.rs) 第 39、45、83 行分别解析原文本、解析候选和降低整个候选文件。

Rust Runtime 在 [`writes/stage.rs`](../../crates/coflow-runtime/src/writes/stage.rs) 第 208 行把已分组请求一起交给 Writer，同文件独立字段批次已有聚合路径；CLI 的逐项调用没有获得该收益。令 K 为某文件的实际修改操作数、S_file 为文件字节数，当前 CLI 批次的文本复制、解析及候选发布可产生 O(K×S_file) 工作量；K 随文件记录数增长时可出现平方放大。此项是批次额外成本，同值单项跳过 Writer 后仍承担前述配置、路径和语义快照成本。

实施内容：

1. **先实施配置与路径缓存。**每个候选配置与输入范围代次保存一次已解析的原始项目视图和两套源根，按唯一源文件保存候选路径、原始路径及展示路径的映射。快照记录复用文件映射，不逐记录调用 YAML 解析或文件系统规范化。配置与输入范围变化时重建相关缓存；创建、删除和迁移更新对应文件映射。符号链接入口、非标准扩展名、外部文件、不同卷及尚未创建的文件保持现有身份语义。此项可先独立交付，不依赖局部语义差异重构。
2. **聚合经证明独立的字段批次。**按请求原序识别安全组，依据记录身份、路径读写范围、值解析依赖和前置条件确认组内操作互不影响。每个安全组对同一文件只构建一次候选、完整验证一次候选语法，并复用验证后的语法或降低结果，统一更新记录索引及临时候选文件。重叠路径、祖先与子路径、集合下标变化、默认值物化及依赖前项结果的操作均形成真实执行边界。创建、删除、重命名、迁移和配置修改保持原序；不通过未经证明的重排扩大分组。
3. 使用一次事务内的不可变输入集合及候选覆盖层，共享未修改文本、已解析来源、schema 和基线模型。候选只保存变化内容、来源操作和实际需要的文件发布数据。
4. 将查询、修改、结构验证和语义差异接入同一候选代次，避免各阶段重复发现、读取或解析同一份未变输入。先优化单次 CLI 调用，不把持久后台服务作为前提。
5. 将语义差异分解为记录成员、来源变化、基础有效值、显式值和维度值；按变化字段及依赖闭包更新。维度模板间接变化必须包含在差异中。
6. `--details` 只展开请求的细节，但无细节模式仍返回完整且正确的计数。预览、同值操作和失败候选使用同一语义模型，保留不发布行为。
7. 将完整输入修订检查放在其安全边界，减少安全边界内部的重复工作。提交前冲突检查和 all-or-nothing staging 保持有效。

配置与路径缓存的工作量目标：路径映射阶段的配置解析、候选源根构造和原始源根构造各不超过每候选配置与输入范围代次一次；映射及展示路径的规范化次数随唯一源文件数和源根数增长，不随同文件记录数增长。固定十个文件扩大记录数时，这些次数应保持稳定；固定记录数改变文件数量时，按实际唯一文件数验收。分别记录 YAML 解析、源根构造、映射命中与未命中、元数据查询和规范化次数，并在同值、预览和真实写入上验证。提交前的修订与冲突复核单独计数，保留其完整输入安全边界。

批次工作量按安全组和文件计数：独立字段组的候选构建、候选完整语法验证、降低、索引更新和临时文件发布次数不随组内 K 增长；原文本未缓存时的首次读取与解析单列。对照现有顺序执行，验证有效值、显式来源、前置条件、自动引用更新、操作序号及首个失败位置。中间前缀超出节点预算而最终文本回到预算内时，仍须在原操作位置拒绝；错误定位可以采用独立失败路径，不让健康批次重新承担逐操作完整解析。跨文件交错操作、同字段多次修改、插入后引用、删除后访问、重命名后修改及失败回滚均使用顺序语义对照。

解析计数必须标明所属阶段。当前健康安全组中，Writer 对每个文件生成并完整验证一次候选，随后复用已验证 AST 降低；发布到临时候选后，CLI 的 `refresh_source` 仍重新解析文本以更新操作 AST 和记录索引。操作缓存测试中的初始解析与发布后刷新次数不包含 Writer 的原文／候选解析，也不包含语义基线和最终 Runtime 数据加载及差异来源解析，不能作为整笔事务的总解析次数。完整验收分别记录上述阶段，后续将已解析来源接入共享候选代次以消除跨阶段重复工作；安全组失败时为保持原序首错所需的额外解析另列。

验收以真实新进程为单位，保存阶段计时、读取字节、候选落盘字节、来源解析次数、模型构建次数、差异字段数和输出字节数。每个修改样本在计时外独立重载验证。预览、拒绝、同值和冲突场景比较完整实际输入的路径与内容摘要，验证没有新增、删除或改写输入文件。同文件批次使用真实 `affected_records`，不能把裁剪为较小批次的结果标作千项批次。

### 4. C# 字段描述符、建表与加载分配

[`Descriptors.cs`](../../runtimes/csharp/Coflow.Loader/Descriptors.cs) 为每个类型快照字段顺序并建立名称到槽位的共享索引。[`Loading.cs`](../../runtimes/csharp/Coflow.Loader/Loading.cs) 按槽位保存源节点、覆盖、读取结果和字段状态，字段登记与首次读取避免重复线性扫描描述符。按实际 CLR 类型的可赋值关系分桶后，建表只遍历实际成员，父表与派生表中的同一记录共享业务对象。表字典按插入增长容量。

记录状态只保存 ID、类型、路径和跨度，槽位建立后根 Record、Field 和 Fields 语法包装可被回收。Reader 继续持有默认值、模板、覆盖与后续视图需要的表达式。无类型 ID 索引直接保存唯一记录或持久歧义状态，限定引用继续使用继承根与 ID 索引。身份、单例和覆盖校验完成后，Reader 按原文档及记录顺序建立，保持原序首错。

[`CfdParser.cs`](../../runtimes/csharp/Coflow.Loader/Cfd/CfdParser.cs) 与名称池在一次加载范围内复用字段名和类型名，扫描名称时先比较源片段，池中缺失才创建字符串。名称哈希已将两个 UTF-16 码元无损打包，并保留长度、随机 HashCode 与完整 Ordinal 碰撞比较；记录 ID 与业务标量独立保存。生成代码继续使用强类型构造与填充委托；业务对象、Reader 结果数组和内联对象缓存的剩余成本需要分别剖析。

后续工作按实测占比推进：

- **保留堆与分配：**在结果存活及完整 GC 后采集堆快照，确认根包装回收和 ID 索引的节省；分别量化源值节点、数字文本、ScalarValue、`object[]`、状态数组、值类型装箱和业务对象。独占大小与共享引用分开，累计分配与保留内存分别报告，再决定紧凑标量及值缓存表示。
- **构造状态：**剖析复杂值夹具中内联 Reader 缓存和空暂停容器的保留链，评估构造完成后的释放或压缩。普通 Reference 及 Option／Dimension 包装的显式 DFS 调度已落地，复杂读取继续由异常筛选器登记暂停帧；32 层原生调用段、256 层逻辑限制、循环身份、混合路径恢复、集合一次构造及深度优先错误顺序继续作为验收条件。
- **解析与来源：**根据阶段计时确认名称池以外的解析成本。进一步的切片表示或容量策略需保持字符串转义、Unicode、诊断跨度及输入所有权；文件顺序和诊断确定性保持不变。

验收采用 scalar8、scalar20、scalar100、tables32 和复杂值夹具，分别改变 F 与 T，防止只在单一 20 字段表上确认收益。记录描述符比较次数、表成员访问次数、总分配、GC 次数、GC 后保留内存以及加载时延。新代次加载时保留旧对象，检查两代均可正常访问，随后释放旧代次验证其可被回收。加载、查询、恢复及文件尾未知类型拒绝均独立检查性能回退，不能用健康加载改善替代错误路径验收。

### 5. C# 维度校验、首次视图与缓存

[`Loading.cs`](../../runtimes/csharp/Coflow.Loader/Loading.cs) 在基础记录构造后完整验证每个已声明单维度变体，每个临时校验视图完成后释放其对象图。业务首次 `For` 按需构造并缓存独立视图。不可变源节点与覆盖槽位在视图间共享，每个视图独立保存求值状态；已确认不依赖上下文的标量及其数组、Option 结果可以复用，模板、引用、内联对象、字典与常量别名在当前上下文求值。

[`Dimensions.cs`](../../runtimes/csharp/Coflow.Loader/Dimensions.cs) 已规范化并共享选择组合、缓存选择转换。变体名称列表按加载上下文保存为共享只读结果，维度存在性查询独立执行。缓存命中路径避免字典克隆、字符串键重建及列表复制。选择顺序无关、同一上下文引用身份与不同视图隔离均保持；上下文锁串行保护视图构造，失败时移除该组合的整个对象缓存。

后续工作：

1. 建立按字段与上下文的依赖关系，评估只为受覆盖或依赖传播影响的内容执行新增求值。所有已声明单变体仍在 Load 返回成功前完成验证；组合在请求 `For` 时验证。
2. 将校验状态与对外业务视图的对象生命周期进一步分离，评估完整校验时减少可丢弃业务对象的构造。该重构必须用基础上下文、单变体、组合和循环引用证明等价。
3. 测量长期组合访问、不同未知变体选择、结果释放后的缓存回收及单个业务对象的上下文保留链，再评估选择表示压缩。业务已取得视图的身份契约保持。
4. 在实际存在并发需求且锁等待已被剖析证明为瓶颈后，再细化视图锁粒度；失败时清除不完整视图，不能暴露半构造对象。

验收必须同时覆盖稀疏与密集覆盖、少量与多个变体、单条首次视图、全表首次视图、缓存命中、两维组合顺序、同一维度替换选择、未知变体回退、未知维度错误，以及显式 `None`。模板默认表达式应在当前上下文求值，不能复用基础上下文已渲染字符串。

未知变体回退的首次选择和缓存选择分别测量；重复相同选择的分配目标与不断输入不同选择造成的缓存增长分别报告。业务已取得的视图身份不可因内存优化被任意逐出。不得通过缓存所有校验视图换取首次 `For` 加速而忽略常驻内存；加载、首次视图、缓存视图和长期持有内存应一起达标。

## 正确性与双宿主验收

### Rust 与 CLI

- 与独立全量重载对照有效值、显式值、记录集合、维度结果、来源位置和完整诊断；覆盖复杂值、默认值、继承和引用。
- 在单文件和跨文件变化后保留旧代次，验证旧代次没有被新修改污染。
- 校验模板依赖顺序、循环处理、规则工作量与结构限制；达到限制时仍按原语义拒绝。
- 验证每文件语法节点边界、预算拒绝后的完整诊断及 UTF-16 来源位置；隔离大文件错误映射与模板级联，并分别核对扫描和构建工作量。
- 对创建、删除、重命名、迁移和维度变体变化验证索引增删；同值及仅来源变化分别验证。
- 候选失败和写入冲突不得发布候选或覆盖外部修改；按失败来源核对输入字节。staging 失败分别验收 `NotAttempted`、`Restored`、`Partial` 和 `Unknown` 恢复状态：只有明确未发布或完整恢复且逐文件字节原样时才允许重放；部分或未知恢复保留准确回执，不能报告为所有文件未变。
- 成功发布后独立重载验证；随后读取 revision 失败仍保留 `written=true`、`written_files` 和验证结果，未知 revision 设为 `null`，准确报告已经发生的写入。

当前 Rust R4 的具体通过用例与源码证据见[最终语义复核](../archive/benchmarks/non-editor-optimization-2026-10-29/verification/final-semantic-review.md)。修改态、失败态及旧快照由独立完整参照验证；性能基准中恢复夹具后的重载不代替这些断言。功能保持结论限于已验证路径，完整性能达标和全部宿主覆盖分别验收。

### C# 与 Unity

双宿主指 .NET 应用与 Unity Player。Unity Mono 和 IL2CPP 是不同后端，分别验收，不能把其中一项当作另一项完成。生成类型、CFD 文本、夹具参数和正确性断言在宿主间保持一致；工具链与可执行产物摘要分别记录。

| 维度 | .NET 8 | Unity Mono | Unity IL2CPP |
| --- | --- | --- | --- |
| 运行入口 | Release 独立进程 | 实际独立 Player | 实际 AOT Player |
| 启动与加载 | 首次调用与预热加载分开 | 记录 Player 启动及首次加载边界 | 同左；包含真实生成与链接产物说明 |
| 正确性 | 全基础字段、复杂值、继承表、引用身份、维度预检 | 使用同样语义断言 | 同样断言，额外确认裁剪和 AOT 所需类型可用 |
| 内存 | 分配字节、GC 次数、保留托管内存、工作集 | 使用宿主实际支持的分配与 GC 指标 | 支持情况单列；不以缺失指标推断零分配 |
| 结果地位 | 只说明 .NET 8 | 实际采样后才能说明 Mono | 实际构建及采样后才能说明 IL2CPP |

C# 正确性对照包含父子表内对象身份、同一视图内循环引用身份、不同维度上下文隔离、组合顺序等价、集合及内联对象覆盖、显式 `None`、基础回退、未知变体回退和未知维度异常。构造深度上限 256 的拒绝独立验证，不能以健康引用环替代。

本轮 [R6 功能验证](../archive/benchmarks/non-editor-optimization-2026-10-29/verification/csharp-r6-build-smoke.json)包含 C# Release 86/86、netstandard2.1 烟测及生成代码／共享语料集成。Unity 2022.3.62f3 Windows x64 Mono Player 的六类夹具各使用 100 条记录、2 文件，并在主线程及默认新线程各完成 15 项深链、模板、循环、集合恢复、混合引用路径及错误顺序契约检查，共 30 项通过。Player 为非 Development、关闭增量 GC、关闭托管裁剪配置；这些烟测没有正式性能样本。Mono 逐操作分配计数不可用时保持 null，IL2CPP 官方模块下载 HTTP 404 的证据保留，二者均不据此登记对应性能目标通过。

首次调用在预检污染缓存前执行；后续预检使用独立加载实例，释放后再正式采样。每个测量样本结束计时和分配计数后再执行结果验证。首次视图样本使用新加载实例准备，准备成本另列，不混入 `For` 计时。查询批次均值不能解释为单调用 P95。

采样前记录 Unity 版本、脚本后端、API 兼容级别、目标平台、架构、开发构建选项、裁剪配置及 GC 配置。构建模块缺失、下载失败或 Player 无法运行时，保留失败证据并将对应结果标为未实测；.NET 8 结果不能补齐 Unity 栏位。

## 复验、报告与完成标准

1. 固定提交与工作区摘要、工具和可执行程序摘要、生成夹具摘要、Release 模式和宿主配置。基线与优化后使用同主机、同夹具、同操作计时边界。
2. 编译、夹具准备和正式采样分离；基准进程串行运行，不同时编译或执行另一组压力测试。前后交替执行至少三轮，记录全部样本。
3. 操作级报告包含实际规模、字节数、变化量、样本数、P50、可支持的尾延迟、分配、保留内存、进程峰值和阶段工作量。少于 20 个样本不报告 P95，少于 100 个不报告 P99。
4. Rust/C#/Unity 基准宿主峰值包含夹具、预热、验证及分配器保留，不能等同于单个模型常驻内存。独立 CLI 内存探针直接跟踪 `coflow.exe`，只含该命令的加载、操作与输出，外部夹具和复核不在进程内；Node 父进程内存不能代替 CLI 内存。外部约每 100ms 采样 OS 累计峰值，可能漏末段峰值，缺测为 null。
5. 原始文件及运行规格进入归档，报告链接到[性能测量索引](../archive/README.md)。图表与目标表从原始样本复算，超时和失败单列。
6. 每项目标给出通过、未达标或证据不足；证据不足不是通过。跨宿主、容量上限、未测错误路径及磁盘冷缓存边界完整列出。

阶段完成需要同时满足：行为等价、工作量目标达到、对应端到端预算达到、内存回归边界达到，以及受影响宿主验收完成。若工作量改善而端到端收益不足，应按阶段计时继续处理占比最大的剩余成本，不以局部微基准倍率替代总体结果。

持久后台服务、改变 CFD 格式、二进制运行时数据、改变加载时校验时机、缓存逐出语义和超出内存的数据处理属于产品或架构范围变化。它们需要独立需求和决策，当前优化优先在既有加载、事务和运行时语义内完成。
