# 引擎性能优化安全性与结构复核

日期：2026-10-26。

后续实施状态：本报告第 2 节的发布指纹与 writer 依赖方向问题已在后续优化中修复，参见[当前实施范围](engine-performance-plan.zh-CN.md#10-局部更新检查与加载的进一步收敛)。本报告保留审查时的触发条件与验收依据。

## 1. 范围与结论

复核范围为 `e458a8f3` 的共享模型、增量构建、检查依赖、批量写入、源码缓存和宿主接入，`daccc61a` 的中间结构预算修复，以及当前工作区的读图差分、入边批量更新、延迟实体化、字段索引和复制收敛修改。编辑器当前并行进行的设置和界面修改不属于本报告的优化评价范围。

总体方案合理，建议保留不可变代次、记录值树共享、整规则失效、完整构建参照和事务候选发布。当前审阅没有确认新的业务结果回退；这不构成所有输入和并发交错均无回退的证明。存在一个已复现的既有宿主一致性问题，以及最新修改引入的模块依赖方向问题。继续优化前应先处理这两项。

## 2. 已确认的问题

### 2.1 内部写入指纹可能吞掉外部变更

位置：`editors/cfd-editor/core/src/editor/session/revision.rs::commit_internal_write`。

该方法在 runtime 发布完成后重新读取文件，并把读到的内容记为内部写入的期望指纹。合法交错为：内部发布 A、外部写入 B、宿主登记指纹 B、watcher 读取 B。此时模型为 A，磁盘为 B，`has_external_change` 返回 false，外部变化没有进入模型。

本次用真实 `RevisionCoordinator`、临时文件和确定性调用次序再次复现，输出 `external_change_detected=false`。该文件在引擎优化提交 `e458a8f3` 中没有变更；问题属于既有缺陷，不归因于最新复制优化。

建议由 runtime 发布结果提供实际发布字节的摘要及删除状态，宿主按发布结果登记期望，不再从发布后的磁盘内容反推期望。watcher 仍需读取实际内容进行比较，发布冲突核对和 revision 票据继续保留。此调整同时消除一次重复读盘。验收必须覆盖内部发布与外部写入交错、删除后重建、同长度外部写入和陈旧候选拒绝。

### 2.2 writer 反向依赖 mutation 准备层

位置：`crates/coflow-runtime/src/cfd_loader/writer/patch.rs::field_patch`，调用 `crate::mutation::set_nested_value`；函数实际定义在 `mutation/prepare.rs`。

当前依赖形成 `mutation → writes → cfd_loader/writer → mutation`。通用值路径操作和 mutation 诊断策略绑定，writer 必须了解上层准备模块；借用路径验证与可变路径修改也维护了两份相近的导航逻辑。现有对照测试覆盖了主要行为，尚未观察到这里导致的业务错误，但后续路径语义扩展容易产生实现分叉。

建议把类型化值路径导航、定位和替换放到模型值操作或 runtime 中立的路径模块。底层返回结构化路径错误，由 mutation 与 writer 各自映射现有诊断。保留延迟实体化，但让底层仅依赖路径操作契约。路径结构不变时可复用准备阶段的定位描述，不能在数组或父对象替换后复用过期位置。

## 3. 功能边界复核

| 机制 | 当前评价与边界 |
| --- | --- |
| 不可变共享 | Arc 和写时复制保留旧代次；模型、来源头部与维度值分离是合理方向。不能把共享指针相同以外的值比较改为普通浮点或枚举相等。 |
| 增量模型 | schema 编译身份、结构限制、记录身份顺序、变体集合和健康状态参与准入。成员变化、错误恢复和不能证明安全的状态完整构建。公开句柄仍限于所属模型代次。 |
| 模板闭包 | 当前按记录保存读取关系并计算传递影响，行为保守。每个根重新清理求值 memo，避免跨根缓存造成依赖漏记；可继续优化，但必须同时设计依赖传播和预算。 |
| 增量 check | 实际读集包含引用链与维度投影；任一根失效仍执行整条规则。成员变化使用静态扩大失效，预算未完成状态不能直接复用。拥有子树替换另行枚举新实例，清除旧路径诊断。 |
| 批量 writer | 不重叠补丁合并，重叠路径与非独立语法形成屏障，跨文件失败仍映射原请求下标。中间节点预算曾存在回退，已由 daccc61a 修复；该校验不能为性能再次删除。 |
| 延迟实体化 | 准备阶段验证路径并共享原对象，显式路径不复制完整顶层值，缺省父路径才实体化。现有直接/延迟写入文本对照和非法路径对照通过。 |
| 读图和入边差分 | 未变读集、未变引用块复用合理；读集投影变化仍更新，入边更新后恢复确定顺序。该优化不等于可任意去掉排序或换成无序集合。 |
| LSP 和宿主 | CFD 语法缓存以路径、实际文本及 URI 校验；候选提交核对 revision。外部修改识别仍受 2.1 的宿主指纹缺陷影响。 |

模型完整相等对照不比较内部模板依赖缓存；因此一次结果相同不足以证明缓存正确，必须继续保留多轮编辑、改向、错误恢复的序列对照测试。

## 4. 底层优化空间

### 4.1 分页存储优先于继续堆叠 Arc

`CfdDataModel.records` 为 `Arc<Vec<Arc<CfdRecord>>>`。首次局部写入仍复制整个指针数组，增量构建还会扫描身份、来源、惰性槽及维度条目；模板依赖外层树也会整体克隆。引用宿主和入边表同样是平坦 Vec。

建议先为记录表、来源表和引用表评估共享页，让局部更新复制受影响页。成员结构变化暂时继续完整构建，不需要同时引入跨代次稳定句柄。分页必须与变化来源驱动的遍历一起实施，否则只是减少复制而仍遍历全表。页大小应比较 256、512、1024 等候选的复制量、随机访问和峰值内存，不预先认定某个大小最优。

读图固定 256 桶降低了复制常数，但桶内写时复制的成本仍随总索引增长。后续可与分页有序索引或持久化树比较，不把固定分桶当作严格的局部复杂度保证。

### 4.2 schema 代次计划复用

`ReferenceFieldPlan` 已避免扫描无引用的值树，但增量替换仍重新分析 schema。`checks/planning.rs::insert_data_tasks` 则仍遍历数组、字典和对象，包括不可能包含 data check 的分支。

建议在 schema 代次绑定的模型/检查计划中分别缓存引用可达字段与 data-rule 可达字段。可达性需包含子类型、递归类型、Option、数组、字典和维度，不可只检查声明类型本身。缓存只保存 schema 身份和紧凑描述，不反向持有模型代次。

### 4.3 记录集合使用借用视图

`records(Type)` 通过 `assignable_records` 每次生成 Vec，再由 len 或量词消费。建议编译类型成员视图，支持稳定顺序的 len、迭代和按位置访问，成员未变时共享。调用计费仍遵守原工作预算，不能因省去实际分配而悄悄放宽资源限制。标量字段、字典和记录成员索引需要分别处理，不能机械地全换 HashMap。

### 4.4 模板依赖与紧凑身份

当前模板依赖是记录级关系，修改无关字段也可能重新计算整批读者；闭包内记录还会重新求值已有维度上下文。建议先差分维护未变化的依赖集合，再评估字段/投影级依赖与可复用求值结果。缓存键必须绑定源值版本、维度上下文、schema 和依赖完整性，循环诊断、来源及预算仍须与原执行契约对应。

TypeId、FieldId、RuleId 和按 schema 布局的字段槽可减少字符串比较与树节点分配，但属于较大布局调整。应晚于重复规划和全表扫描收敛，并验证继承字段、实际子类型、显式缺失/默认值、字段顺序和外部名称协议。

### 4.5 单文件十万条需要源码层面的增量设计

本轮十万条单文件环形引用更新约 217 ms，而检查只执行一个根，说明仅继续压缩 check 集合无法达到 50 ms 目标。整文件读取、解析、候选文本生成、来源更新与提交都需单独计量。

先复用源码版本的记录定位和来源索引，再评估语法子树重用或分段文本。增量解析必须处理字符串/注释跨界、错误恢复、全文件结构预算、行列移动和原子发布；业务记录独立不代表语法片段可以直接独立解析。完整磁盘文件发布本身也有按文件大小增长的成本。

## 5. 推荐顺序和验收

1. 修复发布摘要契约与宿主指纹竞态，消除 writer 对 mutation 的反向依赖。
2. 复用 schema 可达性计划和记录集合视图，差分维护模板依赖。
3. 分页记录/来源/引用索引，同时移除不必要的全量扫描。
4. 分别评估字段槽与源码增量解析，不与句柄体系迁移混成一次大改。

每项均比较完整结果、诊断顺序与位置、旧快照独立性、预算失败下标以及事务原子性。性能矩阵区分十万条单文件与跨百文件、低扇出与集中引用、显式数组与默认父路径、健康数据与错误恢复。除耗时外记录扫描数量、复制字节、分配量和峰值内存；三次样本不作为稳定 P95 证明。

本轮是审查与方案评价，没有实施新的生产代码修改，也没有操作 CFD 编辑器进程。

验证结果：本次 cargo check --workspace 与 cargo test --workspace 均通过，共 722 项测试。指纹竞态使用真实协调器独立复现，生产实现保持未改动。
