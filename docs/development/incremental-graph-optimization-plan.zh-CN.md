# 核心增量更新与超大图节点优化计划

日期：2026-10-26。状态：待实施的设计与验收计划。依据为[当前性能审查](full-performance-audit.zh-CN.md)及当前工作区源码。

## 1. 目标与范围

本轮目标是降低健康工程局部编辑的全局扫描成本，并使超大单个图节点的字段渲染成本主要随画布可见内容增长。优化必须保留模型、诊断、预算、来源定位、写入事务、图连接和编辑行为。

实施顺序为：建立基线与对照 → 稀疏模型更新及图查询优化 → 维度和依赖优化 → 图几何模型 → 节点内部窗口化 → 集成验收。各阶段独立验收，不把未完成的后续阶段计入性能收益。

本计划覆盖 `coflow-runtime` 的变更描述、`coflow-model` 的增量构建、编辑器核心图查询、前端关系投影、几何测量、图布局调度与节点内部挂载。检查器、诊断和写入链路作为正确性与端到端验收范围。首次加载重构、结构变化完全增量化、C# 加载器优化及完整快照增量传输属于后续独立项目。

## 2. 不回退的验收契约

功能正确性是每阶段完成的必要条件，性能收益不能抵消功能差异。发现差异时修正或撤回该阶段改动，不带已知回归进入下一阶段。

### 2.1 核心契约

- 同一输入下，增量结果与完整构建在记录成员、顺序、字段值、实际类型、维度有效值与覆盖来源上相同。
- 存储等价保留符号零、枚举展示信息、Option 包装等已有可观察差异；业务表达式相等性保持原规则。
- 引用目标、入边/出边及顺序、模板依赖、缺失目标、循环诊断和多态解析保持一致。
- 来源位置随文件文本变化正确移动；来源变化与业务值变化分别处理，旧快照保持不可变。
- 诊断代码、级别、消息、标签、来源和确定性顺序一致；错误引入、修复及被拒绝记录恢复均完整。
- 结构预算、检查根预算、请求预算、求值顺序和未完成状态保持既有契约。缓存只减少实际重复工作，不能无意改变预算边界。
- 写入冲突检测、原子发布、失败不产生部分结果、revision 核对、watcher 去重及撤销重做语义保持一致。

### 2.2 图视图契约

- 所有逻辑字段、引用元素、节点和连线继续存在；性能优化不增加静默截断、不丢弃重复目标连线。
- 节点位置、完整尺寸、展开状态、端口 ID、结构化写入路径、连接锚点与缩放坐标一致。
- 保留字段编辑、IME、光标、选区、未提交草稿、集合增删、引用选择、只读状态和错误提示。
- 保留新建连接、重连、线体拖动、拖到空白处创建目标、取消操作和失败后的状态恢复。
- 保留框选、连线命中、平移缩放、节点吸附、MiniMap、定位与适配视图、布局保存及 Ctrl/Command 点击打开记录。
- 窗口卸载不作为编辑提交或取消；活动编辑器、拖线源、弹出层锚点和操作中的行必须维持有效生命周期。
- 只裁剪绘制和挂载，搜索、关系筛选、选择及布局依据完整逻辑数据。两个端点均在屏外而线段穿过视口时，连线仍可见、可命中。

这些契约通过明确夹具、完整构建对照和真实浏览器操作验证。测试通过证明已覆盖场景符合契约，不把有限测试表述为任意输入下的绝对证明。

## 3. 性能目标与测量口径

以下数值是实施验收目标，不是当前已达到的性能。S0 固定机器、构建、数据、操作和采样协议；达不到目标时报告剩余成本，不通过降低功能要求达标。

### 3.1 核心目标

记 N 为全部记录数，R 为变化文件中的记录数，A 为受影响字段依赖闭包，D 为变化的维度覆盖数，B 为分页目录或批次目录规模。

| 场景 | 工作量目标 | 时间与容量目标 |
| --- | --- | --- |
| 相同内容刷新 | 维持零解析、零模型求值、零检查执行；不建立全量临时记录表 | 相对 S0 无稳定回退 |
| 健康单字段修改，身份稳定 | 不逐记录扫描未变化文件；业务求值由 A 决定，来源处理限定在 R | 100,000 条、100 文件、20 字段既有夹具：端到端 P50 ≤50ms、P95 ≤100ms，且 P50 较 S0 降低至少 25% |
| 固定变化文件，扩大无关工程 | 身份和来源访问计数不随无关 N 增长；分页/目录复制单独计数，允许 O(B) 成本 | 10,000→100,000 条时，模型增量阶段 P50 增长不超过 25%；源解析和发布分开报告 |
| 同文件 1,000 项批次 | 每个独立非重叠文件批次一次解析、一次候选构建；不随操作数重复全表扫描 | 既有夹具 P50 ≤150ms；跨文件另测，不推广此数值 |
| 无关维度扩大 | 不重建未变化覆盖索引、不求值无依赖维度字段 | 绑定与依赖无关的维度从 1 增至 20 时，记录实际字段求值计数不增长 |
| 无关模板字段修改 | 无依赖的读者不重新求值；真正的链式与高扇出依赖完整传播 | 记录/字段求值数与真实依赖闭包对应，报告最坏扇出 |
| 冷加载、失败恢复 | 保持完整构建与诊断能力 | 冷加载时间及峰值内存相对 S0 稳定增幅 ≤5%；超出需优化后重新验收 |

单个巨大文件的来源更新与整文件解析仍与文件大小相关，本轮不承诺该场景 O(1)。全局聚合规则、真实高扇出模板和全部变体确实受影响时，其工作量不能伪装成局部常量。既有跨文件批次和首次加载的长期目标继续由引擎总计划管理。

### 3.2 图目标

标准大节点夹具：单个节点 10,000 个简单引用元素，重复指向少量目标；另测 10,000 个标量、复杂对象集合、长字符串及多态/Option/字典。常规交互测量固定 1440×900 视口，当前视口内实际可见连线数不超过 300；密集连线另列压力报告。

| 场景 | 工作量目标 | 时间与容量目标 |
| --- | --- | --- |
| 端口构建和测量 | 消除 P 次循环中的 P 长度 find；关系投影每个数据/字段选择代际只构建一次 | 1,000→10,000 端口呈接近线性增长，计数中不存在 P² 查找 |
| 折叠深度节点 | 不转换字段值树；仅构造身份和诊断摘要 | 字段值转换计数为 0 |
| 画布平移经过超高节点 | 字段挂载量由可见行、overscan 和活动行决定；端口坐标不依赖完整字段 DOM | 相同视口和行类型下，1,000→10,000 项的挂载字段行数增幅 ≤10%；标准夹具每节点挂载行 ≤200 |
| 缩略模式 | 完整明细 DOM 卸载，几何与交互状态由模型保留 | 简单夹具卡片内容 DOM 相对 S0 减少 ≥90%，完整节点尺寸及锚点不跳变 |
| 稳态平移/缩放 | 视口改变不重新遍历整个字段值树，不触发布局重算 | 帧间隔 P95 ≤20ms、P99 ≤33ms，期间无超过 50ms 的主线程长任务 |
| 首次呈现 | 分开计时：查询、传输、投影、ELK、挂载及首次稳定几何 | 保存布局夹具的数据到首个可交互画面 P95 ≤200ms，较 S0 至少改善 50%；冷布局单独报告 |
| 单节点修改 | 未变化节点关系投影与几何复用 | 输入到局部稳定显示 P95 ≤100ms，独立报告真实后端提交延迟 |
| 连续布局请求 | 每个视图至多 1 个运行请求和 1 个最新待执行请求 | 最终数据代际必达，其他视图请求不被误取消 |

100,000 元素作为压力夹具，记录时间、DOM、内存、浏览器尺寸限制及失败边界，不与标准夹具混为一组。所有连线同时可见的密集图仍至少承担相应绘制和命中成本；本计划不以合并或隐藏连线取得上述指标，也不承诺任意边数下固定帧率。

### 3.3 采样

- Rust 使用 Release；前端使用生产构建和无头浏览器；两类测试串行运行，避免相互抢占 CPU。
- 保存优化前后可重现构建标识、工作区差异摘要、工具链、硬件、夹具种子、操作序列与原始 JSON。
- 冷启动至少 10 次，分别报告样本与中位数；热编辑预热 20 次后采样至少 200 次，重复 3 轮。浏览器稳定交互每轮至少 30 秒，首屏重复至少 30 次。单次短样本不报告稳定 P95。
- 热编辑使用真实交替值，单独标注 noop；性能测量结束后执行完整重载对照，不把对照成本混入编辑计时。
- 阶段计时包括失败尝试与完整重试；同时记录解析字节、身份访问、来源访问、字段求值、维度查询、依赖边维护、页复制、诊断复制、DOM、布局读取和长任务。
- 缓存测试包含连续 1,000 次更新和多轮视图切换；释放快照/历史后检查可回收对象。保留历史快照的内存单独统计，不能误报为泄漏。

## 4. 核心方案

### C1. 显式变更描述与身份稳定的更新入口

目前 runtime 已比较重新解析的批次，但 model 再核对所有记录身份并扫描全部来源。两层应共享明确的变更事实，而不是共享未经验证的“相信调用方”布尔标记。

runtime 构建一份绑定旧代际与新输入的变更描述，分别表达：来源批次变化、成员/顺序变化、业务字段变化、记录来源变化、维度覆盖增删改及覆盖来源变化。变化文件解析后核对身份和顺序；未变批次使用不可变代际身份复用。文本长度变化造成的后续来源移动全部纳入该文件的来源变更。

model 提供明确的增量输入与验证边界：旧模型代际、schema 编译身份、预算配置、批次成员身份及变体目录必须匹配；旧代际或不一致的更新不能应用。输入依赖编译器验证的不可变批次/成员描述，不能靠可伪造的摘要或裸句柄省略检查。未变化草稿按稳定句柄查询，仅被模板依赖实际读取时访问。

统一改造调用方，避免长期保留两套增量语义。model 不依赖 runtime 的文件系统类型；runtime 负责文件和变更发现，model 负责数据身份、更新验证及结果发布。结构变化和错误状态继续走有明确前置条件的完整构建，这是算法分工。

完成条件：固定一个变化文件时，增加其他文件记录不增加 model 身份/来源逐记录访问；同文件全部位置移动仍与完整构建相等；错误旧代际不能污染结果。

### C2. 分离值更新与来源更新

分别应用业务替换和来源补丁。只更新来源的记录共享 object、dimension_fields 和业务依赖；维度覆盖来源变化只更新相关来源头部。定位变化不触发业务 check 重跑，但诊断最终显示位置必须更新。

页目录和命中页复制纳入计数，避免把减少深复制误写成完全 O(变更数)。若目录复制成为新热点，再按同一测量评估分页目录层级；不在此阶段引入新的通用存储重构。

完成条件：前部字符串变长、换行、注释变化、跨文件批次、仅位置变化均通过；旧模型和旧诊断快照仍可独立读取。

### C3. 持久的维度覆盖索引

按模型稳定身份建立覆盖键 `(host, field, dimension, variant)` 与来源批次索引，增量应用旧覆盖删除和新覆盖加入；未变化覆盖与索引分片共享。禁止一次 `Arc::make_mut` 深复制全部覆盖表后宣称稀疏更新。

覆盖合法性、重复项、缺失宿主及字段绑定校验仍执行。旧覆盖删除、新覆盖宿主变化必须同时影响旧宿主与新宿主。变体目录增删先保留现有完整构建边界。

完成条件：新增、替换、删除、重定位覆盖，继承字段、多态宿主、默认值恢复及重复覆盖错误均与完整构建相等；无关覆盖不重新查找和构造。

### C4. 维度按字段求值

维度求值以该维度绑定字段为根，通过统一 resolver 按需求展开跨字段和跨记录依赖。未变化的基础字段及其他维度共享。缓存键包含 schema/模型输入代际、记录、结构化路径和维度上下文；生命周期限于可证明有效的代际或构建事务。

不能直接把当前每记录重置的 memo 跨记录或跨变体保留。缓存需要保留/重放依赖读取，并维持循环检测、诊断归属和逻辑结构预算。先建立预算临界值对照；如果按字段求值改变既有完整构建的预算判定，应先完成等价的预算计算设计，不能用扩大预算解决差异。

完成条件：非绑定字段不作为无意义根重复求值；被绑定字段实际引用的其他字段仍被求值；跨维度模板、循环与有限预算结果相同。

### C5. 字段粒度模板依赖

将依赖单位从整条记录细化到顶层字段及维度上下文，保留实际读取的结构化路径。对象/集合的结构变化与父子路径重叠必须失效相应字段；初期字段内部仍完整重算，避免同时引入路径级局部 resolver。

依赖记录涵盖成功读取、缺失读取、引用重定向、默认值和分支读取；旧依赖删除与新依赖加入在候选成功后一次发布。重算队列采用确定性去重顺序，循环诊断沿用统一 resolver。直接修改字段先产生存储语义差异，再传播至依赖它的字段；同值结果可停止业务传播，但仍更新读取依赖和来源信息。

完成条件：长链、菱形、环、条件切换、缺失目标恢复、高扇出、覆盖删除以及同值依赖重定向均通过完整对照。真实全局依赖允许全局工作量。

## 5. 图查询与渲染方案

### G1. 后端避免无效转换

将图节点头部、诊断摘要与字段转换分开。深度折叠节点直接生成头部和诊断；展开节点沿用完整字段转换。开始记录采用保序的有界枚举，引用存在性查询使用无分配判断；遍历与边输出使用现有稳定顺序。

节点上限只约束节点，不能顺便截断已接纳节点之间的边。可用关系字段、焦点文件、深度边界和诊断内容必须与原查询结果一致。测试包括大量引用指向同一目标以及节点上限正好命中的场景。

### G2. 共享关系投影和线性索引

按不可变节点字段及启用关系字段集合构建一次关系投影，同时包含端口数组、`id → port`、强制展开路径、追加路径和顶层字段索引。节点渲染、高度估算、连线和连接校验共享该结果。

端口匹配采用 Map；行 DOM 通过 ref 注册或一次遍历建立路径索引，禁止每个端口重新扫描整棵节点 DOM。显示路径与结构化写入路径继续分离，特殊字符和字典键不得通过显示文本反向解析。

测量通过共享调度器按帧合并，先读取所有需要的几何再发布状态；尺寸未变不通知 React Flow。字体适配按字体、可用尺寸与文本缓存，读写分批；字体加载、主题字号和缩放坐标变化有明确失效规则。

### G3. 独立的节点行与端口几何模型

为节点建立扁平可见逻辑行及结构化路径索引，保存展开状态、行高、前缀高度和端口锚点。节点高度、端口坐标、连线命中和布局均读取同一几何模型。结构不变的平移/缩放只做坐标转换和区间查询，不重新展开字段树。

初始投影允许与节点内容规模线性相关；局部行高更新应更新受影响区间的高度索引，不每次扫描完整节点。固定行高可以精确计算；动态字符串、复杂编辑器、插件和异步内容的行高必须通过实际测量修正，不能把估算误差作为正常锚点漂移。

先制作无头技术验证：不挂载某字段行时，其连线锚点、重连、线体拖动和命中仍正确。当前实现依赖 React Flow Handle 与内置重连元素，不能仅删除 DOM 后假定框架仍能工作。适配层优先使用公开 API；若公开接口不能表达所需几何和连接交互，暂停窗口化阶段，提交具体依赖/交互改造方案确认，不修改第三方私有 store。

### G4. 按画布视口窗口化节点内部

推荐方案是保留节点完整外部尺寸和现有画布滚动方式，按照画布视口映射到节点局部坐标后，只挂载命中行及 overscan。无需新增节点内部滚动条，也不把不可见端口移动到节点头部。

不可见行通过几何模型保留空间和逻辑锚点；可见交互端口保留 Handle，非可见端口的连线由适配层读取逻辑坐标。对屏外端口发起的重连和从线体发起的拖动必须保留现有能力。若完成这些能力仍要求挂载全部 Handle，则该实现只能算字段 DOM 优化，不能宣称端口挂载已受视口约束。

活动编辑器及其展开祖先、拖线源、弹出层锚点固定保留；焦点移动到未挂载行时先定位并挂载，再恢复光标。控件草稿、编辑身份与展开状态放在视图生命周期，跨窗口卸载和快照更新保持一致。集合插入/删除造成索引路径变化时，编辑目标和草稿必须显式重定位或按现有规则结束，不能复用到另一个元素。

缩略模式卸载明细 DOM，沿用完整几何。动态内容尚无精确高度时，需要完成可取消、分帧的测量并校正几何；对必须保持活动的编辑器和插件采用明确生命周期策略。不能为了首次缩略显示一次性同步挂载整个超大树。

该方案需先通过 G3 技术验证和下方设计确认。新增内部滚动、聚合端口、隐藏部分连线或改变节点高度不属于本计划默认行为。

### G5. 布局请求合并

布局请求以视图实例和输入代际区分；同一视图保留一个运行请求和一个最新等待请求，等待请求被新输入替换后明确结束其 Promise。运行结束时丢弃过期结果，立即执行最新请求；视图销毁释放等待状态。

共享 ELK 引擎不因单个视图过期而整体终止。超时和引擎错误继续处理所有真实受影响请求；排队时间与执行时间分开计时。拓扑、尺寸和布局参数未变时复用布局，平移、缩放和纯值变化不触发不必要的 ELK 工作。

## 7. 功能验证矩阵

### 7.1 核心

扩展 `crates/coflow-model/tests/incremental_model.rs`、维度与预算测试以及 runtime 真实文件更新测试。使用相同 schema、输入文本和限制分别执行增量与完整流程，不用被测增量辅助函数计算预期值。

| 类别 | 必测场景 |
| --- | --- |
| 值与来源 | 同值修改、符号零、枚举、空值、多态、嵌套集合；文件前部变长/换行、仅来源变化、多文件交错批次 |
| 身份 | 新增/删除/重命名/排序、重复 ID、类型变化、旧句柄/旧代际输入、schema/预算变化 |
| 模板 | 无关字段、链、菱形、环、条件切换、同值结果但读集变化、引用重定向、缺失目标恢复 |
| 维度 | 覆盖增删改、默认值恢复、来源变化、变体增删、继承、多态、跨字段与跨记录模板 |
| 诊断 | 合法→非法→修复，部分可编辑错误，旧错误保留、标签位置移动、诊断稳定顺序 |
| 资源 | 刚好达到预算、超过预算一次、深度限制、检查提前停止、请求总预算、缓存命中后的预算结果 |
| 发布 | 冲突、写入失败、批次原子性、外部修改与内部发布交错、撤销重做和 revision 竞争 |

至少 20 个固定种子，每个 200 次混合操作，逐步与完整构建及完整检查对照；覆盖页边界和文件边界。失败保存种子与最小操作序列。固定夹具单独验证关键边界，随机测试不替代明确测试。

### 7.2 前端与编辑器核心

新增独立图浏览器回归夹具，复用真实 GraphView、DataCard 和连接回调。现有 `home-graph.tsx` 主要为展示夹具，不能直接充当完整图交互验收。后端查询结果使用优化前语义的固定预期和完整记录诊断对照。

- 规模：1/100/1,000/10,000 端口，100,000 压力样本；单个超高节点、多节点、小节点与超大节点混合。
- 数据：标量、长文本、对象数组、嵌套字典、Option、多态、只读、缺失引用、重复目标引用、追加端口、异步缩略名与插件内容。
- 几何：最小/最大支持缩放、设备像素比例、窗口调整、字体加载、主题切换、展开折叠、字段过滤和动态行高。锚点在稳定后与真实行中心误差 ≤1 CSS px，并验证无逐帧漂移。
- 编辑：中文输入、输入中平移/缩放、窗口卸载再返回、提交失败、撤销重做、集合中间插入/删除、快照刷新、焦点和光标保持。
- 连接：新增、重连、线体拖动、只读拒绝、空白处创建、取消、屏外端点而连线过屏、自动展开引用集合的末项操作。
- 生命周期：快速切换文件/视图、连续布局请求、worker 失败、卸载时有等待请求；检查残留 observer、监听器、计时器和未结束 Promise。
- 已有普通表格及 Inspector 回归继续抽查共用 DataCard、尺寸测量和编辑上下文，防止图优化影响表格。

## 8. 检查、文档和交付

仓库标准必需检查保持为根目录的 `cargo check --workspace` 与 `cargo test --workspace`。本计划不增加格式化、Clippy、C#、扩展或绑定导出作为普通开发门禁。

图实现的交付证据另外包含相关前端单元测试、无头浏览器功能回归、生产构建和专项性能脚本；它们是本次改动的针对性验收，不修改仓库通用发布规则。没有修改 DTO 时不运行绑定生成；若后续设计涉及 DTO，才按实际改动验证生成产物。

不启动、停止或重启用户的 CFD 编辑器。若运行中的编辑器锁定可执行文件阻塞 Rust 检查，记录阻塞并保持会话，不能通过终止进程绕过。

结果进入 `docs/archive/benchmarks/`，设计契约同步到引擎计划、编辑器性能和图视图文档。报告逐项列出目标、实际结果、功能验证、未达项和适用规模，不仅报告平均耗时。产品行为未变化时无需修改公开教程。

## 9. 实施前的设计确认

S1 的等价算法优化可以作为独立实施范围。以下决策需要明确确认后进入对应阶段：

1. S2/S3 引入字段及维度上下文依赖的核心结构改造，保持现有预算与错误恢复契约，预计改动面大于局部扫描优化。
2. S5 采用“保持完整节点几何、按画布视口挂载内部行”的方案；不新增内部滚动条，不合并或隐藏业务连线。G3 原型需先证明 React Flow 连接能力能够完整保留。
3. 如果动态插件高度或框架端口约束使推荐窗口方案无法等价实现，应提交具体受限功能及替代设计重新确认，不自行降低交互要求。

通过标准是“功能对照通过且对应性能目标达到”。尚未通过 G3 原型和 S5 验收前，超大节点窗口化不计作已解决。
