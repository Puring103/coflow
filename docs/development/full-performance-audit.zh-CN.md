# 核心与前端性能审查

日期：2026-10-26。审查对象为当前工作区代码，包括此前完成的优化。范围覆盖语言编译、模型构建与增量更新、检查执行、运行时加载与写入、LSP、编辑器后端、表格与图前端。C# 加载器仅抽查，不作为完整审查结论。

本报告区分源码可确认的复杂度与实际测量。未测量的路径属于优化候选，不代表已经确认的端到端耗时占比。本轮没有修改产品实现。

| 中 | 检查器集合运算 | `intersects`、`disjoint`、`subset` 的配对比较为 O(L×R)，预算按比较消耗 | 对可精确索引的标量建立类型化集合；必须先确定相等语义和预算消耗契约，不可直接用 JSON 字符串作键 |
| 中 | 语言值依赖计划 | 各类型根节点在多个模式下遍历依赖图；长链中保存每个根的完整顺序存在二次规模风险 | 共享 DAG/SCC 计划；分别验证深链、菱形、环和默认值顺序，测编译时间及内存 |

| 中 | 编辑器转换和查询 | 注解缓存命中前仍构造完整形状；查询期间持有会话读锁并执行完整转换或搜索；引用候选缓存随任意修改整体失效 | 不可变形状复用、缩短锁内工作、引用语义代际；测查询与连续编辑并行时的延迟 |
| 中 | 复杂表格与维度表 | 普通预览已有高度预算，选中复杂树仍完整挂载；维度表仅行虚拟化，所有变体列挂载；复制多次构造选区笛卡尔积 | 单独评估选中树窗口、列窗口和复制单次遍历；保留焦点、草稿、键盘、插件和自动行高 |

## 验证要求

本轮为源码审查、既有证据复核和新增微基准，没有重跑产品测试，也没有操作桌面编辑器。后续实现按仓库要求运行 `cargo check --workspace` 与 `cargo test --workspace`；相关优化增加针对复杂度、增量等价或浏览器交互的验证。验收应同时记录冷启动、首次查询、稳定重复查询、单条修改、批量修改、错误恢复、峰值内存与长尾延迟。优化不得移除校验、冲突检测、原子性或执行预算。

## 增量更新与超大单节点专项补充

核心增量入口的当前工作量可拆为：全表身份检查、全部维度覆盖准备、受影响闭包求值、全表来源更新以及全部维度来源检查。受影响闭包变小不等于整条路径成为 O(变更数)。来源位置扫描具有实际职责：同一文件前部文本长度改变，会移动后续记录位置。因此优化应由运行时提供身份变化、值变化和来源位置变化的独立集合，按文件刷新来源；不能只遍历 changed 就删除来源检查。

`ValueResolver::resolve_record_fields` 每次清空 memo 和执行栈并重置结构预算；增量维度循环对每个受影响记录的每个变体调用它，随后只保留该维度绑定字段。候选方向是按维度字段作为根求值，按需求依赖，并在确定的求值上下文内复用结果。必须保持跨字段模板依赖、读集收集、循环定位、诊断及预算语义；不能直接把 memo 移出循环跨上下文共享。

图视图的节点级屏外裁剪已经开启，但不限制单个节点内部规模。`DataCardNode` 不传普通预览高度预算；启用的引用集合祖先自动展开，有关系端口的节点自动展开顶层字段。一个节点含大量引用元素时，会生成对应行与 Handle；缩略模式使用 visibility 隐藏完整卡片，DOM、React 状态和端口几何仍然保留。节点上限仅限制 BFS 的不同记录数量，不限制一个源记录中的字段、引用元素、端口和重复目标连线数量。

超大节点还有三项叠加成本：关系端口在关系投影、节点内容和高度估算中重复遍历；端口测量循环内逐项 find 和 querySelector，Handle 渲染又执行逐项 find；超高节点只要与视口相交，其完整字段树仍挂载。可先实现端口索引、共享关系投影和批量行位置索引，保留现有视觉与锚点语义。真正控制单节点 DOM 规模，需要明确内部滚动窗口或折叠分组及隐藏端口连线策略；这属于展示行为设计。

后端深度折叠路径仍调用完整 record_to_row 后丢弃 fields；可以拆出记录头部与诊断转换，折叠节点直接构造头部。start_records 在节点上限应用前扫描文件并构造引用列表，适合改为有界枚举及无分配的引用存在性判断。上述专项结论来自源码路径复核，尚未取得巨大节点的浏览器耗时、堆内存或 DOM 数量实测。
