# 日志与反馈实现契约

## 分层

`coflow-observability` 是宿主支持模块。桌面和显式启用日志的 CLI 初始化一个 subscriber；runtime、staging、LSP 发出事件，不自行创建日志文件。桌面命令通过统一执行边界记录开始、结束、耗时、错误码、操作编号和持久化状态，并把操作 span 传入后台线程。

`PublicationReport` 保留未尝试、已提交、已恢复、部分恢复失败或未知状态，以及已写入文件、恢复文件、恢复失败文件和保留备份。诊断文本与写入事实独立。编辑器在部分恢复失败后阻止继续写入，显式重新加载建立新的可信会话。

## 日志存储与隐私

日志位于系统本地应用数据目录的 `Coflow/logs/editor` 或 `Coflow/logs/cli`。每个应用用同一跨进程锁协调写入、轮转和快照；总共最多 5 个 10 MiB JSONL 文件。超过 7 天的文件在后续写入时清理。异步缓冲最多 512 条，队列满时丢弃并计数。写入失败独立计数，不向原日志通道递归报告。

另有单个 `last-panic.json` 紧急文件，仅保存最后一次 panic 的代码位置与运行编号，不保存 panic 文本。原生访问违规、强制杀进程和操作系统断电不属于 Rust panic hook 的覆盖范围。

默认事件只含受控标识、计数、耗时和状态，不记录源码、字段值、完整参数、异常文本或完整环境变量。第三方 tracing target 默认关闭。前端详细错误仅在当前窗口的 100 条有界问题历史中保存，传入持久日志的只是事件类别、命令名称与错误编号。

## 反馈界面

“日志与反馈”在项目未打开以及 React 错误边界触发时仍可使用。提供日志目录、最近问题、详情复制、反馈页面、诊断预览和文件下载。默认导出最多 1 MiB 日志尾部、运行环境、panic 元数据及问题编号。原始错误文本和堆栈由用户勾选后加入；预览允许修改与脱敏。提交问题由用户自行完成，不自动发送。

源码保存失败与已提交后刷新失败分别处理。后者推进已保存基线、保留后续输入，恢复按钮只重新加载会话。新建记录失败会拒绝上层 Promise，草稿弹窗保留输入。

图谱的新建目标与建立引用在一个引擎事务中发布。纯数据批量撤销和重做同样一次提交。布局设置等独立副作用保留逐项结果，失败后只保留尚未完成的历史子操作。引擎事务采用磁盘基线检查和失败恢复，不是针对非协作外部写入者的原子 CAS，也不是掉电安全事务。

## CLI 与 LSP

设置 `COFLOW_LOG=1` 后运行 CLI 开启文件日志。日志不进入 stdout，JSON、format 和 LSP 协议不受影响。VS Code 的 `Coflow Language Server` 输出通道显示 LSP stderr；内嵌 LSP 复用桌面宿主的 subscriber。

## 验证与发布

普通开发仍执行 `cargo check --workspace` 和 `cargo test --workspace`。日志轮转、写入失败、恢复备份、源码冲突与复合操作有专项回归；前端测试覆盖保存恢复、历史推进、原子历史请求和失败传播。浏览器测试覆盖默认脱敏、可选错误详情和诊断文件下载。

生产前端构建生成隐藏 sourcemap。正式发布还需按版本与 commit 归档对应 sourcemap 和原生符号，并在真实 Windows/macOS 安装环境执行崩溃、升级和存储压力验收。测试过程不启动或终止用户正在使用的桌面编辑器。
