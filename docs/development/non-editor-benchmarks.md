# 非编辑器性能基准协议

## 范围与入口

基准覆盖共享 Rust Runtime、独立 CLI 进程和 C# Loader。桌面编辑器、浏览器渲染及 LSP 不计入本组结果。Rust 热会话、CLI 冷事务、C# 应用加载分别计量；它们承担的工作不同，不直接据其耗时计算语言实现之间的提速倍数。

| 入口 | 工具 | 计时范围 |
| --- | --- | --- |
| 原有引擎连续编辑 | `crates/coflow-runtime/examples/engine_perf.rs` | 已加载写会话的真实修改与内部临时对象释放；包含该工具原有结果断言 |
| 底层模型与投影 | 同上，`ENGINE_MODE=model` | 模型构建、共享 clone/drop、首次/重复维度投影及独立 parser 探针；输入构造在计时外 |
| Runtime 操作矩阵 | `crates/coflow-runtime/examples/runtime_matrix.rs` | 公共会话 API 调用与内部释放；夹具、复原、正确性对照在计时外 |
| 独立 CLI | `scripts/performance/cli-matrix.mjs` | 进程创建、完整命令执行、退出及标准输出采集；结果解析与复核在计时外 |
| C# 应用运行时 | `runtimes/csharp/Coflow.Loader.Benchmarks/` | 真实生成类型及公共 Loader；文本加载、文件读取加加载、查询与维度视图单列 |
| Unity Player | `scripts/performance/unity/` | 同源生成类型、夹具和断言；Mono/IL2CPP 各自构建并运行实际 Player |

各工具的参数、夹具与操作清单见所在目录说明。`scripts/performance/run-case.ps1` 接受 JSON 运行规格，保存标准输出、错误输出、执行状态及进程峰值采样；所有实际规格随结果保存在 `.meta.json`。`scripts/performance/summarize.mjs` 从原始样本重算汇总 JSON、CSV 和明细表。

`non-editor-suite.mjs` 支持 `--group`、`--only`、`--output` 和可选 `--cli <固定可执行文件>`。正式矩阵可在独立目录中冻结 CLI 产物并记录摘要，避免构建目录后续变动影响采样。续跑仅跳过规格一致的成功结果或显式允许的有界超时；已有不匹配、失败或部分证据需要使用新输出目录。

汇总默认只扫描归档顶层，额外子目录须明确指定，例如 `node scripts/performance/summarize.mjs <归档目录> retry-cli cli-memory`。来源名称保留子目录，原失败与补测分别记录，烟测不递归纳入。独立 CLI 内存探针使用 `node scripts/performance/measure-cli-memory.mjs <新输出目录> <记录数> <文件数> <get,check,set,batch 的选择> <CLI 路径>`；每项仅执行一次以诊断进程峰值，不作为延迟分布。

## 测试维度

采用工具所列常见操作矩阵与容量专项，避免把未执行的笛卡尔积标作已验证。规模变化有时同时改变文件数或实际批量大小，只有其余参数一致的对照才用于单因素归因。

- 规模：千条、万条、十万条；字段宽度、文件数量及内容字节数同时记录。
- 数据形态：标量、字符串、数组、字典、内联对象、Option、引用和模板。
- 引用：Rust 的全记录环与高扇入星形，CLI 的稀疏二叉树与高扇入，C# 的无引用、成对引用、最多 64 条的独立环及高扇入。长依赖链的深度拒绝使用独立夹具，实际是否测量以报告为准。
- 语言维度：基础值、已有覆盖、新增变体、删除覆盖、稀疏与密集覆盖、多个变体、组合视图、缺失变体回退。
- 操作：首次加载、重复新会话加载、只读查询、局部修改、批次修改、成员与来源变化、校验、失败拒绝、恢复和冲突。

主矩阵覆盖工具明确列出的常见操作；容量专项记录每个变化参数。各次实际参数与未覆盖边界必须列入结果报告。

## 测量与正确性

1. Release 构建使用锁定依赖；记录提交、工具源码摘要、二进制摘要、工具链、主机和原始参数。
2. 编译与采样分离；正式性能子进程串行运行。工具开发期的并发冒烟结果仅用于正确性验证。
3. 新会话加载不清空操作系统文件缓存，不称为机器冷启动。C# 预热样本与首次进程调用分别解释；.NET 8 结果不推广为 Unity Mono/IL2CPP 性能。
4. 修改采样使用实际不同的值；无变化操作独立成组。批次必须核对实际操作数量。失败场景验证诊断及原文件保持状态，成功场景核对有效值或独立重载结果。
5. 保存全部样本，不删除长尾。中位数采用算术中位数，P95/P99 采用最近秩法。少于 20 个样本不列 P95，少于 100 个样本不列 P99；这些阈值仅控制展示，不能证明尾延迟已经稳定。
6. 查询可以在一个计时区间批量执行，必须标记每样本操作数。批量平均调用时间不解释为单调用尾延迟。
7. Rust/C#/Unity 基准宿主的进程峰值包含夹具、预热、正确性对照与分配器保留空间，不等于单模型常驻内存。C# 分配量、GC 后保留内存、进程工作集分别报告。独立 CLI 内存探针直接采样 `coflow.exe`，只含该命令的加载、操作与输出，夹具和外部复核不在进程内；Node 驱动峰值不能充当 CLI 子进程内存。外部约每 100ms 采样 OS 累计峰值，可能漏掉退出前最后区间，缺测为 null。
8. 超时、语义拒绝、工具失败与已完成测量分别记录。未测量的场景保留为空缺，不用理论复杂度或其他场景结果填充。

## 目标与复验

性能目标应同时列出绝对交互预算、相对本次基线的收益和可验证工作量。现有已约定目标继续有效；新增目标在专项报告中列出实施阶段、适用夹具及测量口径。

优化前后使用同主机、同夹具和同工具，交替执行至少三轮。局部操作增加独立样本和持续操作验证；容量结果同时检查正确性、诊断、引用身份、维度语义、旧快照、执行预算及发布事务。性能工具不自动加入普通开发或补丁发布门禁。

## 成对优化套件与验收工具

`scripts/performance/optimization-suite.mjs` 通过 `--baseline`／`--optimized` 选择冻结的原生程序目录，通过 `--dotnet` 和 `--mono` 独立选择优化后托管 DLL 目录及 Mono Player。`--group` 和 `--only` 限定场景，`--rounds 3` 生成三个独立进程轮次，顺序为 AB／BA／AB。每次运行将完整规格和载荷摘要保存为 `plan-*.json`；输出目录内已有规格或载荷变化时必须使用新目录。

基础 CLI 在千条规模执行 39 项操作，在万条规模的 `cli-common-10k` 执行 8 项重点操作。启用 `--extended-cli true --only cli-expanded-10k --group cli` 可补测万条基础夹具的其余 31 项，参数与 `cli-common-10k` 保持一致。扩展场景默认不启用；完整万条覆盖需要两组证据，不能用千条或十变体专项替代。

测量完成后按顺序运行 `summarize.mjs`、`compare-optimization.mjs`、`audit-optimization.mjs` 和 `report-optimization-targets.mjs`，参数均为结果目录。比较表是描述性数据，含部分失败进程中已完成的单项；验收以审计结果及目标报告为准。相对目标至少需要三对同轮、同夹具且完整成功的进程；部分成功、超时和缺失数据不自动通过。

直接 CLI 内存采用 `cli-memory-r4/r<轮次>-<baseline|optimized>/<记录数>/` 的归档结构，每轮分别执行万条的 `set,batch` 和十万条的 `get,check`。三个轮次按 AB／BA／AB 串行安排；`report-cli-memory.mjs <内存归档目录>` 验证 24 个被测进程、12 份夹具复核及逐轮顺序，独立输出四项内存目标。可用 `--baseline-sha256`／`--optimized-sha256` 额外绑定冻结的 CLI 产物摘要。空计数、退出失败、来源不一致或缺少三对证据均不能判定通过。
