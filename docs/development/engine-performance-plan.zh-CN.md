# 引擎核心性能优化方案

状态：已批准并实施安全增量路径。本文保留十万条记录规模下的架构目标、设计边界与验收方式；当前实现范围见第 9 节，性能验收以独立测量报告为准。语言、数据模型、规则执行及事务契约保持一致。

主目标是十万条有效记录工程中的高频局部编辑和大批量更新，同时改善首次加载、源码校验与完整 check。延迟目标见[测量报告](../archive/benchmarks/engine-performance-2026-10-25.md)。

当前验收结果见[优化后测量](../archive/benchmarks/engine-performance-optimized-2026-10-25.md)：十万条单字段提交 P50 50.29 ms、P95 54.09 ms，局部校验 P95 48.29 ms；完整加载和跨文件批次仍保留原目标阈值。

## 1. 优化范围与原则

优化覆盖 `coflow-language`、`coflow-model`、`coflow-checker`、`coflow-runtime` 及编辑器和 LSP 对这些核心能力的接入。各模块继续遵循[语言核心实现契约](../language-design/05-language-evolution.zh-CN.md)和[项目代次定义](../architecture/project-generations.md)。

性能以用户请求的完整路径和实际工作量共同衡量：单字段更新包含计划、源码修改、模型更新、检查、事务发布及结果组织；草稿校验、源码保存、外部文件更新与 LSP 同步分别计量。缓存命中率与实际减少的解析、物化、索引及规则工作对应。

优化顺序为 P0 算法与重复工作、P1 身份与存储布局、P2 统一增量 generation、P3 精确规则依赖。每阶段以正确性对照、工作量变化和性能复测作为进入下一阶段的依据。并行化在主要重复工作消除后按测量结果评估。

## 2. P0：消除算法退化与重复工作

### 2.1 批量源码修改

同一文件中的批量字段修改采用一个事务源快照：定位记录和字段、生成语义化修改计划、合并可同时应用的补丁、构造一次候选文本，再进行最终语法校验与项目验证。记录位置索引在源版本内复用。

对于独立的 B 个修改和总长 S 的文件，目标工作量为与 B 无关的固定次数解析、一次源码生成及与 B 成比例的定位和渲染；补丁排序允许 O(B log B)，文本处理与 S 成比例。结果组织按操作下标一次遍历，避免逐条扫描整份结果列表。

同字段多次赋值、父子字段重叠、数组索引变化、缺省对象实体化、插入后修改及重命名等操作先按请求顺序归并。跨文件操作只有在依赖独立性已证明时才合并执行；成功、失败归属及返回顺序仍与原请求对应。

### 2.2 装载、索引与容器

缓存草稿通过借用、所有权转移或共享块进入模型构建，减少“缓存批次 → 临时全量草稿 → builder”的重复深复制。源文本、原始字节、候选文本与回滚快照具有明确所有权；仅在需要独立可变内容时创建新分配。

文件缓存使用规范路径索引，记录元数据使用直接索引，避免逐文件扫描全部文件、逐记录重复构建中间映射。树形有序容器用于确实需要有序遍历的边界；热点查找采用稠密数组、预编译索引或哈希容器，最终展示和诊断顺序单独保证。

字典重复键、集合唯一性和集合包含等操作按键的相等性语义选择索引。数值位宽、浮点相等、枚举、记录引用及复合值使用一致的比较规则；哈希只是查找手段，碰撞仍执行语义比较。

### 2.3 check 求值分配

规划先按规则实例去重，再展开一次根语句；保持当前整规则失效边界，避免含 R 个根的规则出现 R² 次重复插入尝试。跨记录依赖合并失效规则后只枚举一次拥有者，runtime 与 checker 的内部计划共用一次归一化。每个根任务独立的工作量与迭代预算保持不变，合并规划不合并这些预算。

只读集合与模型值尽量以借用视图或轻量句柄传递。作用域绑定、路径、来源位置和诊断上下文使用可复用结构；成功路径避免构造最终不会输出的诊断文本。索引化集合操作、聚合缓存及中间结果复用分别验证顺序、错误位置和预算计量。

本阶段保留规则的执行顺序、错误传播、完整性状态及量词语义。`any` 是否提前结束是语言语义选择，性能实现继续执行当前契约规定的求值过程。

## 3. P1：紧凑身份、字段布局与记录块共享

### 3.1 编译期身份与字段布局

为 schema 中反复使用的类型、字段、规则、维度等建立内部紧凑 ID，并在 schema 代次内统一解析。业务名称与源码拼写由符号表保存，对外仍使用当前协议规定的名称和坐标。

按已编译 schema 的字段布局访问值，使常规字段读写从字符串查找转为字段槽访问。字段声明顺序、实际类型、缺失状态、显式值与默认值来源分别表示。嵌套对象、可选值和容器保留各自语义。

值布局以真实字段分布、嵌套深度、字符串长度和分配测量确定。大变体装箱、共享字符串或共享子树按收益评估；选择同时计入句柄开销、间接访问、缓存局部性和回收成本。

### 3.2 稳定内部身份与不可变块

记录存储采用可共享的不可变块，候选代次只复制变化块及相应索引分片。按记录粒度共享与按页共享通过基准比较，块大小不预先固化。

内部记录槽需要能够稳定关联相邻代次中的同一记录，并在删除与复用时识别旧槽。可采用带代数的 slot 或显式迁移映射；具体表示在实现前确认。公开的 `CfdRecordHandle` 仍遵守当前“仅在所属模型代次有效”的契约，跨代次的宿主状态继续保存 `RecordCoordinate`。

源码版本与位置索引同语义值存储分离。同文件前部文本变长时，后续记录的行列与 span 随源版本更新，值未变化的记录块继续共享。记录显示顺序独立于存储槽，插入、删除、移动不迫使全部业务值搬迁。

模型建立、索引维护和增量更新共用一套值、身份与约束表示。完成迁移后移除被替代的中间表示和重复构建路径。

### 3.3 容器选择与验证重点

| 数据 | 候选结构 | 需要保留或验证的性质 |
| --- | --- | --- |
| 类型、字段、规则名称 | schema 代次符号表与紧凑 ID | 名称在输入/输出边界解析，诊断保留原拼写与来源 |
| 同类型对象字段 | 按 schema 布局的连续槽数组，独立来源/存在性元数据 | 继承字段、默认值、显式缺失及多态实际类型 |
| 记录存储 | 不可变记录块或记录级共享，稳定内部槽 | 测量块大小和复制放大；不为每个 bool/int 单独分配 Arc |
| 引用邻接表 | 按稳定槽寻址的分块邻接数组和共享边块 | 局部改边不复制整个索引；完整 CSR 只在静态视图收益明确时采用 |
| 字典 | 保留有序条目，小容器线性访问，大容器辅助索引 | 相等性、重复键、确定性遍历与 typed-key 路径 |
| check 局部变量 | 编译期变量槽号、紧凑作用域栈 | when 绑定、嵌套量词、短路条件的作用域和错误定位 |
| 值路径与证据 | 类型化路径段、父链或节点 ID，结构化值借用 | 失败时还原完整诊断，数组重排和引用改向后路径有效 |
| 文件来源 | SourceId、源版本和 span | 文本移动只更新来源索引，不重复持有每条记录的文件路径字符串 |

这些选择通过分配与访问基准确定，不进行全局容器机械替换。输出顺序由明确的顺序索引或排序规则决定，不依赖哈希表遍历顺序。

## 4. P2：统一增量 generation

### 4.1 统一变化入口

runtime 接收结构化 mutation、文本覆盖、文件新增/删除和配置/schema 变化，产生同一种候选 generation。编辑器表格、源码保存、草稿校验、文件 watcher 与 LSP 接入同一源版本和失效机制。

数据变化复用已编译 schema、未修改源批次和未变化模型块。配置与 schema 变化具有独立失效范围；初期可以明确执行全量重建，数据编辑路径保持局部更新。草稿 generation 与已发布 generation 隔离，草稿诊断不能覆盖较新版本。

### 4.2 模型变化闭包

模型更新从直接变化字段和记录成员变化开始，沿以下关系计算闭包：

- 拥有关系：内联对象、数组、字典及 Option；路径结构变化更新相应子树。
- 引用关系：目标存在性、实际类型及反向引用；创建、删除、重命名同步更新关联索引。
- 全局约束：继承域唯一 ID、singleton、类型成员集合、重复身份冲突组及被拒绝记录恢复。
- 模板关系：字段源表达式、默认表达式、引用路径及上下文传播；值变化继续传播到依赖模板。
- 维度关系：基础值、显式覆盖存在性、有效值、已发现变体集合及多维选择上下文。

显式覆盖与基础值相同仍保留存在性差异。空覆盖块、变体新增/删除、模板循环与循环修复进入闭包。跨维度缓存以完整选择上下文区分，组合视图按实际请求计算。

全局约束使用专用成员/冲突索引更新，确实依赖全体成员的工作按实际范围执行。局部更新的预期成本由变更闭包决定；高扇出引用和全表聚合单独报告。

### 4.3 诊断来源分区

诊断至少分为源文件解析/降级、模型构建/全局约束、check 执行三个分区。分区同时记录来源身份、源版本、规则目标及失效范围。

未变化文件复用其语法与降级诊断，变化文件替换自己的源诊断。模型诊断随受影响记录、引用和约束组更新；规则诊断随实际失效目标替换。删除、数组重排、类型替换及维度变化清除旧路径；仅位置变化时重新投影来源位置。

错误恢复覆盖从拒绝到有效、从有效到拒绝及部分可编辑错误状态。检查或规划未完成时保留明确的未完成状态，后续代次按当前恢复规则补齐检查。

### 4.4 事务与 revision

候选构建继续遵循“计划、暂存、验证、核对基线、原子发布、提交代次”的顺序。文件冲突检测、失败回滚和 generation 一致性覆盖全部写入文件。

只读查询持有不可变 generation。耗时候选计算在会话锁外执行，发布时验证所基于的 revision；仅有效候选提交到当前会话。连续输入可合并尚未开始的派生计算，已确认的写操作保持其顺序和完成语义。

## 5. P3：精确规则依赖与增量 check

在现有静态依赖和整规则重跑边界上，细化实际访问记录、字段、拥有路径、引用目标、维度上下文及集合成员关系。schema 依赖索引负责初始规划，执行时读集可用于缩小再次执行的目标范围。

依赖覆盖成功读取、失败查找和成员变化。条件分支与量词会改变后续访问路径，触发后重建本次完整读集。记录不存在、空集合、显式覆盖缺失、字典键不存在等结果同样登记依赖。

命中一个根语句依赖时仍按当前契约执行整个规则，维护规则内停止行为、继承顺序及根语句状态。内联 data 依赖同时包含宿主、拥有路径与维度选择。数组重排和对象替换更新目标身份与旧诊断范围。

集合成员依赖与元素字段依赖分开。成员未变的局部字段更新可以只触发实际依赖它的规则；全表唯一性、聚合、成员查询和高扇出引用按其完整依赖集合执行。聚合结果的增量维护需要各自的正确性证明与基准，不以通用字段缓存代替。

check 结果缓存绑定 schema、模型依赖、检查配置与执行完整性。无足够依赖信息的任务继续采用明确的扩大失效范围，以完整检查作为可验证参照。

## 6. 实现约束

| 项目 | 方案边界 |
| --- | --- |
| 操作重排序与合并 | 独立字段补丁按文件合并；重复路径、父子重叠、插入位置冲突和结构修改形成顺序屏障。请求顺序、最早失败下标和事务原子性保持一致。 |
| 有限预算 | 按实际请求执行的工作计量，保留原任务与请求预算。增量请求与全量请求执行集合不同，分别验证中断位置及完整性；预算耗尽的上一代不能作为完整检查缓存。 |
| 全量等价 | 在未耗尽预算的条件下比较业务结果、规则状态、诊断及来源；有限预算另行验证确定性、资源上界和未完成标记。 |
| 量词与错误 | `any` 等量词继续遵循现有求值、错误传播和诊断契约；短路属于独立语义变更，须确认后更新规格和测试。 |
| 内部身份 | 记录身份及顺序稳定时共享句柄索引；成员或顺序变化执行完整构建。公开 handle 保持当前代次约束，宿主跨代次保存 RecordCoordinate。 |
| 增量覆盖范围 | 每阶段明确可局部处理的变化类别及全量失效类别；完成相应阶段后统一接入路径和缓存归属。 |

以上约束用于实现和回归验收；第 3 节的进一步布局目标与当前已实施结构分别记录。

## 7. 基准矩阵

主验收规模为十万条有效记录；千条和万条作为规模曲线对照。数据采用唯一 ID，包含标量、字符串、嵌套对象、集合、跨文件引用、模板及维度，并在测量前断言有效记录数、引用数、预期诊断和 check 任务数。

| 基准 | 变量与操作 | 主要观测 |
| --- | --- | --- |
| 首次加载 | 总记录数、字段数、文件数、嵌套与引用密度 | 各阶段时间、分配、峰值内存、验证/物化记录数 |
| 文件粒度 | 固定总记录量，改变文件数量和单文件长度 | 文件查找、发现、解析字节数与元数据工作量 |
| 高频单字段 | 常驻会话连续修改真实交替值，覆盖不同记录和同一记录 | 单次 P50/P95、吞吐、队列等待、模型复用、内存趋势 |
| 批量字段 | 同文件与跨文件，按文件连续与交错，同字段与父子路径重叠 | 批次耗时、整文件解析次数、源码复制字节数、结果组织工作量 |
| 结构变化 | 插入、删除、重命名、移动、引用目标变化 | 身份/成员索引、反向影响集、拒绝记录恢复、事务正确性 |
| 草稿和外部修改 | 文本覆盖、保存、watcher 更新、LSP 同步分别测量 | 端到端延迟、读取/解析文件数、重复构建和过期候选 |
| 完整 check | 本地规则、嵌套 data、集合、引用、维度、诊断密集输入 | 规划与求值时间、任务数、访问值数、诊断成本 |
| 增量 check | 无关字段、局部依赖、跨记录依赖、高扇出、全表聚合 | 失效集、重跑规则/目标数、缓存复用与完整性 |
| 错误和预算 | 语法错误、重复 ID、缺失引用、模板循环、根任务/请求预算 | 恢复路径工作量、诊断保留、未执行任务和资源上界 |

Release 构建与运行串行分离，记录代码版本、硬件、工具链、夹具参数和测量范围。独立报告预热前与预热后结果；工程内 CPU 阶段、磁盘发布、编辑器适配和 IPC 各有明确边界。

高频场景以足够的重复样本报告中位数、尾延迟和离散程度，并记录长期内存变化。样本不足时逐项列出原始值，不将单次结果解释为稳定 P95。真实连续操作的输入生成、noop 和缓存复用行为在报告中说明。

## 8. 分阶段工作量验收

| 阶段 | 验收目标 |
| --- | --- |
| P0 | 独立同文件字段批次的整文件解析次数与操作数无关；结果组织与文件命中检查消除平方增长；集合优化与原比较语义一致；实际分配和复制量下降。 |
| P1 | 未变化记录/块共享，局部修改不深复制全模型；字段热路径使用布局索引；删除和插入不引起无关业务值搬迁；旧 handle 不会指向错误记录。 |
| P2 | 直接变化源及依赖闭包决定重建量；无关源不重新读取/解析，无关模型块不重新物化；各入口共享更新机制；诊断完整，事务与 revision 行为一致。 |
| P3 | 局部依赖只执行受影响目标的整条规则；成员、缺失项和条件依赖完整；高扇出和全局规则的实际工作量明确；完整性状态独立于业务通过状态。 |

计数器在实际工作发生处累计：解析次数和字节数、候选构建次数、草稿复制、记录验证/物化/复用、引用边更新、模板求值、索引更新、规则规划/执行和诊断更新。失败重试同样计入，最终模型大小不代替真实工作量。

增量正确性以确定性编辑序列和随机编辑序列双重验证。每次操作后，与相同输入的全量重建比较模型值、维度、引用、顺序、被拒绝记录、诊断及完整规则结果；有限预算使用独立对照验证资源与状态契约。每个阶段同时复测冷加载和高频路径，确认成本没有被转移到另一个常见请求中。

实现阶段的必需检查遵循仓库 `AGENTS.md`：`cargo check --workspace` 与 `cargo test --workspace`。性能验证使用无头程序，不启动、停止或重启用户的 CFD 编辑器。

## 9. 当前实现

### 9.1 数据与来源

schema 的已验证名称通过 `Arc<str>` 共享字节，编译身份使用不可复用的共享 token。引用可达性和内联 data check 可达性计划绑定 schema 代次共享。模型构建借用源批次草稿；需要拥有输入时才装箱，增量求值的惰性草稿表只在实际访问时分配记录。

Windows CLI 和桌面宿主使用 mimalloc 处理大量小对象分配与释放；核心库保持宿主可选择的分配器边界。选择依据及峰值内存范围记录在验收报告中。

记录按 `Arc<CfdRecord>` 共享，记录目录、来源目录和引用邻接表采用共享分页存储，业务对象与维度值树独立共享。源码位置变化只更新来源头部。引用边按宿主分块，反向索引保存宿主和块内索引；局部更新重建变化宿主的边，并恢复原有确定性顺序。会话的坐标与文件成员索引在身份稳定时共享，来源元数据按重新解析文件更新。

来源缓存同时保存文本、草稿、加载状态及诊断顺序。文件发现、语法解析和类型降低诊断保持完整。读失败的来源不视为可复用的已加载文本。诊断映射按实际涉及的记录查询来源，局部更新无需复制全项目文件路径。

### 9.2 重建与检查

增量模型要求 schema、结构限制、记录身份、顺序及变体集合保持一致。直接变化记录与模板实际读取关系决定重建闭包，已有维度上下文同时参与求值。字段比较保留浮点符号零和枚举显示信息等可观察差异；业务比较运算继续使用语言原有相等性。

新增、删除、重命名、排序变化、变体集合变化、被拒绝记录恢复、投影模型以及需要重新归并模型诊断的状态执行完整构建。完整构建继续支持容错会话。该边界使局部路径与完整路径使用同一验证、模板求值和引用语义。

检查规划按规则实例展开一次。执行读集记录字段、引用来源和目标、失败查找、条件分支及维度访问，按整条规则合并到反向索引。字段更新只选择实际读取者；成员变化和无法证明完整的读集扩大失效范围。规则内停止行为、量词求值顺序、各根独立预算和请求预算均保持一致。

### 9.3 写入与宿主

独立字段批次对同一源码快照生成不重叠补丁，一次拼接候选源码并执行完整语法及结构预算校验。已解析候选立即降低为草稿，拥有权移交重建阶段，AST 随文件处理释放。后续同文件修改清除先前候选结果；发布前继续检查磁盘基线并执行原子事务。

编辑器 watcher 和源码保存保留变化路径，复用已编译 schema 和数据缓存。候选在会话锁外计算，提交时核对 revision，旧代次在锁外释放。LSP 共享内容未变的文本、语法树、语法诊断及定义索引，并保留未保存草稿和快照版本规则。

### 9.4 验证与可观测范围

回归同时覆盖确定性编辑序列与固定种子的混合编辑序列，逐轮对照完整模型、维度值、引用顺序、记录来源及诊断。批量修改对照顺序写入，检查对照完整规则执行，预算耗尽使用独立资源边界测试。

工作量统计中的记录验证、物化、复用和引用边计数来自模型构建器，检查根计数来自执行器。模型计数描述成功返回的构建轮次；诊断导致的完整重试总成本包含在端到端耗时中。十万条健康夹具据此验证局部复用，错误场景通过结果对照验证。

进一步目标仍包括更低的首次加载成本、来源路径与字段槽的更紧凑布局、成员结构变化的局部维护，以及宿主导航统计的局部更新。各项收益按同一基准矩阵验收，当前实现不将这些目标计作已完成工作。


## 10. 局部更新、检查与加载的进一步收敛

下一阶段的稀疏更新、维度索引与字段依赖方案及验收目标见[核心增量与超大图节点优化计划](incremental-graph-optimization-plan.zh-CN.md)。该计划为待实施设计，以下内容描述已完成的优化。

本轮工作量与端到端结果见 [2026-10-26 测量报告](../archive/benchmarks/engine-performance-incremental-2026-10-26.md)，包含完整原始样本、对照基线及尚未达到的目标。

共享分页容器由 `coflow-storage` 提供，无语言或宿主依赖。记录目录、反向引用目录和运行时来源记录目录按 512 项分页；局部写入复制页目录和命中页，旧代次保持独立。只读来源扫描不触发页复制。512 项是本轮验证的布局，不代表所有工作负载的最优页大小。

`records(Type)` 的有序成员句柄数组按需构建，字段更新复用共享数组；完整成员重建重新建立缓存。缓存只用于匹配的 schema 编译身份，检查工作与节点预算继续按原契约计量。模板读集不变时直接复用依赖图，变化时维护差集；惰性草稿按访问到的页初始化。

引用与 data-check 可达性采用 schema 代次共享的不动点计划，涵盖继承、多态、递归对象与容器。无内联检查的标量数组不再枚举元素和构造路径。源缓存中的基础记录和维度覆盖草稿均借用进入 builder。

加载同一版本的文件时仍比较实际内容，不依赖 mtime 或文件长度；内容相同则复用源诊断、草稿和健康模型，重复 watcher 通知不重复解析。未完成检查的恢复规则仍保留。

发布成功后 runtime 返回实际发布字节摘要和删除状态，宿主据此登记内部版本；摘要不从发布后的磁盘反读。源码保存采用相同凭证，外部写入即使发生在发布和登记之间仍会被识别。底层源码 writer 使用中立值路径模块，不反向依赖 mutation 准备层。

当前边界：实际变化的 CFD 文件仍整份解析；记录成员、顺序、schema 和变体目录变化继续走完整构建；模板依赖仍为记录粒度，字段槽尚未替代名称映射。分页减少复制量，但记录身份/来源仍存在代次级扫描。以上边界不计作已完成的完全增量化。


## 11. 编辑输入与界面热路径

本轮数据见 [编辑热路径与界面帧间隔测量](../archive/benchmarks/engine-editing-2026-10-26.md)。

健康模型增量构建按源文件批次借用草稿，不建立全项目记录引用平面表。混合单条拥有输入、单条借用输入和批次借用输入保持相同顺序及句柄语义。完整容错重建仍保留候选表以支持剔除非法记录；诊断坐标只在标签涉及记录时构造。记录身份与来源核对仍执行，批次输入不等于完全稀疏构建。

普通表格与维度表的虚拟行键在展示项不变时保持函数身份，滚动和选区变化复用虚拟列表测量缓存。排序、过滤、分组及折叠改变展示项时失效；缩放继续触发测量。维度分组按来源文件建立一次成员索引，保持首次命中优先级、来源隔离及展示顺序。

普通表格使用专用顶层行模型。记录对象、标识和位置均未变时复用行对象；内容、位置或标识改变时重建。列定义变化时清除复用行的取值与唯一值缓存。手动分组由展示层负责，不将嵌套 subRows 输入此行模型。输入快照采用不可变更新，与现有前端投影契约一致。

导航、拖选和批量清空复用当前排序过滤后的坐标索引；导航数组与索引一次遍历生成。无分组时跳过分组计算。大分组追加使用迭代，不依赖函数参数展开的数量上限。

生产构建基准同时记录滚动帧间隔、选区响应与真实组件的编辑提交耗时。组件编辑夹具使用内存宿主，实际文件发布与检查耗时由引擎基准单独记录，二者不能直接视为桌面端到端延迟。性能结果与限制见本轮归档报告。
