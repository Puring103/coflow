# 运行时数据结构

> 新 VM 的设计与验收以 [新 VM 实施计划](../plans/new-vm-and-csharp-snapshot.zh-CN.md) 及其配套规格为准；本文冲突内容在同一次交付中同步。

> 状态：架构设计
>
> 范围：运行时的数据归属、对象布局、引用、函数值、内存回收和调用状态。

## 1. 整体结构

```text
Runtime
├── 只读契约
├── CFD 编译程序
├── 固定配置数据
│   ├── 记录目录与查询索引
│   ├── 对象与集合
│   └── 普通维度记录
├── 动态值存储
├── 宿主持有的句柄
└── 执行状态
    ├── 调用栈与寄存器
    └── 预算、临时保活记录和错误信息
```

契约、固定数据和 CFD 程序在构建后只读。动态区可以创建和回收值，但已创建的对象和集合内容仍只读。
各部分使用同一套类型规则，不建立第二套值语义。

## 2. 固定区与动态区

| 存储 | 内容 | 释放方式 |
| --- | --- | --- |
| 契约 | CFT 类型、常量、默认值描述和类型化 IR | 由契约持有者共享管理 |
| 固定区 | 加载完成的配置记录、对象、集合和维度数据 | Runtime 释放时整体释放 |
| 动态区 | 函数中新建的对象、集合、闭包和字符串 | 不再可达时回收 |

动态值可以引用固定区对象，不复制整条记录。
反复读取动态 fstring 产生的字符串归动态区，不能一直积累到 Runtime 释放。
函数返回不代表返回值立即释放；宿主或其他活跃值仍持有它时继续保留。

契约常量、固定区对象和动态值的身份需要能区分所属存储，不能只用一个没有来源的数字索引。
契约可被多个 Runtime 共享，运行时 self、记录引用和捕获环境不写回契约。

## 3. 记录与对象

```text
记录：key、对象引用
对象：实际类型、按布局保存的字段数据
```

table 和单例记录在记录目录中拥有身份；data 对象只保存对象内容，不提供 record key。
记录参数保留记录身份，可访问 id。data 参数传递普通对象内容，记录与 data 不进行隐式转换。
命名类型的声明类别决定值的表示：table/singleton 类型存储记录身份，data 类型存储对象内容的引用。
语言类型直接使用声明名，内部仍区分记录句柄和 data 对象句柄。

- 记录引用按所属 Runtime 和记录身份比较。
- data 对象按实际类型和字段内容比较。
- 对象的引用字段只比较引用身份，不递归展开被引用记录。
- 查询索引只定位记录，不另存一份对象内容。

记录 key 的唯一性索引覆盖整棵继承树，类型查询索引只包含指定类型及其子类型。
引用链接使用编译时确定的静态查询类型和 key；继承默认程序中的引用不根据实际 self 类型重新选择查询域。

字段名在编译时解析为字段槽。执行时按槽读取，不逐次按字符串查找。
父类型字段在子类型布局中具有稳定的访问位置，实际类型信息支持继承判断和子类型访问。
具体列布局、对齐和标量压缩由实现及性能测试决定。

## 4. 可选值与递归

可选值保存“是否有值”和存在时的内容。None 不能与 0、false、空字符串或默认对象混用。
对象和记录引用的可选值可以使用空句柄优化，但语言上仍是独立的可选状态。

data 内容递归必须经过可选类型，数组和字典本身不作为例外。
记录字段中的记录引用只连接记录身份，不展开内容；记录引用可以成环。

| data Node 中的字段 | 是否允许 |
| --- | --- |
| next: Node | 禁止 |
| children: [Node] | 禁止 |
| children: {string: Node} | 禁止 |
| next: Node? | 允许 |

同样的规则适用于间接递归。即使允许可选递归，默认值展开也必须有限。
递归的可选对象使用间接存储，不能无限内联到自身布局中。
@struct 决定目标语言的值类型表示，不要求 Rust 内部把递归字段展开；宿主包装也使用有限布局。

## 5. 数组与字典

数组保存有序元素。字典以有序键值项为主体，可以附加 key 到项位置的查询索引。
索引不保存第二份 value，不决定遍历顺序。

VM 读取连续 int、float、bool 及其可选数组时直接产生标量槽，完整保留浮点位模式与 None 状态。
公开数组读取仍返回 ValueId；引用数组经身份解析读取，不建立逐元素标量堆节点。

字典条目连续保存，键内容只有一个所有者。冻结时，bool 使用两项位置表；整数键跨度不超过条目数两倍且不超过一百万时，可使用包含空洞标记的稠密位置表。位置表构建受剩余内存预算限制，稀疏整数与字符串使用随机化哈希索引。单一枚举域的索引只散列枚举数值，并在入口验证枚举域。查询字符串与枚举键借用内容，不复制键文本。可变构造器使用可扩容索引，冻结后选择只读查询布局。

字典顺序以原始源码为准：

- CFD 提供的字典保留该 CFD 中键值项的声明顺序。
- CFT 默认值和常量中的字典保留该 CFT 中的声明顺序。
- 函数体字典字面量按键值项的书写顺序构造。
- 解析、常量编译、默认值补齐、复制和写回均保留这个顺序。
- for、keys()、values() 使用保存的顺序，不按 key 排序，也不使用哈希表的枚举顺序。

例如 `{ "z": 1, "a": 2 }` 的 keys() 返回 `["z", "a"]`。
字典相等按 key 和对应值判断，不要求两边声明顺序相同。重复 key 报错，不用覆盖来消除重复。

## 6. 函数与 fstring

```text
程序：已编译代码和执行所需的只读信息
函数值：函数身份、代码引用、所属对象或捕获环境
```

CFT 默认实现的类型化 IR 由契约共享，CFT/CFD 程序均在 RuntimeImage 构建期间降低并由映像持有。
每个对象的函数槽选择最终代码，不为每条记录复制一份默认程序。

执行帧借用映像中的固定函数绑定，动态闭包共享拥有捕获环境的绑定，捕获缓冲直接转移给绑定，空捕获不单独分配。固定函数调用与帧切换不克隆程序 Arc；动态闭包的程序和捕获通过共享所有权保活。构造器清理状态只在首次开始构造时分配，其头部和根容量计入共享预算。普通标量调用仍逐次执行工作量、深度和寄存器预算检查。

同一代码绑定不同 self 时是不同的绑定函数，不能只比较代码编号。
复制函数值保留其身份和绑定，不根据存放位置重新绑定 self。

创建对象时，字段及字段集合中直接声明的函数、fstring 绑定该对象；
嵌套对象自身字段的字面量绑定嵌套对象。普通局部闭包捕获外层绑定。
对象 self 绑定与外层局部值捕获分别保存，使同一函数可以读取新对象字段和捕获的外层对象。
已有函数值复制时沿用原绑定，不再执行字面量的创建绑定步骤。

fstring 保存文本函数，已经常量化时也可以保存固定文本表示；其声明类型和原始模板始终保留。
内部访问分清两件事：

- 获取原始存储值：供模板传递、绑定、复制、回收和工具检查使用，不执行文本函数。
- 按语言规则普通读取：fstring 执行后返回 string，普通值正常读取。

编译器在明确的 fstring 期望类型位置生成原模板传递，普通读取位置生成文本执行。
字典 values() 复制原模板；filter 以读取结果进行判定并保存入选原模板；
map 按回调声明的返回类型保存文本或模板。上述复制均保留模板的原有绑定和捕获环境。

获取集合本身不执行 fstring 元素。复制对象或追踪引用时也不通过文本 getter，避免意外执行 Host 调用。
data 对象或集合的内容相等比较则遵循语言读取规则，动态文本可能被执行。
记录相等只比较身份，不读取记录字段中的文本。

## 7. 维度记录

每个业务记录的维度字段都建立对应的普通生成记录。
没有覆盖文件时，覆盖字段全部为 None，仍可通过原记录引用回退基础值。

构建时先分配业务记录和生成记录的身份，再填入数据、连接双向引用。
基础值保存在原记录内部字段中，公开维度字段保存生成记录引用，不重复保存业务值。

基础字段为 T 时，覆盖字段为 T?；基础字段已经为 T? 时，覆盖字段仍为 T?。
覆盖 None 表示回退，不生成嵌套可选类型。基础值本身为 None 时，回退结果也为 None。

维度基础值及覆盖值中直接声明的函数、fstring 绑定关联的原业务对象。
生成记录的存储归属与函数的 self 绑定分别表示；回退和变体选择保留已有绑定。
覆盖值中的用户内联对象仍按普通对象规则建立其自身字段的绑定。

variants() 按静态维度顺序构造当前调用的结果字典，value 保存各变体的有效读取结果。
直接 fstring 值执行为普通字符串；集合、data 和函数保留其普通读取得到的值及绑定。
结果字典属于动态值，按可达性管理，不作为另一份常驻维度覆盖数据或读取缓存。

## 8. 句柄与回收

宿主可见句柄关联所属 Runtime。动态区中可复用的句柄包含位置及该位置的分配次数。
值被回收后，即使新值占用了同一位置，旧句柄也必须报失效，不能指向新值。

动态 ValueId 使用独立标记位、20 位槽位置和 23 位代数，固定身份与内联标量位于不同区域。
定位直接读取槽并校验完整身份。代数在槽复用时递增，达到上限的槽永久退役；GC 与局部构造清理共用该规则。
代数表、空闲槽表和仍持有的槽容量均计入动态内存预算。
这只管理存储位置复用，不引入 Runtime 多版本快照。

动态区回收从以下活跃来源追踪引用：

- 正在执行或因 Host 重入而暂停的调用栈、寄存器。
- 宿主持有的对象、集合和函数句柄。
- Host 调用期间仍在使用的参数、返回值和临时保活记录。
- 已存活对象、集合及闭包捕获环境中的引用。

固定区随 Runtime 整体释放，动态区处理循环引用，不能仅依靠对象之间的引用计数回收整个图。
Runtime 释放后，依赖它的句柄失效；已复制到宿主的独立标量和普通字符串继续存在。

## 9. Host 重入与错误清理

Host 回调可能再次进入 Runtime，并触发分配、扩容或回收。
外层调用暂停时，其活跃值仍然保活。
跨 Host 调用保留稳定句柄，不保留指向可扩容存储内部的裸地址；必须传地址时，存储需保证地址有效期内稳定。

正常返回、除零、预算耗尽和 Host 异常都执行相同的调用状态清理：

- 恢复本次调用占用的栈和寄存器范围。
- 移除本次调用的临时保活记录，保留外层调用的状态。
- 保留已被宿主或其他活跃值持有的返回结果。
- 失败调用不留下影响下一次执行的残余状态。

清理不回滚已经发生的 Host 外部副作用，也不重置同一顶层调用链已消耗的预算。
check 在一个检查执行失败后继续其他检查时，复用同样的清理机制。

## 10. 资源限制的归属

编译、优化与运行分别管理自己的资源限制。

| 限制 | 作用范围 | 达到限制时的行为 |
| --- | --- | --- |
| 源码结构与分析限制 | 解析深度、节点数及分析工作量 | 返回编译或分析诊断 |
| 常量优化预算 | 尝试提前计算确定结果的优化工作 | 保留原计算；普通常量定义仍须满足编译期确定规则 |
| 单函数寄存器槽数 | 编译后函数的寄存器窗口需求 | 槽位复用后仍超限时返回编译诊断 |
| 调用深度 | 当前执行链的嵌套调用 | 返回执行错误 |
| 执行链寄存器内存 | 活跃及暂停的全部调用窗口 | 返回执行错误 |
| 执行工作量 | 普通调用及其间接调用、文本读取、遍历与内建操作 | 返回执行错误 |
| 检查总预算 | 一次检查请求及其调用链 | 停止本次检查，报告未完成 |

限制参数与当前用量分开保存。相同调用链内的嵌套调用沿用当前用量，
调用帧退出清理占用的状态，但不撤销已经消耗的工作量。
后续独立普通调用使用自己的调用预算；检查预算与这些调用分开。

动态值的可达生命周期独立于调用帧生命周期。宿主持有的返回对象、集合或函数继续保活，
不能因为产生它的调用结束而回收；失去全部活跃根的动态图可以回收。
动态存储的内存限制与按可达性回收共同约束运行时存储，不能用单函数寄存器上限代替。
