# 构建与宿主接口

> 状态：架构设计
>
> 范围：核心构建输入、产物归属、宿主操作和交付边界。本文规定接口职责，具体 ABI 编码与导出名称另行定义。

## 1. 核心与项目工具的输入边界

核心使用内存中的源码、逻辑路径和静态定义工作。项目工具负责读取配置、发现文件，
把读取结果交给核心；业务宿主可以自行提供相同输入。

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| 解析源码 | 源码文本、逻辑路径、源码种类 | 无损源码树、解析诊断 |
| 编译 CFT | CFT 源码、静态维度定义 | 分析结果、诊断、成功时的只读契约 |
| 读取契约 | 契约字节 | 只读契约，或格式、版本与读取错误 |
| 构建 Runtime | 只读契约、CFD 源码及宿主绑定 | 分析结果、诊断、成功时的 Runtime |
| 执行调用 | Runtime、调用目标、参数、执行限制 | 普通返回值或执行错误 |
| 执行检查 | Runtime、选择的检查范围、检查限制 | 检查报告及是否完成 |

源码输入包含逻辑路径，使解析、编译与运行中的错误能够定位到同一来源。
逻辑路径不要求核心访问对应的物理文件。

维度名称和静态变体集合由调用方随 CFT 编译输入提交。项目工具从项目配置取得这些定义。
契约保存编译完成的生成类型及关联信息，CFD 加载使用契约中已经确定的维度结构。

## 2. 契约的逻辑内容

| 内容 | 使用方与用途 |
| --- | --- |
| 类型、继承、字段和 enum 声明 | CFD 类型检查、数据布局、查询与目标代码生成 |
| 函数签名和字段布局 | 函数链接、按槽访问和强类型包装 |
| Host 服务类型与成员签名 | 校验宿主服务绑定并编译其调用，具体宿主实现归 Runtime |
| 常量及默认值描述 | CFD 默认值补齐和运行时构造 |
| CFT 函数、fstring 和 check 程序 | 执行核心直接解释执行 |
| 未绑定的记录引用及 self 使用信息 | 构建 Runtime 时完成记录链接和对象绑定 |
| 维度生成类型与关联元数据 | 构建普通生成记录及基础值、覆盖值之间的关联 |
| 注解、原始模板及必要源码位置 | 编辑展示、代码生成和错误定位 |
| 格式版本和 schema 身份 | 契约读取与生成代码匹配 |

上表描述逻辑归属，不规定序列化分区的物理顺序或 Rust 结构体布局。
程序、附表及常量的序列化遵循[寄存器与字节码](./04-寄存器与字节码.md)的编码规则。

契约中的记录引用保存可链接的定义。每个 Runtime 根据自己的记录目录解析目标，
并持有绑定结果。CFT 默认程序保持共享，具体对象持有最终函数选择及所属对象绑定。
两个 Runtime 使用同一份契约时，各自的记录身份、CFD 覆盖和执行状态仍分别归属各自实例。

## 3. 分析结果与成功产物

解析和编译结果同时服务编辑与执行，成功 Runtime 是其中独立的成功产物。

| 构建状态 | 分析与编辑 | 执行 |
| --- | --- | --- |
| 源码未完成或语法错误 | 返回源码树、诊断及可用分析结果 | 本次构建不产生成功 Runtime |
| 类型、必填值或链接错误 | 保留可用的类型信息与源码对应关系 | 本次构建不产生成功 Runtime |
| 构建成功 | 工具按需保留源码树与分析信息 | 返回可读取、调用及显式检查的 Runtime |
| Host 服务缺失绑定，其余构建正常 | 保留完整服务类型与成员信息 | 返回 Runtime，在实际服务调用或宿主数据读取时报未绑定错误 |
| 检查失败或未完成 | 检查报告独立展示 | 已构建 Runtime 继续可用 |

业务宿主可以在成功构建后释放完整源码树。运行所需的代码、数据及必要定位信息继续存在。
编辑器保留自己的源码树和分析结果，并将预览绑定到成功构建的 Runtime。
构建失败时，旧 Runtime 的保留、展示和释放由宿主管理。

## 4. 宿主操作与生命周期

核心公开操作覆盖契约读取、Runtime 构建、记录查询、字段读取、函数调用、显式检查及释放。
C ABI 适配相同的操作和结果，C# 包装通过该边界取得权威数据与执行结果。

语言字符串操作采用 Unicode 码点规则。C# 包装调用语言长度、索引及比较操作时遵循核心结果，
不以宿主 UTF-16 字符串长度或代码单元索引替代语言行为。
复制到宿主的普通字符串可供宿主按自己的 API 使用，其原生操作与语言操作分别定义。

| 取得的内容 | 读取或调用行为 | 生命周期 |
| --- | --- | --- |
| 普通标量 | 返回对应标量值 | 独立复制后可脱离 Runtime |
| 普通字符串 | 返回已经保存的文本 | 独立复制后可脱离 Runtime |
| fstring 字段 | 执行文本函数，返回本次普通文本 | 复制出的结果字符串独立存在 |
| 对象或集合 | 返回关联 Runtime 的访问包装 | 宿主句柄参与保活，访问依赖 Runtime |
| 普通函数 | 返回保持原绑定的函数包装 | 宿主句柄参与保活，调用依赖 Runtime |
| 编译诊断或检查报告 | 返回对应阶段的结果 | 与业务返回值和执行错误区分 |

运行中的 fstring 读取沿用当前执行链；宿主直接读取 fstring 建立一次顶层调用。
对象复制、集合整体获取、内存追踪和源码编辑使用原始存储信息，保持模板及绑定。

Runtime 释放后，依赖它的对象、集合和函数句柄访问返回失效错误。
动态槽位复用时检查分配次数，旧句柄保持失效。跨 Runtime 的记录及函数使用按所属实例检查。

C# 使用创建线程拥有型句柄管理契约、builder 和 Runtime，通过 `using`、`Dispose()` 或 `RuntimeThread.Shutdown()` 显式释放。
普通标量和字符串复制到托管侧；对象、集合和函数包装保存 Runtime 与局部值 ID，继续访问 Rust 权威数据。
fstring 属性返回本次读取的 string，另提供显式取得模板句柄的接口，供 fstring 参数、返回值及模板复用使用。
对象、集合、函数及 struct 包装不单独释放；释放 Runtime 统一使访问失效，已复制字符串或标量不受影响。
三部分职责及具体 API 见 [C# 访问接口](08-CSharp访问接口.md)。

同一 Runtime 只在创建线程执行。其他线程访问返回线程错误；同线程 Host 同步重入沿用当前执行链及预算。

## 5. 构建能力与交付

`cft-compiler` feature 提供 CFT 契约编译能力。只加载契约的业务交付仍包含 CFD 解析、
名称与类型检查、函数和 fstring 编译、数据链接及解释执行所需组件。
共享函数编译能力同时被 CFT 和 CFD 使用。

项目配置读取、文件发现、源码写回、格式化命令、代码生成、发布和编辑会话属于工具交付。
业务宿主通过核心公开接口工作；C# 包装提供强类型访问、codec 和句柄管理。

C# 首批交付必须支持 Unity 2022 及以上版本及 IL2CPP，当前不引入 Unity 之外的专属特性或依赖。
托管包装、原生库加载、Host 回调和生命周期适配必须在 IL2CPP 构建产物中验收，
不能仅以编辑器内运行或普通 .NET 测试代替。托管包装适配 IL2CPP 的 AOT 编译，
不依赖运行时动态生成托管代码。

Host 服务声明与绑定属于当前实现范围，规则见[Host 函数](../1-语言/12-Host函数.md)。
宿主按 @Host singleton 类型整对象提供服务。Runtime 保存固定的绑定表示，
未绑定服务保留声明身份和签名，实际使用时报告缺失绑定。
C# 经 C ABI 调用 Rust 核心属于业务宿主交付，与语言内调用 Host 服务是两个独立方向。

## 6. 统一实现的完成条件

共享核心接入完成后，CLI、编辑器、LSP 和业务宿主使用同一套 CFD 语法、函数编译、
fstring 读取和执行规则。check 通过共享执行核心运行，检查入口负责选择、调度和收集报告。

C# 交付保留强类型包装、codec 和生命周期适配，解析器、函数编译器、执行器及权威数据由 Rust 提供。
编辑器使用共享源码树与项目修改能力，保持源码编辑和成功 Runtime 预览各自的职责。

行为验收见[实现验收](./06-实现验收.md)。
