# 核心架构

> 状态：架构设计
>
> 范围：CFT 编译、CFD 加载、运行时、项目工具和宿主接口。

## 1. 核心原则

- 一套 Rust 核心服务 CLI、编辑器、LSP 和业务宿主。
- 核心接收内存源码、契约和逻辑路径，不读取项目配置、不发现文件、不写文件。
- CFT 编译成只读契约。CFD 使用契约，不修改、重新编译或继续优化其中的内容。
- Rust 持有权威数据；其他语言通过强类型包装和句柄访问。
- Runtime 构建完成后，契约、程序和配置数据只读；每次调用的执行状态可变。
- 更新时创建新 Runtime，成功后由宿主切换。旧 Runtime 的释放也由宿主负责。
- check 可选，只返回报告，不参与 Runtime 的可用状态判断。

## 2. 分层与依赖

| 层 | 内容 |
| --- | --- |
| 核心 | 词法与语法、契约、类型检查、函数编译、数据加载、执行、诊断 |
| 项目工具 | 配置、源文件发现、代码生成、编辑写回、发布、索引 |
| 宿主 | CLI、编辑器、LSP、C ABI、C# 等语言包装 |

```text
CLI / 编辑器 / LSP -> 项目工具 -> 核心公开接口
C# / 其他业务宿主 -> C ABI   -> 核心公开接口
构建工具          -> CFT 契约编译 -> 共享核心组件
```

业务宿主不依赖项目工具层。核心组件之间按职责调用，核心不反向依赖工具或宿主。
CFT 契约编译通过 cft-compiler feature 提供；只加载契约的业务宿主不需要 CFT 声明编译器。

## 3. 核心组件

目标实现按以下 crate 边界组织：

| crate | 职责 |
| --- | --- |
| coflow-language | 共享词法、语法及源码结构 |
| coflow-core | 内部按契约、声明类型检查、数据、VM、加载和 check 接口划分模块，负责宿主无关的语言与运行时核心 |
| coflow-runtime | 项目配置、文件与源码操作、命令及工具编排 |
| coflow-ffi | 将核心公开接口适配为 C ABI |

coflow-core 依赖共享语法，不依赖 coflow-runtime 或宿主包装。
CFT 声明编译由 coflow-core 的 cft-compiler feature 控制；共享函数编译与 CFD 加载不随其关闭。
以上为目标实现边界；迁移完成后核心职责集中于 coflow-core，不保留重复的数据和检查实现。

| 组件 | 职责 |
| --- | --- |
| 诊断 | 错误码、消息、源码位置和报告 |
| 共享语法 | CFT/CFD 的无损词法、共享源码树、结构化值、表达式和函数体语法 |
| 契约 | 类型、字段、默认值、函数代码、生成元数据和文件格式 |
| 共享编译 | 名称与类型检查、函数和 fstring 编译、局部布局、常量优化 |
| CFD 加载 | 默认值补齐、记录创建、函数实现选择、引用与维度链接 |
| 执行核心 | 调用栈、寄存器、临时值、预算、Host 调用和执行错误 |
| 核心公开接口 | 加载、构建、查询、调用、可选 check 和释放 |

CFT 默认函数、CFD 函数、fstring 和 check 复用共享编译及执行核心。
执行核心采用寄存器式虚拟机，始终解释执行，不引入 JIT。
调用窗口、回收所需的存活信息和编码方向见[寄存器与字节码](./04-寄存器与字节码.md)。
check 增加检查入口、调度和诊断收集。require 通过普通 Host 函数绑定记录报告，
与其他 Host 函数共用调用机制。

## 4. 契约

契约包含：

- 类型、字段、enum、继承关系和稳定的声明身份。
- 函数签名及公开类型所需的布局。
- 常量、默认值描述和 CFT 编译好的函数、fstring、check。
- 维度生成类型、关联说明、编辑和代码生成元数据。
- 格式版本、schema 身份和必要的源码位置。

契约与目标代码一起交付，也可以嵌入生成产物。
schema 身份用于确认生成代码与契约的类型和布局匹配，不用于缓存业务检查结果。

CFT 编译时完成常量优化；不能确定时保留程序。
契约保存未绑定的记录引用和 self 使用信息，具体记录绑定由 Runtime 完成。
执行默认函数或求出默认数据，不等于修改契约。

契约按可信编译产物加载。读取时处理格式、版本、截断和读取错误，不重复运行完整类型检查或程序验证。
CFD 源码仍正常解析、检查和编译。

## 5. Runtime 构建

```text
读取契约
  -> 解析 CFD，保留源码树和诊断
  -> 检查记录与字段类型，补齐默认值
  -> 编译 CFD 函数和 fstring
  -> 建立记录、选择最终函数实现、连接记录引用与维度引用
  -> 可执行 Runtime
```

构建过程不执行 check，也不提前读取动态 fstring。
类型错误、必填值缺失、悬空引用或编译链接错误使构建失败。
Host 服务缺失绑定允许构建成功；实际调用其函数或读取其宿主数据时返回未绑定执行错误。
构建失败不影响已经在使用的旧 Runtime。
加载成功后，业务宿主可以释放源码树；编辑工具按需保留。运行时继续保留必要的诊断位置。

CFD 函数内部的组合类型、闭包和寄存器信息由其编译结果持有，不回写契约。
函数覆盖只改变运行时的实现选择：有 CFD 实现时使用它，否则指向契约默认实现。

## 6. 数据与程序归属

| 内容 | 归属 | 生命周期 |
| --- | --- | --- |
| CFT 类型、默认值和已编译程序 | Contract | 只读，可被多个 Runtime 共享 |
| 记录、集合、引用和最终函数选择 | Runtime | 构建后只读 |
| Host 服务身份、宿主数据与函数绑定表示 | Runtime | 构建后固定；缺失绑定在实际访问时检查 |
| CFD 函数、fstring 和局部编译信息 | Runtime | 构建后只读 |
| 寄存器、调用栈、临时值、当前预算 | 执行状态 | 随调用变化 |
| 源码树、文件索引、编辑内容 | 工具及分析结果 | 随编辑变化 |

契约常量与运行时对象使用各自的内部身份，不能因编码相似而混用地址或索引。
运行时可以直接引用契约中的只读定义，无需复制整份契约。

配置数据放入固定区，随 Runtime 整体释放；运行中新建的值放入动态区，按可达性回收。
对象按编译后的字段槽访问，记录身份与对象内容分开保存。
字典保留原始 CFT/CFD 键值项的声明顺序，查询索引不改变顺序或复制 value。
具体表示见[运行时数据结构](./02-运行时数据结构.md)。

## 7. 函数与 fstring 执行

普通函数显式调用。函数字段保留所属对象的只读引用，self 不需要对象副本。
普通函数需要其他记录时通过参数传入，不接收调用方的隐式当前记录。

fstring 是独立语言类型，模板由 f"..." 创建，已有模板可以按期望类型传递，底层复用函数代码和执行状态：

- 字段声明保留 fstring 信息，编辑器据此提供文本编辑。
- 普通读取具体 fstring 值时执行，返回本次 string；模板期望类型位置保留原模板及绑定。
- 函数内读取 fstring 共用当前调用状态和预算。
- 宿主直接读取 fstring 建立一次顶层调用。
- 获取集合不执行其中的 fstring；普通读取具体元素时执行。
- 编译为常量的 fstring 仍保留原声明类型及源码，不改变生成 API。

同一 Runtime 同时执行一条调用链。同线程同步重入沿用当前预算。
其他线程在执行链活跃时调用立即返回 Runtime 忙错误，不等待；空闲后允许换线程使用。
Host 调用按普通调用处理；异常转为执行错误，阻塞的 Host 调用不承诺被核心预算强行终止。

## 8. check

核心提供显式的 check 入口，调用方选择检查范围。
check 的目标是记录。data 不声明 check，执行器不根据字段、集合或引用自动展开检查对象图。
记录 check 可以直接读取 self.id；跨记录或 data 内容的业务校验由 check 代码显式表达。
检查请求可以覆盖多个记录，入口逐条执行所选规则；顶层 check 可以显式查询并遍历记录。
check 可以调用任何函数，包含 Host 和 CFD 实现，所需记录通过参数显式传入。

- require 不满足时记录问题并继续。
- 执行错误结束当前 check，继续其他 check。
- 检查总预算耗尽时停止并报告未完成。
- 检查结果和检查错误都不改变 Runtime 的可用状态。
- 每次请求实际执行所选 check，不做增量 check，不缓存检查结果。

解析和编译复用不等于检查结果复用。项目工具可以显示报告，但不能让核心把业务检查变成加载门槛。

## 9. 维度

维度通过普通生成类型和记录实现：

- 业务字段持有维度记录引用，基础值保存在业务记录的内部存储中。
- 维度记录保存覆盖值和原业务记录引用。
- 加载器建立双向引用；覆盖为 None 时通过原记录读取基础值。
- 没有覆盖文件时也建立对应维度记录，变体为空；先建立记录身份，再连接双向引用。
- 数据存入普通记录表，不再维护独立的覆盖值副本。
- 维度元数据描述生成类型、字段和关联关系，不代替记录存储。

细节见[维度](../1-语言/09-维度.md)。

## 10. 跨语言接口与生命周期

C ABI 是核心公开接口的二进制适配。C# 生成强类型包装、codec 和句柄，不建立第二份完整执行数据。
普通字段通过包装读取；fstring 属性 getter 调用核心计算，返回普通 string。

宿主持有的对象、集合和函数句柄参与保活。动态值按可达性回收，允许引用环。
可复用句柄记录位置及分配次数，旧句柄不会误指向复用该位置的新值。
Runtime 释放后，依赖它的句柄访问报失效错误；已复制到宿主的独立标量和字符串继续存在。
不同 Runtime 的记录和函数句柄不能隐式混用。

Host 同步重入保留外层调用的活跃值。跨 Host 调用使用稳定句柄，避免保留指向可扩容存储内部的裸地址。
正常返回和执行错误都清理本次调用的临时状态，不影响外层调用或宿主仍持有的返回值。

接口形态如下，名称由实现确定：

```text
加载契约 -> 构建器
构建器提交 CFD 和可用宿主绑定 -> 编译结果
编译结果 -> 诊断、可用分析结果、成功时的 Runtime
Runtime -> 查询记录、读取字段、调用函数、可选 check、释放
```

Host 服务的语言声明和绑定协议单独定义；调用预算、错误和生命周期规则与普通调用衔接。
Host 声明与绑定属于当前实现范围；require 使用同一 Host 调用机制，见[Host 函数](../1-语言/12-Host函数.md)。

构建输入、契约逻辑内容、分析产物和宿主交付见[构建与宿主接口](./05-构建与宿主接口.md)。

## 11. 编辑器与 LSP

编辑基于源码树、契约信息、源码位置和分析结果，不要求先构建成功的 Runtime。
未完成函数、缺字段或悬空引用仍能显示、定位和编辑，不另写一套语法解析器。

成功 Runtime 用于预览、执行和检查。若展示旧 Runtime 的结果，工具应说明其对应旧数据。
fstring 编辑保存原始 f"..."，预览结果不能写回模板。
涉及 Host 的预览由用户显式触发，不随每次敲字自动执行。

编辑器与业务程序共用核心实现，分别管理 Runtime 实例。
CFD 修改由项目工具基于共享源码树完成，编辑器负责交互和会话；不直接修改 Runtime。
源码树、编辑流程和交付边界见[编辑与共享语法树](./03-编辑与共享语法树.md)。

## 12. 诊断与验证

基本文件位置和调用位置始终保留；详细调试追踪可以关闭。
语法、类型和引用错误属于编译或加载诊断；check 报告与普通执行错误分别返回。

架构验证重点是：契约只读、CFD 覆盖正确、记录身份一致、fstring 读取次数正确、
check 可选且不复用结果、编辑失败时分析仍可用、释放后句柄明确失效。

具体场景及期望结果见[实现验收](./06-实现验收.md)。
