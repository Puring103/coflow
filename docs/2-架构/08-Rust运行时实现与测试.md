# Rust 运行时实现与测试

> 新 VM 的设计与验收以 [新 VM 实施计划](../plans/new-vm-and-csharp-snapshot.zh-CN.md) 及其配套规格为准；本文冲突内容在同一次交付中同步。

> 状态：Rust 运行时实现。
>
> 范围：共享函数编译、字节码、寄存器虚拟机、运行时内存、宿主调用和语言回归测试。

语言语义以 `docs/1-语言/` 为依据，组件边界见[核心架构](01-核心架构.md)。
本次实现范围包含普通函数、闭包、fstring、check、Host、通用内建方法、区间与 range-for。
条件分支使用 if、is TypeName 和 is Some(name)。每次请求实际执行所选 check；
解析和编译结果可以复用，检查结果每次重新产生。
数据加载成功、函数编译成功、执行正常返回和检查通过是不同的结果。

## 2. 编译与发布路径

```text
CFT 源码
  -> 共享语法
  -> 声明及默认值检查
  -> 默认函数、常量函数、fstring、check 语义分析及类型化 IR
  -> 只读 Contract

Contract + CFD 源码
  -> CFD 共享语法与结构化数据检查
  -> CFD 函数、fstring 类型检查与编译
  -> 记录身份预分配
  -> 字段、记录引用、self 和最终函数实现链接
  -> IR 降低、程序链接与验证
  -> 共享 RuntimeImage
  -> 线程所属 Runtime 实例
```

构建失败时返回诊断及可用的源码分析结果，不发布半成品 Runtime。
任何不可到达分支中的函数代码也接受静态类型检查；运行时只执行实际到达的路径。
构建不调用 Host、不执行 check、不求值动态模板。

CFT 默认实现的类型化 IR 保存在 Contract 中。映像构建从 IR 降低程序，再与 CFD 覆盖及固定数据链接。
选择最终实现仅修改候选映像，不修改 Contract。RuntimeImage 同时持有固定数据和已验证程序，
多个实例可以共享同一映像，并分别绑定 Host 和动态堆。构建映像不重新解析 CFT 函数源码。

## 3. 类型检查与控制流

编译环境包含声明命名空间、显式 use、常量、self 静态类型、参数、局部作用域、
当前函数结果类型和最近循环。名称解析产生稳定声明身份，执行阶段不重做名称解析。

`var` 必须显式声明类型。参数和函数最外层局部变量共用重复名称检查；内层 block
建立新作用域。参数、self、捕获和 for/Some 绑定只读，赋值仅写入可变局部变量。

类型检查按期望类型进行：

- None、空数组和空字典从声明、参数、字段或结果位置取得类型。
- int 使用 checked i32，float 使用 IEEE 754 binary32；允许的数值提升显式进入 IR。
- fstring 期望位置保留模板；普通读取位置生成模板执行操作。
- 函数参数和结果使用静态签名，调用目标先于参数求值，参数从左到右求值。
- 对象、记录、可选类型和继承收窄保留已确定的语言区别。

控制流图以基本块表示条件跳转、循环回边、返回和传播。所有可到达出口均检查返回类型。
break、continue、return 与可选传播的目标在编译阶段固定；闭包和插值具有独立的边界。
根局部变量被赋值时，撤销其自身及字段路径上的旧收窄。

闭包按实际使用的外层局部值生成捕获表。创建时复制值或稳定句柄，不保存寄存器地址。
对象字面量中直接声明的函数与模板绑定新对象；已存在的函数和模板保留原身份及绑定。

## 4. 字节码逻辑模型

程序包含只读指令流以及同一程序的附表：

| 部分 | 内容 |
| --- | --- |
| 函数头 | 静态签名、参数槽、寄存器数、程序身份 |
| 常量表 | 数值、字符串和静态声明引用 |
| 调用表 | 间接目标寄存器或直接 FunctionId、按求值顺序排列的连续参数窗口 |
| 对象表 | 实际类型、字段槽、初始化传输和绑定信息 |
| 闭包表 | 子程序、捕获来源及 self 绑定方式 |
| 来源表 | 指令到逻辑路径和原始表达式 span 的映射 |
| 活跃根表 | 分配及 Host 暂停位置仍需保活的寄存器 |

字段访问操作数保存编译后的字段槽。函数调用点不保存执行状态。
链接时将可静态确定的函数目标绑定为映像程序编号，发布前核对目标与参数签名。
参数窗口在程序发布前完成布局和跳转重定位；执行时复制连续槽位，Host 调用借用只读窗口切片。
源码映射与执行数据分离。Debug 保留原始调用边界和表达式定位；Release 内联可使用调用点定位，计算 fault 和 Host 的执行顺序保持不变。

| 指令族 | 逻辑操作 |
| --- | --- |
| 常量和绑定 | LoadConstant、Move、LoadSelf、LoadCapture |
| 数据读取 | LoadField、LoadIndex、LoadRecord |
| 值构造 | MakeObject、MakeArray、MakeDictionary、MakeClosure、MakeTemplate |
| 数值运算 | 区分 int/float 的加减乘幂、真除法、整数除法、余数和转换 |
| 逻辑与比较 | bool 取反、相等、顺序比较、位运算、类型判断、可选判断 |
| 控制流 | Jump、JumpIf、Return、可选传播 |
| 调用 | 直接调用、绑定函数调用、Host 调用、内建调用 |
| 模板 | ReadTemplate、模板插值与结果文本构造 |
| 遍历 | 集合迭代和整数区间迭代 |

短路运算降低为控制流，不将两个分支都编译成无条件执行的值计算。
require 使用普通 Host 调用指令，条件和消息均正常求值。
类型判断和可选解包降低为测试、只读绑定和条件分支。

## 5. 编码确定与测量

契约版本为 5，载荷保存声明及类型化 IR，不保存最终执行字节码。执行程序使用 64 位定长指令：低到高为 opcode:8、A:16、B:16、C:16、flags:8。
A/B/C 是 u16，BC 合并为 u32 索引。跳转单位是绝对指令序号，参数顺序保存在调用附表。
操作码属于 `vm/bytecode.rs::Opcode` 定义的内部执行编码，不属于 Contract 或 C ABI。

紧凑对照编码的常用指令为 opcode/A/B/C 四个字节；操作数超过 255 或 flags 非零时，
使用 `FF 00 00 00` 和完整的 8 字节指令。两者解码后的逻辑指令完全相同。

2026-09-20，本机 Release 构建测量如下；解码列为每个程序重复 1,000 次的总微秒数。
完整程序体积包含签名、常量、附表、嵌套程序、源码和存活信息，紧凑列替换指令流后计算。

| program | instructions | registers | fixed total bytes | compact total bytes | extension % | fixed decode us | compact decode us |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| arithmetic | 9 | 5 | 628 | 624 | 44.4 | 26 | 108 |
| wide-registers | 403 | 401 | 177446 | 179042 | 99.5 | 100 | 687 |
| large-constants | 802 | 2 | 33405 | 33405 | 50.0 | 124 | 1146 |
| closures | 25 | 9 | 1738 | 1694 | 28.0 | 51 | 197 |
| templates | 13 | 5 | 1194 | 1158 | 15.4 | 51 | 146 |
| host-calls | 10 | 6 | 747 | 723 | 20.0 | 25 | 108 |
| collections | 43 | 11 | 2812 | 2752 | 32.6 | 78 | 285 |

固定编码的解码成本更低；紧凑编码对包含全部附表的程序节省有限，因此当前采用固定编码。
以上是存储与解码对比，不是两套解释器的业务执行对比；动态指令数和附表查询没有变化。
执行性能受 Host、模板分配和活跃值规模影响，不能从解码微秒数推导业务吞吐量。

复现命令：`cargo run -p coflow-core --release --example bytecode_layout`。
程序覆盖算术循环、400 个同时存活的数值、大常量表、闭包、模板、Host 调用和集合回调。
对应执行语义通过 `vm_execution`、`vm_integration` 和 `vm_checks` 验证。

契约头为 8 字节 `COFLOWCT`、u32 版本、u64 载荷长度、32 字节 SHA-256，后接
小端定长整数编码的声明与类型化 IR 载荷。读取检查长度、版本、摘要、IR 类型和控制流，
不重新执行源码编译。该格式保存字段值，不转存 Rust enum/结构体的原始内存。

## 6. 执行器与调用窗口

```text
执行链
├── 线程所有权与进入次数
├── 连续 Slot 寄存器存储
├── 显式调用帧
│   ├── 程序、当前 PC 和函数绑定
│   ├── 窗口起点、长度和返回位置
│   └── 暂停位置的活跃根
├── 临时保活记录
└── 共享工作量、深度及内存用量
```

每个函数按编译结果分配独立窗口。参数写入约定的起始槽，其他槽用于局部值和临时值。
空槽状态与 unit、None 分开。编译器通过存活分析复用互不重叠的局部值和临时值槽位。

普通调用使用显式帧，不以 Rust 递归实现语言调用栈。返回先保留结果，再移除当前帧和窗口。
帧使用索引访问寄存器；扩容、回收或 Host 重入之后重新按索引获取值。
Host 回调期间不持有执行器内部互斥锁或指向可扩容容器元素的借用。

Runtime 固定在创建线程执行，同线程同步重入共享当前用量。异线程执行始终被拒绝，空闲时也不迁移线程。独立顶层调用建立新的预算，重入不建立可绕过限制的新预算。

## 7. 动态值与保活

固定区随 RuntimeImage 整体管理，包含共享 UTF-8 区、对象布局、连续字段/元素引用缓冲、字典、维度和独立函数/模板/Host 描述。TypeId、FieldId 与 LayoutId 区分类型、字段和实际布局。固定热读取直接借用这些区域，不创建通用 Value 或借用动态堆。通用检查接口与批量投影按需物化值。
动态区保存函数构造的字符串、对象、集合、闭包及模板，采用可达性追踪回收引用环。
句柄包含 Runtime 归属、槽位索引与代数；动态身份不复用，旧句柄不会访问新值。

回收根包含宿主持有的句柄、活跃寄存器、暂停帧的活跃值、函数绑定以及 Host 调用临时保活项。
扫描对象、集合和模板时读取原始存储，不执行动态文本或 Host 数据 getter。

正常返回与执行错误共用清理路径。宿主持有的结果在调用结束后继续保活；无人持有的结果和
临时值可以回收。释放 Runtime 后，依赖它的句柄失效；已经复制出的标量和普通字符串独立存在。

## 8. 内建方法与模板

内建签名及普通读取类型由编译器确定。map、filter、fold、any、all 的回调通过
同一调用帧执行；内建迭代不能绕过调用深度、工作量和动态内存限制。

集合遍历遵循保存顺序。filter 判定时普通读取元素，结果保存入选的原始值；values()
保留原模板。any/all 按语言要求短路。查询与集合关系不改变字典顺序。

字符串长度和索引使用 Unicode 标量值，比较不做 Unicode 规范化。数字文本与插值采用
相同 binary32 输出规则。正则模式在编译阶段检查，执行使用 Rust regex 语义。

每次普通读取动态 fstring 都执行模板，保存到 string 后重复读取不再次执行。
模板插值从左到右执行，错误使整个读取失败，不返回半截文本。
维度 variants() 按变体声明顺序执行普通读取，每次调用重新生成结果。

## 9. 错误与资源限制

编译错误、加载错误、执行错误和业务检查报告使用不同结果类型。
执行错误携带错误类别、逻辑来源、当前表达式 span 和 Coflow 调用栈，不携带寄存器快照。

| 限制 | 计量范围 |
| --- | --- |
| 编译结构 | 深度、节点、控制流规模、函数和常量规模 |
| 优化工作 | 常量尝试、分析和变换；与执行预算分开 |
| 单函数寄存器 | u16 虚拟寄存器编号及复用后的窗口需求 |
| 调用深度 | 普通调用、间接调用、模板和同步重入 |
| 执行链寄存器 | 所有活跃和暂停的窗口 |
| 执行工作 | 指令、迭代、线性扫描及内建工作 |
| 动态存储 | 活跃对象、集合、闭包和字符串 |
| 检查总工作 | 本次检查及其函数、模板和 Host 重入 |

算术溢出、无效索引、缺失函数、Host 未绑定、Host 异常、句柄失效和预算耗尽均返回执行错误。
错误退出清理占用，但不撤销已消耗的工作量或已发生的 Host 外部副作用。
核心预算不承诺中断阻塞中的 Host 回调。

默认执行限制为 10,000,000 工作量、1,000,000 次循环、256 层调用、1,000,000 个活跃寄存器，
动态堆载荷上限为 64 MiB，动态值数量上限为 1,000,000。堆计量包含值头、字符串与集合容量、
闭包捕获槽；不将共享 Contract、分配器元数据和进程其他内存计入这个逻辑预算。
检查入口使用 `CheckLimits` 指定工作与迭代预算，所有规则共用；普通调用使用 `ExecutionLimits`。

公开 Rust 入口为 `Runtime::invoke`、`read_text`、`run_checks`、`retain_value`、`release_value` 和 `collect`。
C ABI 的 `CALL(29)` 接收显式小端参数序列并返回带 tag 的值，Host 回调 operation 2
传递成员名与同格式参数；`RELEASE_VALUE(42)` 释放动态返回值保活，`COLLECT(43)` 显式回收，
`RETAIN_VALUE(44)` 为借用的子值增加独立保活。
具体字节载荷与所有权见 `engine/crates/coflow-ffi/include/coflow.h`，无需 C# 执行器。

## 程序发布与线程资源

执行入口使用字段私有的 `ValidatedProgram`；可编辑的 `Program` 必须重新计算活跃集合并通过结构验证后发布。嵌套闭包在发布时建立已验证程序引用，不在每次创建闭包时重新验证。

C ABI 的 Contract、缓冲区、声明编译器、Runtime、构建器和 lease 句柄全部保存在创建线程的 TLS 中。异线程访问和释放均被拒绝。全局原子计数仅分配不复用身份；句柄表和执行状态无需锁。显式释放或线程关闭时先移除登记，再在表借用之外运行析构；关闭期间拒绝重新登记。

动态值采用槽位索引与代数组成的句柄，槽位复用时递增代数，代数耗尽后退役。标记清扫直接访问槽位，过期句柄不能命中新值；长寿命的早期值不阻止其他槽复用。

## 11. 发布与优化证明

执行程序、绑定和执行宿主是 crate 内部类型。外部宿主通过 Runtime 调用；Contract IR 先完成语义验证，映像链接再核对固定引用、直接调用签名、指令结构和活跃根映射，成功后发布不可变程序。

Release 在语义值上建立 SSA 与 phi，保留 checked 运算和浮点位模式。基本块 CSE 只复用相同版本的标量表达式。局部数组只有用途全部可见、索引有效且元素未重写时才标量替换。局部标量闭包只有不逃逸、不观察身份、捕获未重写且函数体有限时才消除。区间分析证明计算对所有输入都成功后，才允许将循环不变量移到单入口循环之前。未证明的操作保持原位置。

指令扩展共用控制流重定位，循环附表在降低时重新生成。优化工作量和展开大小有上限，耗尽后保留有效计算。每个 pass 配套独立结果 oracle、故障反例或身份/Host 轨迹测试。

C ABI 批量投影逐节点编码原始存储，不保留整张通用值副本。C# 托管 Runtime 强持有 Host，native 回调上下文使用弱 GCHandle；执行期间显式保活，避免 Host 反向引用配置对象形成不可回收的跨语言环。拥有型资源由创建线程显式释放；动态投影通过弱引用登记，在托管 GC 后的下一次请求或 Runtime 释放时回收 lease。


## 10. 紧凑存储、发布映射与资源账目

固定数据由 `runtime/fixed.rs` 整体拥有。对象使用共享实际类型布局和连续字段字节；语义 `FieldId` 是声明字段域编号，布局内的 `FieldNameId` 是名称池编号，两者不能混用。int/float/bool 字段分别占 4/4/1 字节，固定复合引用占 4 字节。存在 None 或 Host 覆盖时，布局增加独立有效性/间接标记，保留完整数值位模式。同一实际类型的不同记录共享布局，记录和函数身份不按内容合并。枚举描述按声明类型与位值共享。

数组按载荷分类：int/float/bool 为 4/4/1 字节，可选 int/float 为 5 字节，可选 bool 为 2 字节；全 None 仅保存长度。固定复合数组使用 4 字节索引，动态引用数组使用实例身份编码。GC 不扫描纯数值、全 None 和固定引用数组。寄存器槽为 8 字节，动态身份不复用，存储槽可回收复用。

发布后的 `SourceMap` 将连续相同位置压缩为区间；没有空间收益时保留稠密表示。两种表示保留同一逐指令位置，查询只用于诊断。子程序附表指向同一发布版本，不额外保留未压缩的子映射。后续构建期优化通过 `to_editable` 还原完整映射，优化后重新验证、发布。

实例预算区分动态载荷和持有容量。槽数组、空闲索引、身份索引、builder/保活索引、根集合，即使当前没有存活载荷，也持续计入实例占用。哈希容量使用覆盖桶与控制字节的保守上界，不将该账目当作原生分配器的精确字节数。

临时预留通过 RAII 与顶层执行及同步重入共享；失败和提前返回自动释放。寄存器、帧、操作数窗口、根草稿、builder 根、Host 导出实参、默认值/导入集合、结构比较工作栈、集合判定索引、格式化输出与正则缓存均在扩容前预留，实际分配使用可失败预留。缓冲转交动态堆时解除临时预留，由实例账目接管。暂停外帧保留的容量不会因重入而漏计。

GC 在入栈时标记，工作栈每个动态槽最多进入一次；标记数组和栈先预留，栈容量上限为动态槽数。执行期间收集使用当前共享预算；执行结束后的显式收集使用独立的可失败临时分配。外借 Arc、活跃帧、捕获、owner、builder 和外部保活均纳入可达根。

动态正则使用无捕获 Pike VM，显式保存 NFA 与缓存，编译设置 NFA 上限；缓存容量和字符串键累计计费，工作量按状态数乘输入长度结算。顶层调用结束释放整个缓存表。Host 自有内存和阻塞时间不属于 VM 可控制资源；返回值导入重新验证并计费。

测试观测模块仅在 `cfg(test)` 编译，使用安全的分配计数依赖记录当前线程真实分配、峰值与回收量；GC、派发、调用和闭包计数不进入生产执行循环。测量范围与参数验证要求见 [新 VM 实施计划](../plans/new-vm-and-csharp-snapshot.zh-CN.md#19-性能验证门禁和文档)。
