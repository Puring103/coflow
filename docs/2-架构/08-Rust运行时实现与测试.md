# Rust 运行时实现与测试

> 状态：Rust 运行时实现。
>
> 范围：共享函数编译、字节码、寄存器虚拟机、运行时内存、宿主调用和语言回归测试。

语言语义以 `docs/1-语言/` 为依据，组件边界见[核心架构](01-核心架构.md)。
本次实现范围包含普通函数、闭包、fstring、check、Host、通用内建方法、区间与 range-for。
条件分支使用 if、is TypeName 和 is Some(name)。每次请求实际执行所选 check；
解析和编译结果可以复用，检查结果每次重新产生。
数据加载成功、函数编译成功、执行正常返回和检查通过是不同的结果。

## 1. 模块责任

| 模块 | 输入 | 输出与责任 |
| --- | --- | --- |
| `coflow-language` 共享词法 | CFT、CFD、函数及插值源码 | 无损 token、UTF-8 字节 span、结构错误 |
| `coflow-language` 函数语法 | token 与逻辑来源 | 表达式、语句、函数和插值语法树 |
| `coflow-core` 函数编译 | 语法树、声明环境、期望类型 | 类型诊断、控制流、捕获信息、字节码 |
| `coflow-core::contract` | CFT 编译结果 | 可共享且不可变的声明、默认程序及契约字节 |
| `coflow-core::loading` | 契约与 CFD 内存源码 | 数据诊断、对象和引用、CFD 程序及绑定 |
| `coflow-core::vm` | 已编译程序与参数 | 返回值或带来源和调用栈的执行错误 |
| `coflow-core::runtime` | 契约、配置数据、Host 绑定 | 值访问、调用入口、生命周期、动态值保活 |
| `coflow-core::check` | Runtime、所选记录及规则、检查限制 | 检查报告、执行错误和完成状态 |
| `coflow-runtime` | 项目路径与请求 | 文件发现、核心调用、诊断展示和工具命令 |
| `coflow-ffi` | C ABI 参数和句柄 | 参数校验、Host 回调适配、核心调用和资源释放 |

该 feature 只控制 CFT 声明编译。核心运行时不依赖文件系统、项目配置、桌面宿主或 C#。

## 2. 编译与发布路径

```text
CFT 源码
  -> 共享语法
  -> 声明及默认值检查
  -> 默认函数、常量函数、fstring、check 编译
  -> 只读 Contract

Contract + CFD 源码
  -> CFD 共享语法与结构化数据检查
  -> CFD 函数、fstring 类型检查与编译
  -> 记录身份预分配
  -> 字段、记录引用、self 和最终函数实现链接
  -> 完整候选校验
  -> Runtime
```

构建失败时返回诊断及可用的源码分析结果，不发布半成品 Runtime。
任何不可到达分支中的函数代码也接受静态类型检查；运行时只执行实际到达的路径。
构建不调用 Host、不执行 check、不求值动态模板。

CFT 默认程序保存在 Contract 中；CFD 覆盖保存在 Runtime 中。选择最终实现仅修改
候选 Runtime 的绑定，不修改 Contract。两个 Runtime 可以共享同一默认程序并绑定不同 self。
CFD 加载不重新编译或重新优化 CFT 默认程序。

## 3. 类型检查与控制流

编译环境包含声明命名空间、显式 use、常量、self 静态类型、参数、局部作用域、
当前函数结果类型和最近循环。名称解析产生稳定声明身份，执行阶段不重做名称解析。

`var` 必须显式声明类型。参数和函数最外层局部变量共用重复名称检查；内层 block
建立新作用域。参数、self、捕获和 for/Some 绑定只读，赋值仅写入可变局部变量。

类型检查按期望类型进行：

- None、空数组和空字典从声明、参数、字段或结果位置取得类型。
- int 使用 checked i32，float 使用 IEEE 754 binary32；允许的数值提升显式进入 IR。
- fstring 期望位置保留模板；普通读取位置生成模板执行操作。
- 函数参数和结果使用静态签名，调用目标先于参数求值，参数从左到右求值。
- 对象、记录、可选类型和继承收窄保留已确定的语言区别。

控制流图以基本块表示条件跳转、循环回边、返回和传播。所有可到达出口均检查返回类型。
break、continue、return 与可选传播的目标在编译阶段固定；闭包和插值具有独立的边界。
根局部变量被赋值时，撤销其自身及字段路径上的旧收窄。

闭包按实际使用的外层局部值生成捕获表。创建时复制值或稳定句柄，不保存寄存器地址。
对象字面量中直接声明的函数与模板绑定新对象；已存在的函数和模板保留原身份及绑定。

## 4. 字节码逻辑模型

程序包含只读指令流以及同一程序的附表：

| 部分 | 内容 |
| --- | --- |
| 函数头 | 静态签名、参数槽、寄存器数、程序身份 |
| 常量表 | 数值、字符串和静态声明引用 |
| 调用表 | 目标寄存器、按求值顺序排列的参数寄存器列表 |
| 对象表 | 实际类型、字段槽、初始化传输和绑定信息 |
| 闭包表 | 子程序、捕获来源及 self 绑定方式 |
| 来源表 | 指令到逻辑路径和原始表达式 span 的映射 |
| 活跃根表 | 分配及 Host 暂停位置仍需保活的寄存器 |

字段访问操作数保存编译后的字段槽。函数调用点不保存执行状态。
源码映射与执行数据分离，优化前后的故障仍指向产生该操作的原始表达式。

| 指令族 | 逻辑操作 |
| --- | --- |
| 常量和绑定 | LoadConstant、Move、LoadSelf、LoadCapture |
| 数据读取 | LoadField、LoadIndex、LoadRecord |
| 值构造 | MakeObject、MakeArray、MakeDictionary、MakeClosure、MakeTemplate |
| 数值运算 | 区分 int/float 的加减乘幂、真除法、整数除法、余数和转换 |
| 逻辑与比较 | bool 取反、相等、顺序比较、位运算、类型判断、可选判断 |
| 控制流 | Jump、JumpIf、Return、可选传播 |
| 调用 | 直接调用、绑定函数调用、Host 调用、内建调用 |
| 模板 | ReadTemplate、模板插值与结果文本构造 |
| 遍历 | 集合迭代和整数区间迭代 |

短路运算降低为控制流，不将两个分支都编译成无条件执行的值计算。
require 使用普通 Host 调用指令，条件和消息均正常求值。
类型判断和可选解包降低为测试、只读绑定和条件分支。

## 5. 编码确定与测量

契约版本为 2，使用 64 位定长指令：低到高为 opcode:8、A:16、B:16、C:16、flags:8。
A/B/C 是 u16，BC 合并为 u32 索引。跳转单位是绝对指令序号，参数顺序保存在调用附表。
操作码编号按 `vm/bytecode.rs::Opcode` 固定，0–27 分别覆盖常量到迭代预算操作。

紧凑对照编码的常用指令为 opcode/A/B/C 四个字节；操作数超过 255 或 flags 非零时，
使用 `FF 00 00 00` 和完整的 8 字节指令。两者解码后的逻辑指令完全相同。

2026-09-16，本机 release 构建测量如下；解码列为每个程序重复 1,000 次的总微秒数。
完整程序体积包含签名、常量、所有附表、嵌套程序、源码和存活信息，紧凑列替换指令流后计算。

| program | instructions | registers | fixed total bytes | compact total bytes | extension % | fixed decode us | compact decode us |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| arithmetic | 19 | 7 | 978 | 918 | 10.5 | 16 | 104 |
| wide-registers | 403 | 401 | 180590 | 180138 | 36.0 | 67 | 741 |
| large-constants | 1203 | 3 | 50193 | 46541 | 12.1 | 119 | 1823 |
| closures | 25 | 9 | 1680 | 1588 | 4.0 | 26 | 131 |
| templates | 14 | 6 | 1108 | 1060 | 7.1 | 25 | 81 |
| host-calls | 10 | 6 | 701 | 669 | 10.0 | 13 | 70 |
| collections | 41 | 10 | 2628 | 2496 | 9.8 | 40 | 221 |

固定编码的解码成本更低；紧凑编码对包含全部附表的程序节省有限，因此当前采用固定编码。
以上是存储与解码对比，不是两套解释器的业务执行对比；动态指令数和附表查询没有变化。
执行性能受 Host、模板分配和活跃值规模影响，不能从解码微秒数推导业务吞吐量。

复现命令：`cargo run -p coflow-core --release --example bytecode_layout`。
程序覆盖算术循环、400 个同时存活的数值、大常量表、闭包、模板、Host 调用和集合回调。
对应执行语义通过 `vm_execution`、`vm_integration` 和 `vm_checks` 验证。

契约头为 8 字节 `COFLOWCT`、u32 版本、u64 载荷长度、32 字节 SHA-256，后接
小端定长整数编码的声明与程序载荷。读取检查长度、版本、摘要、指令索引与存活布局，
不重新执行源码编译。该格式保存字段值，不转存 Rust enum/结构体的原始内存。

## 6. 执行器与调用窗口

```text
执行链
├── 线程所有权与进入次数
├── 连续 Value 寄存器存储
├── 显式调用帧
│   ├── 程序、当前 PC 和函数绑定
│   ├── 窗口起点、长度和返回位置
│   └── 暂停位置的活跃根
├── 临时保活记录
└── 共享工作量、深度及内存用量
```

每个函数按编译结果分配独立窗口。参数写入约定的起始槽，其他槽用于局部值和临时值。
空槽状态与 unit、None 分开。编译器通过存活分析复用互不重叠的局部值和临时值槽位。

普通调用使用显式帧，不以 Rust 递归实现语言调用栈。返回先保留结果，再移除当前帧和窗口。
帧使用索引访问寄存器；扩容、回收或 Host 重入之后重新按索引获取值。
Host 回调期间不持有执行器内部互斥锁或指向可扩容容器元素的借用。

同一 Runtime 同时只有一条执行链。同线程同步重入共享当前用量；另一线程立即收到忙错误。
空闲后可以换线程使用。独立顶层调用建立新的预算，重入不建立可绕过限制的新预算。

## 7. 动态值与保活

固定区持有加载完成的对象、记录和集合，随 Runtime 生命周期整体管理。
动态区保存函数构造的字符串、对象、集合、闭包及模板，采用可达性追踪回收引用环。
句柄包含 Runtime 归属与单调递增的值身份；动态身份不复用，旧句柄不会访问新值。

回收根包含宿主持有的句柄、活跃寄存器、暂停帧的活跃值、函数绑定以及 Host 调用临时保活项。
扫描对象、集合和模板时读取原始存储，不执行动态文本或 Host 数据 getter。

正常返回与执行错误共用清理路径。宿主持有的结果在调用结束后继续保活；无人持有的结果和
临时值可以回收。释放 Runtime 后，依赖它的句柄失效；已经复制出的标量和普通字符串独立存在。

## 8. 内建方法与模板

内建签名及普通读取类型由编译器确定。map、filter、fold、any、all 的回调通过
同一调用帧执行；内建迭代不能绕过调用深度、工作量和动态内存限制。

集合遍历遵循保存顺序。filter 判定时普通读取元素，结果保存入选的原始值；values()
保留原模板。any/all 按语言要求短路。查询与集合关系不改变字典顺序。

字符串长度和索引使用 Unicode 标量值，比较不做 Unicode 规范化。数字文本与插值采用
相同 binary32 输出规则。正则模式在编译阶段检查，执行使用 Rust regex 语义。

每次普通读取动态 fstring 都执行模板，保存到 string 后重复读取不再次执行。
模板插值从左到右执行，错误使整个读取失败，不返回半截文本。
维度 variants() 按变体声明顺序执行普通读取，每次调用重新生成结果。

## 9. 错误与资源限制

编译错误、加载错误、执行错误和业务检查报告使用不同结果类型。
执行错误携带错误类别、逻辑来源、当前表达式 span 和 Coflow 调用栈，不携带寄存器快照。

| 限制 | 计量范围 |
| --- | --- |
| 编译结构 | 深度、节点、控制流规模、函数和常量规模 |
| 优化工作 | 常量尝试、分析和变换；与执行预算分开 |
| 单函数寄存器 | u16 虚拟寄存器编号及复用后的窗口需求 |
| 调用深度 | 普通调用、间接调用、模板和同步重入 |
| 执行链寄存器 | 所有活跃和暂停的窗口 |
| 执行工作 | 指令、迭代、线性扫描及内建工作 |
| 动态存储 | 活跃对象、集合、闭包和字符串 |
| 检查总工作 | 本次检查及其函数、模板和 Host 重入 |

算术溢出、无效索引、缺失函数、Host 未绑定、Host 异常、句柄失效和预算耗尽均返回执行错误。
错误退出清理占用，但不撤销已消耗的工作量或已发生的 Host 外部副作用。
核心预算不承诺中断阻塞中的 Host 回调。

默认执行限制为 10,000,000 工作量、1,000,000 次循环、256 层调用、1,000,000 个活跃寄存器，
动态堆载荷上限为 64 MiB，动态值数量上限为 1,000,000。堆计量包含值头、字符串与集合容量、
闭包捕获槽；不将共享 Contract、分配器元数据和进程其他内存计入这个逻辑预算。
检查入口使用 `CheckLimits` 指定工作与迭代预算，所有规则共用；普通调用使用 `ExecutionLimits`。

公开 Rust 入口为 `Runtime::invoke`、`read_text`、`run_checks`、`retain_value`、`release_value` 和 `collect`。
C ABI 的 `CALL(29)` 接收显式小端参数序列并返回带 tag 的值，Host 回调 operation 2
传递成员名与同格式参数；`RELEASE_VALUE(42)` 释放动态返回值保活，`COLLECT(43)` 显式回收，
`RETAIN_VALUE(44)` 为借用的子值增加独立保活。
具体字节载荷与所有权见 `crates/coflow-ffi/include/coflow.h`，无需 C# 执行器。

| 层次 | 主要断言 |
| --- | --- |
| 共享词法与语法 | 完整消费、无损重建、Unicode span、错误恢复、结构限制 |

每个正向语言案例配对代表性的拒绝案例，断言错误阶段、类别和位置。

重点组合案例包括：闭包返回后调用、对象内新模板绑定 self、fstring 集合筛选后的再次读取、
None 与空集合、记录循环、数值提升和溢出、短路避免 Host 副作用、递归和预算耗尽、
Host 重入触发扩容及回收、失败调用之后再次正常调用。

## 11. 完成与提交条件
