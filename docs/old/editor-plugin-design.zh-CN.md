# CFD 编辑器插件设计

## 1. 范围

插件系统服务于 CFD 编辑器界面的团队内部二次开发。插件作为完全可信的前端模块运行，可以读取编辑器数据、提交编辑操作，并在编辑器预留的位置提供界面。

插件能力统一由以下三组 API 提供：

- 注册 API：注册页面、视图、侧栏、类型界面、命令和按键绑定。
- 事件 API：订阅项目、数据、选择和活动界面的变化。
- 数据 API：查询当前项目数据，并通过编辑器统一的数据修改链路提交写操作。

插件系统不替换编辑器外壳。窗口框架、活动栏、文档标签栏、内置数据视图和 Inspector 始终由编辑器管理。

## 2. 插件与贡献

每个插件拥有稳定且唯一的插件 ID。插件注册的每个页面、视图、侧栏、类型界面和命令都拥有插件内唯一的贡献 ID，编辑器使用“插件 ID + 贡献 ID”形成全局标识。

插件激活时完成注册并获得对应的注销函数。插件被禁用、卸载、重新加载或者项目关闭时，编辑器注销该插件的全部贡献、事件订阅和界面实例。

插件按照项目插件配置中的顺序加载，同一插件的贡献按照注册顺序排列。异步加载完成顺序不改变贡献优先级。

## 3. 注册 API

### 3.1 页面

插件页面作为独立文档打开在中央内容区域，并进入编辑器的文档标签栏。页面只占用文档内容区域，不覆盖活动栏、主侧栏、标签栏、Inspector 或其他编辑器外壳。

同一个页面贡献可以创建或激活自己的文档标签。页面的打开、激活和关闭由编辑器管理，插件只负责页面内容。

### 3.2 视图

插件视图是当前数据文档的一种展示方式。编辑器根据当前显式记录类型筛选可用的插件视图，并将它们显示在视图标签栏的加号菜单中。

插件视图必须声明一个或多个明确的记录类型。注册不接受通配类型、全类型目标或空目标集合。

插件视图可以声明为只读视图。只读视图只展示内容，不提供项目数据编辑交互。

视图可以声明是否需要字段值：

- 包含字段值时，数据 API 向视图提供记录及其字段数据。
- 不包含字段值时，只提供记录标识数据，对应由记录键和记录类型组成的两列记录视图。

所有匹配的插件视图都保留在加号菜单中，由用户选择，不使用“第一个匹配”规则隐藏其他视图。

### 3.3 侧栏

插件侧栏在活动栏中增加一个入口，并在左侧主侧栏区域显示内容。编辑器管理侧栏的激活、切换和尺寸，插件负责侧栏内容。

插件侧栏不会替换中央文档区域或整个编辑器界面。

插件可以通过注册 API 激活自己注册的侧栏。侧栏上下文可以关闭当前侧栏、打开同一插件的页面，也可以按文件路径和记录坐标打开编辑器中的记录；字段搜索结果还可以携带字段路径，请求编辑器定位并高亮对应字段。

### 3.4 类型界面

类型界面按照明确的类型和 slot 自动匹配。类型目标既可以是记录类型，也可以是字段类型；不接受通配类型、全类型目标或空目标集合。

系统提供以下 slot：

#### `cell`

- 仅用于表格单元格。
- 仅匹配记录的顶层字段。
- 上下文包含所属记录、顶层字段路径、字段声明类型和当前值。

#### `inspector`

- 用于记录视图和右侧 Inspector。
- 可以匹配记录根节点、顶层字段和嵌套字段。
- 上下文包含所属记录、完整字段路径、声明类型和当前值；记录根节点不包含字段路径。

#### `summary`

- 用于折叠容器标题中的摘要文字。
- 只返回文字，不提供任意布局界面。
- 可以用于顶层字段和嵌套字段。

同一类型和 slot 被多个类型界面匹配时，编辑器使用稳定注册顺序中的第一个有效贡献。项目配置指定的默认贡献优先于注册顺序。

### 3.5 命令和按键

插件可以注册命令，并为命令注册默认按键。界面入口和按键都调用同一个命令处理函数。

命令 ID 在插件内唯一。编辑器只在按键绑定的生效上下文满足时执行命令，并避免在文字输入和组合输入过程中截获普通编辑按键。插件被注销时，其命令和按键绑定同时失效。

## 4. 事件 API

事件 API 使用订阅和注销模型。事件处理函数的异常被限制在对应插件内，不中断编辑器的事件分发。

事件覆盖以下编辑器状态变化：

- 项目打开和关闭。
- 项目数据修订发布。
- 当前记录、字段或者多记录选择变化。
- 当前文档、视图和侧栏变化。

数据修订事件只在编辑器接受该修订并完成界面数据发布后发送。事件携带项目会话标识和修订号，插件可以据此刷新查询结果并丢弃过期计算。

撤销和重做与普通数据修改使用相同的数据修订事件，插件不需要单独处理撤销来源。

## 5. 数据 API

### 5.1 查询

数据 API 提供结构化查询，不要求插件解析 CFD 源文件。查询覆盖：

- 当前项目和数据修订。
- 已编译的类型与字段结构。
- 按明确记录类型查询记录。
- 按记录坐标读取记录。
- 读取顶层或嵌套字段值。
- 按记录键或完整字段内容跨项目搜索记录。

查询结果携带会话标识和修订号。同一查询返回的数据属于同一个已发布修订，插件可以使用修订号判断异步结果是否仍然有效。

记录坐标由文件、实际记录类型和记录键共同确定。字段位置使用结构化字段路径，能够表示对象字段、数组元素和字典项。

### 5.2 修改

插件通过数据 API 提交编辑器支持的数据修改请求。数据 API 将请求交给编辑器统一的 Mutation 管线，由模型校验、写入、重新加载、诊断发布和界面刷新共同完成。

一个插件修改请求对应一个历史事务。批量字段修改作为一个请求提交时，也作为一个整体进入撤销历史。请求成功后返回新的会话标识和修订号；失败时不产生历史项。

插件不能直接修改编辑器缓存、记录对象或源文件来表达项目数据修改。

## 6. 内置插件

编辑器自带、但不属于编辑器外壳的功能使用内置插件实现。内置插件与团队插件使用相同的注册 API、事件 API、数据 API、贡献生命周期和错误隔离规则。

内置插件由编辑器版本提供，始终启用，不出现在项目插件和全局插件的安装、禁用或卸载列表中。内置插件先于全局插件和项目插件激活，因此贡献顺序稳定。

项目搜索是内置插件。它通过数据 API 执行跨文件记录搜索，通过侧栏贡献提供界面，通过命令和按键绑定注册全局搜索入口，并通过宿主导航打开搜索结果。

## 7. 撤销与重做

插件修改与内置编辑操作共享同一个撤销和重做栈：

1. 数据 API 将插件请求提交给编辑器 Mutation 控制器。
2. 修改成功后，Mutation 控制器记录对应的历史事务并发布新修订。
3. 用户撤销或重做时，编辑器执行历史事务的逆向或正向操作。
4. 新修订发布后，插件通过数据修订事件重新查询和刷新界面。

插件页面、视图和侧栏中的临时界面状态不属于项目数据，不进入项目撤销栈。

## 8. 项目配置与默认项

项目插件配置保存以下内容：

- 插件清单位置。
- 启用状态。
- 稳定加载顺序。
- 按明确记录类型选择的默认插件视图。
- 按“类型 + slot”选择的默认类型界面。

项目默认项覆盖插件注册时声明的默认设置。默认贡献不存在、被禁用或者失效时，编辑器继续按稳定注册顺序选择有效贡献；没有有效插件贡献时使用对应的内置界面。

## 9. 错误隔离与回退

编辑器分别管理每个页面、视图、侧栏和类型界面实例。单个插件的清单加载、激活、挂载、更新、事件处理、命令执行和释放阶段的异常都记录为插件错误，并限制在发生异常的插件或贡献范围内。

- 类型界面失效时，继续选择下一个有效贡献；没有有效贡献时使用内置显示。
- 插件视图失效时，当前数据文档使用对应类型的内置视图。
- 插件页面失效时，编辑器保留文档标签和编辑器外壳，并在页面内容区域显示失败状态。
- 插件侧栏失效时，编辑器保留活动栏和其他侧栏，并切换到可用的内置侧栏。

一个贡献失效不会自动停用同一插件的其他有效贡献。插件重新加载或者重新注册后，编辑器可以重新创建对应实例。

## 10. 正确性约束

插件系统通过以下约束保持编辑器内容正确：

- 类型和 slot 使用明确目标，不提供全局替换注册。
- 插件读取已发布且带修订标识的数据快照。
- 插件写入统一经过模型校验和 Mutation 管线。
- 撤销、重做和外部文件变化都通过同一修订发布机制通知插件。
- 自动匹配和项目覆盖使用确定顺序，不依赖异步时序。
- 每个贡献独立处理生命周期和错误回退。
- 编辑器内置界面始终作为数据视图和类型界面的最终回退。
