# CFT/CFD 语言与运行时统一提案

> 状态：待实现提案。
>
> 本提案记录已确定的语言、契约、运行时和维度设计。实现细节在不改变本提案契约的前提下确定。

## 1. 目标

- CFT 与 CFD 共享词法、表达式、类型检查和函数执行语义。
- CLI、编辑器、LSP 与 C# 宿主共享一套 Rust 执行核心。
- 契约、数据、函数和校验规则具有清晰的生命周期与边界。
- 数据更新由宿主切换独立 Runtime，运行时不内置多版本快照管理。
- 维度数据无隐式选择状态，通过显式操作访问。

## 2. Runtime 生命周期

一个 Runtime 的生命周期固定为：

```text
构建 -> 编译 -> 可执行 -> 释放
```

Runtime 进入可执行状态后，配置、契约和程序不可修改。更新配置时，宿主创建新的 Runtime，完成编译和必要校验后切换应用入口；新 Runtime 构建失败不影响原 Runtime。

Runtime 不提供实例内快照、代际切换或反复编译。版本切换、旧实例取消和释放由宿主负责。不同 Runtime 的执行值不能隐式混用；纯数据可以经过类型验证后复制导入，带有函数身份或闭包环境的值保持所属 Runtime。

## 3. 共享执行核心

Rust 提供唯一的语言前端、契约编译、数据加载、函数编译、VM 执行、check 执行和诊断实现。CLI、编辑器、LSP 直接使用该核心，C# 通过稳定的原生接口调用。C# 负责生成类型、数据转换、Host 绑定和资源句柄管理，不再实现另一套函数或校验语义。

普通函数和 check 共用表达式、局部变量、控制流、闭包、类型检查和执行预算。check 使用独立的校验入口和权限规则，不因此成为普通函数值。

## 4. 类型与函数

### 4.1 可选类型

可选类型写为 `T?`，空值写为 `None`，有值时直接使用 `T` 的值。移除内建 `Result`、`Ok`、`Err` 及 Result 传播规则。业务结果由普通返回类型、枚举或业务结构表达；校验诊断和 VM fault 保持独立。

字段省略、默认值和显式 `None` 的精确优先级在类型与 CFD 规范中统一定义。可选值是否允许嵌套及是否保留专门传播语法列入详细设计，但不得重新引入隐式错误协议。

### 4.2 闭包

闭包是一等函数值，可以在 CFD 内返回、保存，也可以跨 Host 边界传递。宿主持有不透明函数引用，通过所属 Runtime 调用；闭包不会转换成脱离 Runtime 的宿主函数。

语言不提供可变全局变量，所有全局量都是常量。常量可在编译期内联或从只读常量存储读取，不进入捕获环境。闭包只按值捕获实际使用的外层参数和局部值，捕获值不可修改；无捕获匿名函数可直接表示为函数引用。

函数引用维持所属 Runtime 和捕获数据的存活。宿主显式释放 Runtime 后，既有函数引用调用返回明确的失效错误。更新应用入口不会改变既有闭包所属的 Runtime。运行期闭包、集合和其他动态值按存活关系回收，不能无限保留至进程结束。

同一 Runtime 同时只执行一条调用链，支持同线程同步 Host 重入，并沿用顶层执行预算。不提供异步挂起与恢复；延迟回调必须遵守相同的线程和生命周期规则。

## 5. Check 契约

`check` 是 CFT 契约中的专用校验结构，不能由 CFD 覆盖、返回、保存或作为回调传递。它使用与 CFD 函数一致的函数体语法，但语义仍是校验：执行适用规则、收集结构化诊断，并继续执行相互独立的失败条件。

VM 提供 check 执行入口，由调用方决定是否以及何时调用。Coflow 的完整数据校验、构建和编辑器数据校验流程必须调用该入口；仅处理 schema 或格式化的流程不执行完整数据校验。调用方跳过 check 时，不得宣称数据已满足业务契约。

check 自动处理类型规则、继承链规则和跨记录规则。校验失败是诊断，不是返回值；除零、越界、预算耗尽和未处理 Host 异常属于 VM fault。宿主参数、Host 返回值和临时构造值只进行类型及边界验证，不自动触发全量业务 check。

校验只能使用允许的纯计算和诊断能力，限制沿直接调用、间接调用和闭包调用链生效。应用 Host 外部服务不可从 check 访问。

### 5.1 内置 Host 类型与 `require`

系统内置能力由保留的系统 Host 类型组织，统一参与名称解析、签名声明和类型检查。系统声明不可覆盖，应用 Host 由宿主绑定。

`Check.require(condition, message)` 是校验上下文提供的特殊内置 Host 调用，返回 `()`。条件为 `true` 时不产生诊断；条件为 `false` 时记录诊断并继续执行。编译器识别该调用，附加源码位置，并使消息仅在条件失败时求值。

```cft
use std::Check::require;

check {
    require(level > 0, "等级必须大于 0");
}
```

`require` 失败不提供后续解包或类型收窄保证。普通内置函数遵循正常参数求值规则；短路运算和类型判断仍是语言结构。

## 6. 命名空间

类型、枚举、常量和内置 Host 使用统一命名空间机制。完整限定名全局唯一，不同命名空间允许相同短名；系统保留 `std` 命名空间。

文件可在所有导入和声明之前指定一次文件级命名空间：

```cft
namespace game::combat;

use std::Check;
```

不声明时属于全局命名空间。多个文件可以属于同一命名空间，目录和文件名不决定名称归属。命名空间不使用块状声明，也不负责加载文件。

本命名空间内可使用短名，其他声明通过完整名称或显式 `use` 访问；支持 `use std::Check::require;` 这样的成员导入。导入冲突和短名歧义直接报错；初始方案不提供通配导入、隐式导入或别名。CFD 使用相同规则解析类型名称，但命名空间不改变 record key。

## 7. 维度与自动生成类型

维度由基础数据和变体覆盖组成，不保存当前语言、地区或其他隐式选择状态。访问维度值必须显式调用 `.for(...)`：

```cft
item.name.for("zh")
```

字段声明继续使用维度注解，例如 `@dimension("language") name: string`。维度数据以字段为单位生成具体类型，类型名规则为：

```text
原始类型_字段_维度名称
```

因此 `Item` 的 `name: string` 字段绑定 `language` 维度时，生成类型 `Item_name_language`。该类型保存字段基础值和稀疏变体覆盖；`.for(...)` 返回原始字段类型 `string`。不同字段分别生成类型，即使它们绑定同一维度。

覆盖未提供某字段时使用基础值；显式覆盖值为 `None` 时表示明确为空，仅适用于可选字段。存储层必须区分“没有覆盖”和“覆盖为空”。维度查询不修改任何 Runtime 或宿主状态，返回值可被局部变量和闭包持有。

自动生成类型纳入契约和目标语言绑定。变体名称枚举化、未知变体诊断、覆盖粒度、基础值访问名、继承字段归属和多维度组合规则在详细设计中统一。

## 8. 错误与诊断

基础类型验证、业务返回值、check 诊断和 VM fault 是四种不同结果：

- 类型验证失败阻止数据或边界值进入执行环境。
- 业务函数使用普通返回类型表达业务状态。
- check 失败产生可继续收集的结构化诊断。
- fault 表示执行不变量、资源预算、非法操作或未处理外部异常，绑定源码位置和调用信息。

任何一种结果都不能通过 `Result`、异常捕获或隐式 `None` 相互替代。
