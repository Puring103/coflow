# Rust VM 设计

> 状态：内部设计契约
>
> 范围：函数编译、寄存器程序、调用、闭包、Host、校验和执行限制。

语言语义见 `01-language-design.zh-CN.md`；加载和宿主边界见 `02-api-runtime-design.zh-CN.md`。

## 1. 边界

VM 位于 `coflow-core`，只执行由同版本 Rust 编译器从已验证 CFT/CFD 函数、模板和 check 生成的内存
program。Contract 只保存类型契约、声明语义和函数源信息，不保存最终 VM bytecode；VM 不接受应用提供
的任意 bytecode，也不依赖 C# 生成布局。

Runtime 值、记录索引、集合、函数绑定和 VM 共用同一不可变快照。执行读取权威 Rust 数据，不经过
C# 对象图。C#、Unity 和其他宿主通过 `coflow-ffi` 使用相同执行器。

## 2. 编译与程序

函数语法解析使用显式续延栈处理表达式、语句块、闭包、模板插值与复合类型，统一按源码结构预算限制嵌套。
一元运算链、中缀运算链及短路链通过显式工作栈降低到 IR；一元负数字面量保留有符号整数边界语义。

Runtime 绑定 CFD 时完成函数编译与链接，在候选快照发布前完成名称解析、静态类型检查、捕获分析、
寄存器分配、调用点建立和 source map 生成。每个 Runtime 拥有与当前不可变数据快照对应的 Program Image；
同一 Contract 可以为不同 CFD 快照分别生成映像。

链接器把记录类型名、记录 key、常量名和字段链解析成固定值槽。最终映像不含通用记录引用指令；纯固定
标量直接成为指令常量，固定字段链不进入 Runtime 名称查找。Host 符号使用独立指令并保持动态边界。
Release 映像还融合立即整数运算并压缩指令流，同时重映射控制流目标和重新计算寄存器存活信息。

字节码的扩展和删除通过统一改写入口维护位置映射，同时更新直接跳转、循环附表与源码位置。
优化过程生成的分支使用原程序坐标；删除目标指向后续保留指令，扩展目标指向替换序列入口。
改写后由调用阶段重建活跃性或重新分配寄存器。

指令为 64 位定长字：opcode:8、A/B/C 各 16 位、flags 8 位。数值与布尔常量直接内联进指令字，
只有字符串和枚举常量进 K 表；整数字面量键可内联进索引附表；`self.字段` 融合为单条指令；区间
循环用 `ForPrep`/`ForLoop`（附表携带 limit、目标与开闭标记）把每迭代降到 2～3 条指令；双绑定
迭代融合为单条 `IterNext`。整数与浮点运算使用静态类型专用指令；调用和内建参数保存在程序级连续
操作数池中，调用点只保存范围。

编译或链接失败产生结构化诊断，程序不会进入发布快照。Contract 反序列化验证格式、版本与完整性；
Runtime Program Image 在发布前验证索引、寄存器、跳转目标和附表边界。

`OptimizationProfile::Debug` 保留源码求值结构和精确 source map，只执行发布所必需的链接；
`OptimizationProfile::Release` 开启固定数据折叠、指令融合和控制流压缩。两者的成功结果、Host 副作用
顺序一致；资源预算约束实际执行占用，内联、寄存器分配和尾调用会使两种模式的资源消耗不同。

## 3. 值与寄存器

寄存器槽保存标量或指向 Runtime 值的句柄。object、record、集合、函数和模板的内容由不可变 Runtime
存储拥有；程序不会把宿主对象地址写入寄存器。可选值由 `None` 或内部非空表示承载，源码中不存在
`Some(...)` 构造。

记录参数只传递当前 Runtime 的已验证索引，不复制对象。固定对象图传递性不可变，指令集不提供记录、
字段或集合元素写入；局部 `var` 只修改当前执行帧。动态集合操作构造新值，不修改固定快照。

函数参数、结果和字段访问都按静态类型验证。临时构造的复合值进入当前执行上下文的受限存储；返回给
宿主时仍由所属 Runtime 管理，不产生第二套语言值模型。

动态值存放在可复用槽位 arena 中，句柄由槽位索引和代数组成；槽位重用时递增代数，耗尽代数后永久退役，
过期句柄不能指向新值。回收使用槽位位图标记，执行中的活跃句柄、owner、捕获值和宿主显式保活值共同构成根集合。
新增动态值标记回收状态。存在长期保活图时按槽位增长或内存压力触发自动扫描；释放最后一个宿主保活、仍有外借 Arc 待归还或请求没有保活值时及时回收。无动态区变化的调用跳过自动扫描。显式回收始终执行。顶层请求收紧内存预算时，先结清此前延迟回收的垃圾，再安装新预算；同步重入继续共享外层预算。
固定值读取、字符串和枚举排序、集合及对象内容比较使用借用视图，只有确实需要拥有完整值的边界才物化；闭包共享程序和源码，动态预算只计捕获等实例载荷。

## 4. 调用与闭包

直接函数、函数字段、匿名函数、Host 函数和 check 使用统一调用协议。普通调用建立显式 frame；返回时
恢复调用者寄存器窗口。函数值包含程序身份、绑定 owner 和按值捕获环境。

匿名函数只捕获实际使用的外层值。捕获值不可变，不提供开放 upvalue。普通递归和相互递归
允许，但 frame、递归和总工作量均受预算限制。

模板作为受约束程序执行并产生 string。读取 fstring 字段时执行模板；复制模板保留原 owner 绑定。

## 5. 控制流与工作量

条件和循环编译为显式跳转。编译器验证跳转目标、分支结果类型和循环内的 `break`/`continue`。预算按
加权成本计费：循环回边、函数调用、Host 调用、分配以及文本长度向当前顶层请求的共享预算计费，普通
寄存器操作不计费（直线代码必然终止）。循环迭代预算以 256 次为单位批量扣减，允许最多 255 次的有限
超额；顶层返回与 Host 副作用边界前结清剩余计数。预算用于阻止失控执行，不构成程序可观察的精确计数。

执行限制至少覆盖指令、frame、寄存器、结构深度、集合元素、临时值和 Host 重入。达到限制立即产生
可定位 fault，不能依赖线程超时或进程终止。

## 6. Host 边界

VM 通过 `HostBindings` 抽象读取 Host 字段并调用 Host 函数。`coflow-ffi` 把该调用转换为 C ABI callback，
再由 C# 强类型适配层分派。参数和返回值按声明类型编码并验证，Host 错误转换为带调用位置的 fault。

Runtime 为单线程设计（与 Lua 的 `lua_State` 约定一致）：一个 Runtime 实例只允许从创建线程访问，
并发使用由类型系统拒绝（`!Sync`），解释器热路径不包含任何锁。同线程同步重入沿用同一执行预算
和 Runtime 身份；host 回调在同线程重入读取与调用不阻塞。

执行预算使用同线程共享计数；调用帧直接登记和归还深度与寄存器用量。执行器只在下一次分配可能触发
回收时发布活跃寄存器根，普通分配不会扫描调用栈。字段、索引和迭代在短暂堆借用内读取，HostData
离开堆借用后按原有 Host 边界求值。

## 7. Fault 与 source map

动态错误包括算术溢出、除零、非法索引、缺失函数、未绑定 Host、Host 回调失败、过期值和预算超限。
fault 记录当前函数、源模块、UTF-8 span 和精简调用栈。内部寄存器内容和宿主敏感值不进入公开错误。

## 8. 固定不支持

- 应用或 C# 侧提交任意 bytecode。
- 运行时反射、动态字段查找和按字符串调用函数。
- 可变闭包捕获、协程、暂停、异步恢复和持久化执行帧。
- 绕过统一预算的循环、高阶集合操作或 Host 重入。
- 将内部寄存器布局作为稳定 FFI 或生成代码 ABI。

## 9. 实现职责

- `runtime/image.rs`：只依赖固定数据和契约的链接上下文；可编辑程序完成链接、特化与内联后一次性验证发布，共享程序保持共享。
- `runtime/heap.rs`：代数句柄、载荷计费、保活及标记清扫。
- `runtime/state.rs`：实例独占的堆、预算和缓存所有权。
- `runtime/execution.rs`：请求上下文、导入导出与临时内存。
- `runtime/execution/host.rs`、`comparison.rs`、`builtins.rs`：指令与 Host 适配、借用比较及内建操作。
- `vm/compiler/`：表达式、集合、闭包及 builder 的语义分析与 IR 构造。
- `vm/slot.rs`、`vm/budget.rs`、`vm/scalar.rs`：执行槽、共享预算与统一标量运算语义。
- `vm/bytecode.rs`：字节码格式、附表与调用窗口。
- `vm/bytecode_analysis.rs`：发布验证、寄存器读写集合、控制流与工作队列存活分析。
- `vm/builtins.rs`：编译器与 IR 验证器共享的内建签名契约。

每个 Runtime 缓存已清空的寄存器、调用帧、根和操作数缓冲。调用帧归还前清除程序借用和捕获；缓存仅保留容量。
同步重入使用独立缓冲。活跃容量计入临时预算，空闲容量计入堆占用；新请求按入口所需容量裁剪缓存，根索引和参数预留也参与逐出判断。
根发布通过交换缓冲所有权完成，临时预算与堆占用同步转移，避免再次复制整组根。

编译器使用显式工作栈降低算术与短路逻辑链，各类复杂表达式独立处理，保留求值顺序和条件收窄语义。
高阶方法的期望类型探测使用独立语义状态，不复制已有指令、闭包程序和循环跳转。正式编译仍按源程序顺序生成 IR。
IR 降低逐个验证子程序；寄存器分配复用已经计算的活跃集合。链接优化只重算被修改程序的活跃集合，最终发布仍重建并验证整棵程序树。
子程序发布转移构建期所有权，共享的不可变程序仅在需要独立修改时复制。

动态字典按插入、删除增量维护键载荷容量；克隆后按副本实际容量重新记账。资源限制使用 `LimitKind` 分类，fault 保存原始原因及源码上下文，check 根据错误类别生成预算诊断。
