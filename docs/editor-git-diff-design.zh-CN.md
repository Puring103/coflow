# CFD 编辑器 Git Diff 设计

## 1. 定位

Git Diff 是编辑器原生的只读比较模式，不属于插件系统。它比较当前已发布项目与 Git `HEAD`，不提供暂存、还原、提交或补丁写入能力。

Runtime 拥有统一的变化语义和查询接口，CLI 与编辑器共享同一结果。编辑器 Core 负责调用 Runtime，前端只负责把结构化结果投影到主视图。

Runtime 通过 `gix` 在进程内发现仓库、解析 HEAD、读取提交树和 blob，并查询忽略规则。Git Diff 功能无需安装 Git，也不启动外部 Git 进程。一次查询固定 HEAD 提交，复用索引和忽略规则栈；已跟踪文件保留在比较范围内。

路径规范化、仓库外输入和生成文本的统一约定见 [路径与生成文本处理](path-and-generated-text.zh-CN.md)。

源码差异使用 `gix` 的 Myers 算法与行位置启发式在内存中生成，输出三行上下文的统一 Diff hunk，并保留末行缺少换行的标记。HEAD 项目快照写入临时目录，供 Runtime 按提交内自身的配置加载。

## 2. 入口与生命周期

活动栏提供 Git 变更入口，左侧主侧栏显示变更文件和记录。中央文档区使用独立的 Git Diff 标签进入比较模式。

比较结果绑定当前项目 session、数据修订和 `HEAD` commit。项目数据发布新修订时重新查询；用户也可以显式刷新以获取新的 `HEAD`。过期结果不进入界面。

## 3. 变化投影

比较模式使用统一颜色语义：

- 新增为绿色，只有当前工作区端点。
- 删除为红色，只有 `HEAD` 端点。
- 修改为黄色，同时具有 `HEAD` 和当前工作区端点。

表格视图复用主 `TableView`。新增和删除记录各显示一行，修改记录以相邻的 `HEAD` 行和当前行显示。比较行使用独立的展示 ID，记录坐标仍保持原有领域身份。

记录视图复用主 `RecordView` 和 `DataCardExpanded`，左侧显示 `HEAD`，右侧显示当前工作区。字段路径标注由共享的字段行组件渲染。

源码视图复用主 CodeMirror 组件，左右分别显示 `HEAD` 和当前源码。统一 Diff hunk 被转换为两侧的行标注，比较期间不启用草稿、保存和项目写入。

## 4. 正确性

`HEAD` 使用 commit 内自身的项目配置、Schema 和 CFD 数据构建，当前端点使用 session 已发布的数据和源码。两个端点都能形成完整模型时才提供记录和表格视图；否则只提供源码比较并显示状态。

比较模式始终只读。查询失败、修订过期或语义 Diff 不可用时，界面显示明确状态，不把未标注的普通文档伪装成比较结果。
