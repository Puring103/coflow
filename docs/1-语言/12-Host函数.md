# Host 函数

> 状态：语言设计
>
> 范围：宿主提供的函数、普通调用规则及其与 check 的关系。

## 1. 声明与实现的职责

Host 函数的类型由语言声明确定，具体实现由宿主绑定提供。
Host 声明、绑定、异常映射和同步重入属于当前实现范围。
普通函数、CFD 实现、fstring 和 check 使用同一套 Host 调用规则。

Host 服务使用 `@Host singleton` 声明，继承规则与普通 singleton 相同。
服务对象包含宿主提供的只读数据字段及函数字段；每种 Host 类型在一个 Runtime 中对应一个服务身份。

```cft
namespace app;

@Host
singleton Services {
  environment: string;
  log: fn(message: string) -> ();
}
```

@Host 服务由宿主整对象提供。函数字段在 CFT 中声明签名，具体实现来自服务绑定，
不声明 CFT 默认函数体，也不由 CFD 覆盖。Host 对象不使用用户 CFD 记录或用户内联对象构造。
普通 singleton 的 CFD 记录数量检查不用于要求 Host 必须提供 CFD 记录。

### 1.1 成员访问

Host 服务使用普通单例记录的类型和固定 key 定位，key 为类型短名。
例如 `(&app::Services::Services).log("开始")` 调用上述服务，
`(&app::Services::Services).environment` 读取绑定的数据。
服务的字段类型和函数签名在 CFT 编译时确定，实际绑定归所属 Runtime。

系统名称 `Coflow::Check::require` 解析到系统提供的 Host 服务成员。
导入该成员后取得其绑定函数值，后续调用与通过服务对象取得的 Host 函数使用同一机制。

### 1.2 整对象绑定与缺失绑定

宿主向构建器提交服务对象，以 Host 类型身份选择绑定。不同 Host 类型可以同时绑定。
绑定对象提供该服务的数据和函数实现，构建成功后 Runtime 持有自己的服务绑定表示。
同一宿主服务对象可以被多个 Runtime 使用，各自的语言记录及函数身份仍属于各自 Runtime。

允许服务缺失绑定，CFT 编译及 Runtime 构建仍可成功。
声明身份和函数签名足以完成类型检查；实际调用未绑定服务的函数或读取其宿主数据时返回执行错误。
取得和传递该服务的函数目标保留服务身份，实际调用时检查绑定。
未执行到该服务访问的路径按普通规则运行。

已构建 Runtime 的服务绑定保持固定。变更绑定通过创建新 Runtime 生效；旧 Runtime 保留原绑定状态。
绑定缺失与声明未知、签名错误分别处理：后两者仍是编译或构建诊断。

Host 实现可以产生外部副作用。CFT 常量优化不执行 Host 调用，
Runtime 构建也不通过提前执行 Host 函数取得动态文本结果。

## 2. 调用与函数值

Host 函数使用普通函数签名检查参数和返回值。
直接调用、保存为函数值后间接调用，以及在闭包或集合中传递，均遵循普通函数规则。
复制已有 Host 函数值保留所属 Runtime 与宿主绑定。

调用目标和参数从左到右求值，全部参数求值成功后进入宿主实现。
任一参数计算发生执行错误时，本次 Host 调用不发生。
Host 函数使用普通参数求值规则；需要延迟执行的业务逻辑可以通过普通函数参数显式传递。

Host 返回值遵循声明类型与所属 Runtime 的值规则。
未处理的宿主异常转换为包含调用位置的执行错误。
执行错误沿普通调用链退出，不回滚已经发生的宿主外部副作用。

## 3. require

`Coflow::Check::require` 是普通 Host 函数，签名为：

```text
fn(condition: bool, message: string) -> ()
```

检查入口使用的宿主实现，在 condition 为 false 时把 message 写入本次报告，然后正常返回。
condition 为 true 时不记录检查问题，但调用前仍按普通规则计算 message。

require 可以被普通函数、闭包、CFD 实现和 check 调用，也可以作为函数值传递。
报告接收与其他 Host 外部行为一样由绑定实现负责；语言和执行器不为 require
增加检查专用函数类型、闭包逃逸限制或调用权限规则。
普通入口调用 require 仍执行所绑定的宿主实现。

检查入口负责组织本次检查与报告，require 的宿主实现负责提交检查问题。
函数内部的 require 不改变该函数的 self、参数、返回类型和普通控制流。

## 4. 执行链与生命周期

同一 Runtime 同时执行一条调用链。Host 在同线程同步重入时沿用顶层调用预算。
外层暂停的寄存器、函数绑定、Host 参数和临时值继续保活。
跨 Host 调用保存稳定句柄；存储扩容或回收后按有效句柄访问数据。

Host 返回或发生执行错误时，清理本次调用状态，保留仍然活跃的外层调用和宿主持有的值。
同一执行链已经消耗的预算继续累计。执行预算约束核心工作，不能强制终止阻塞的宿主函数。

Runtime 释放后，依赖该 Runtime 的 Host 函数值与其他函数句柄按相同规则失效。
宿主独立持有的业务资源生命周期由宿主负责。
