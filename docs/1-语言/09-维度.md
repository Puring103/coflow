# 维度

> 状态：语言设计
>
> 范围：维度注解、生成记录和变体访问。

## 1. 声明

维度为一个字段提供多组值。`@localized` 等价于 `@dimension("language")`。

```cft
table Item {
  @localized
  name: string;

  @dimension("region")
  price: int;
}
```

一个字段只绑定一个维度，两种注解不能同时使用。
维度定义静态给出变体集合，生成类型的字段在契约编译时确定。

维度字段用于记录类型，也可以声明在 abstract table 父类型上。
data 不声明维度字段，维度的基础值和覆盖值可以包含 data 对象。

## 2. 普通生成类型与引用

每个维度字段生成一个 table 类型，位于 `Coflow::dimension`。
例如 Item.name 对应 `Item_name_language`。

加载后的关系为：

```text
业务记录
  name -> 维度记录
  基础 name 值（内部存储）

维度记录
  原记录引用 -> 业务记录
  zh / en / ... -> 对应覆盖值或 None
```

- 业务记录上的维度字段转为指向维度记录的引用。
- 该公开字段的类型直接使用生成的 table 名称，与普通记录类型一样不加 `&` 前缀。
- 维度记录保存对原记录的引用，使用它读取基础值。
- 原始基础值独立保存在业务记录的内部存储中，不通过已经转为引用的字段递归读取。
- 维度记录和引用使用普通记录存储，不另外维护一份覆盖值表。
- 用户自行创建的同形对象不是有效维度记录，不能使用 for 访问。
- 继承字段的生成类型归声明字段的类型，覆盖记录按对应业务记录定位。
- 每个业务记录的维度字段都有对应的生成记录；没有覆盖文件时，各变体为 None，仍可通过引用回退基础值。
- 基础字段为 T? 时，生成覆盖字段仍是 T?，不再套一层可选类型。

生成身份由原始类型的完整限定名、字段名和维度名共同确定。
短显示名可以使用下划线拼接；内部身份和目标代码名称必须能区分命名空间及分隔符碰撞。

## 3. CFD 输入

业务 CFD 写基础值；维度 CFD 写变体覆盖。引用关系由加载器建立，不要求用户手写。

```cfd
sword: Item {
  name: "Sword",
  price: 100,
}

sword: Item_name_language {
  zh: "剑",
  en: None,
}
```

覆盖记录 key 与业务记录一致。生成类型的短名仅在维度数据记录的类型位置参与特殊名称解析。
若与用户类型短名冲突，使用完整限定名。

## 4. 读取和回退

```cft
item.name.for("zh")
item.name.default()
```

`.for(variant)` 接受 string 表达式；`.default()` 读取基础值。
没有隐式的当前语言或当前地区。

| 覆盖内容 | 结果 |
| --- | --- |
| 有值 | 使用覆盖值 |
| None 或未提供 | 使用基础值 |

覆盖只有有值和 None 两种状态，None 不另外表示清空。
基础字段本身可以为可选类型，其基础值可以是 None。
变体不存在时按基础值回退；未知变体数据不加载，工具可以提示。

查询返回原业务字段类型的读取结果。例如 fstring 变体读取后得到 string，
可选 fstring 得到 string?。读取到的普通结果可以保存到变量中。

### 4.1 函数与文本的 self

维度基础值和覆盖值中直接声明的函数、fstring 均绑定原业务对象。
其数组、字典和可选值中的函数字面量、文本字面量沿用这一绑定。
生成的维度记录负责保存覆盖值和关联引用，self 的类型检查上下文采用原业务字段所属类型。
继承的 CFT 默认实现仍按声明类型检查，运行时绑定实际业务对象。

维度值包含用户内联对象时，该内联对象自身字段中的函数字面量和 fstring
按普通对象规则绑定该内联对象。已有函数值保持创建时的绑定。

例如 Item 有普通字段 code 和维度字段 label：

```cft
table Item {
  code: string;

  @localized
  label: fstring = f"编号：{self.code}";
}
```

```cfd
sword: Item {
  code: "S01",
}

sword: Item_label_language {
  zh: f"物品编号：{self.code}",
}
```

静态维度包含 zh 时，`(&Item::sword).label.default()` 得到 `"编号：S01"`，
`(&Item::sword).label.for("zh")` 得到 `"物品编号：S01"`。
两处 self 均绑定业务记录 sword 的对象。覆盖值回退只选择基础值，不改变模板的 self。

## 5. 遍历与 check

`.variants()` 不接受参数，返回全部静态变体名称到回退后有效值的只读字典。
key 类型为 string，value 类型为原业务字段的普通读取结果类型，顺序与静态维度定义一致。
基础值通过 `.default()` 单独访问，不额外作为一个字典项。

| 原业务字段类型 | variants() 返回类型 |
| --- | --- |
| string | {string: string} |
| int | {string: int} |
| 普通 T?（T 非 fstring） | {string: T?} |
| fstring | {string: string} |
| fstring? | {string: string?} |
| [fstring] | {string: [fstring]}，获取集合不执行其元素模板 |

例如静态维度按 zh、en 顺序定义，基础 name 为 `"Sword"`，zh 覆盖为 `"剑"`，en 为 None：

```cft
var names: {string: string} = item.name.variants();
```

names 的内容为 `{ "zh": "剑", "en": "Sword" }`。
未提供覆盖的变体仍有对应字典项，其值与调用 `.for(variant)` 的有效结果相同。

### 5.1 求值与保存

调用 variants() 时，按静态变体顺序逐项选择覆盖值或基础值，再进行该值的普通读取。
直接的 fstring 值在本次调用内执行，返回字典保存生成的 string；
fstring? 为 None 时保存 None，有值时保存本次得到的文本。

多个变体回退到同一基础 fstring 时，每个变体分别读取和执行，不共享缓存的文本结果。
成功返回后，再次读取结果字典中的普通字符串不执行原模板；重新调用 variants() 则重新计算。
当业务字段是集合、data 对象或普通函数时，保留对应值及绑定，不递归执行其中的模板或普通函数。

任一变体读取产生执行错误时，整个 variants() 调用失败，不返回部分字典。
已发生的 Host 外部副作用遵循普通执行错误规则，不回滚。
变体遍历、模板执行及结果构造计入当前执行链的预算。

### 5.2 显式校验

check 显式读取或遍历要检查的变体，不根据字段依赖自动重跑。
没有覆盖的变体也参与遍历，检查内容与正常读取结果相同。

例如在 Item 的记录 check 中：

```cft
check namesPresent {
  for variant, name in self.name.variants() {
    require(!name.isBlank(), f"记录 {self.id} 的 {variant} 名称为空");
  }
}
```

示例先导入 `Coflow::Check::require`，并使用本次检查的 Host 绑定。
variant 和 name 的类型从返回字典确定，均为 string。

## 6. 编辑与生命周期

编辑器编辑基础值和覆盖值，隐藏系统建立的关联引用。
生成类型纳入契约和目标语言绑定，维度记录不作为普通业务表对外展示。

维度值和关联记录归所属 Runtime 管理。数据更新通过切换 Runtime 完成。
