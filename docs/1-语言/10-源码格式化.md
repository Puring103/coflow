# 源码格式化

> 状态：语言设计
>
> 范围：CFT/CFD 的规范排版契约。

格式化是消费无损 token 流的空白规范化过程。它只改变 trivia、换行和结构布局，不重排或改写非 trivia
token，不补默认值，也不执行 schema-guided 类型检查。

## 1. 不变量

- 对有效输入保留 token、注释内容和声明/值顺序。
- 对可识别的编辑中未完整文本尽可能产生稳定布局，不要求先通过语义检查。
- 输出幂等：对格式化结果再次格式化不产生变化。
- 规范输出使用 LF，并以一个换行符结束。
- 语法和语义检查是源码有效性的权威。
- 格式化成功不代表源码通过解析或检查。

## 2. 通用排版

- 每一级缩进为 2 个空格，不使用制表符。
- 行尾不保留空格；连续空行最多保留一个。
- `#` 注释内容保持不变，缩进跟随所在结构。
- 二元运算符、`=`、`->`、`=>` 两侧使用规范空格；`:` 和逗号后使用一个空格。
- `::`、字段访问 `.`、一元运算符和泛型尖括号内侧不添加空格。
- 顶层声明或记录之间使用一个空行。

## 3. CFT 布局

type、enum、check 和函数体的左花括号与头部放在同一行，结构成员各占一行：

```cft
@label("Item")
type Item : Entity {
  name: string;
  tags: [string] = [];

  check {
    require(name != "", "名称不能为空");
  }
}
```

- 字段、const、类型别名和 check 语句以分号结束。
- enum 变体以逗号分隔；多项 enum 展开为每行一个变体。
- 注解单独占行并紧贴它修饰的声明；字段注解组前保留一个空行。
- 多行泛型、函数参数和续行相对所属行再缩进一级。
- 短数组、字典和对象默认值可以保持单行；结构性 type/check 块始终展开。

```cft
type Handler = fn(
  value: int,
  fallback: fn(int) -> int
) -> int?;
```

```cft
enum Rarity {
  Common,
  Rare = 10,
}
```

## 4. CFD 布局

顶层记录和带 type marker 的多态对象使用展开块。字段每行一个并保留尾逗号：

```cfd
sword: Item {
  name: "Sword",
  tags: [weapon, melee],
}

shield: Equipment {
  name: "Shield",
}
```

- 记录写作 `key: Type {`，冒号后一个空格。
- 展开块的右花括号单独占行；若它是字段值，逗号跟在右花括号后。
- 数组内的多态对象展开后，数组右方括号单独对齐。
- 简单数组、字典和 `TypeName { ... }` 对象允许保持单行。
- 函数字段签名尽量合并到同一逻辑行；多行签名和函数体按 2 空格层级缩进。
- 函数体中手工保留的单个空行不会被删除。

```cfd
sword: Item {
  name: "Sword",
  tags: [weapon, fire],
}
```

```cfd
calculator: Calculator {
  classify: fn(value: int) -> string {
    if value >= 10 {
      "large"
    } else {
      "small"
    }
  },
}
```

## 5. 与检查的关系

- 格式化不替代语法检查和数据检查。
- 语法与语义检查始终以语言规则为准。
