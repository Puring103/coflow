# Coflow 语言总览

> 状态：语言设计
>
> 范围：CFT 与 CFD 的语言层设计。

## 1. 设计目标

- CFT 与 CFD 共享词法、标识符、类型引用、值语法、表达式、类型检查和函数执行语义。
- 语言只有一套前端和执行语义，不建立第二套解析、检查或校验语义。
- 类型错误在数据或边界值进入执行环境前被诊断；执行期只处理动态 fault。
- 语言行为具有确定性，不依赖外部环境的反射顺序、区域设置或容器实现细节。
- 诊断、源码位置和规范格式在 CFT、CFD 与函数体之间保持一致。

## 2. CFT 与 CFD 的职责

| 语言 | 职责 |
| --- | --- |
| CFT | 类型、字段、枚举、常量、别名、函数签名、默认值、注解和 check 规则 |
| CFD | 记录值、字段值、引用、内联对象，以及覆盖默认实现的函数体 |

CFT 提供静态结构与规则，CFD 在结构约束下提供数据。CFT 编译为一个不可变契约，CFD 依据该契约加载、
校验和链接。普通函数字段可以在 CFT 声明默认实现，CFD 提供同字段函数值时覆盖该默认实现。

## 3. 共享语言基础

CFT、CFD 与内嵌函数体统一使用：

- 一套无损词法规则，包括 Unicode 标识符、字符串转义、数字边界、注释和成对分隔符。
- 每个 token、trivia 和声明保留原始源码范围。
- 标量、字符串、枚举、集合、对象和引用的值语法。
- 可选类型 `T?`、函数签名、表达式和函数体的类型规则。
- 默认值与 CFD 字段值的公共解析和校验。
- 诊断类别、严重级别和规范格式化规则。

## 4. 编译与加载关系

```text
CFT -> 契约编译 -> 不可变契约 -> 目标语言生成代码
                              |
CFD -------------------------> 契约加载、校验、链接和执行
```

CFT 的声明在编译期确定名称、类型、布局所需的语义信息和规则；CFD 的值在加载期依据契约完成类型
转换、默认值物化、引用解析、维度装载和 check。

## 5. 结果模型

以下四种结果彼此独立：

| 结果 | 产生位置 | 表现 |
| --- | --- | --- |
| 类型验证失败 | 数据或边界值进入执行环境前 | 诊断，阻止值进入 |
| 业务返回值 | 普通函数 | 普通返回类型、枚举或业务结构 |
| check 失败 | check 执行 | 可继续收集的结构化诊断 |
| 执行 fault | 执行不变量、预算、非法操作、未处理外部异常 | 绑定源码位置和调用信息的执行错误 |

语言不内建通用错误传播协议；`Option` 提供 `?` 传播，业务结果由普通返回类型表达。全部诊断与 fault
条件见 [11-错误与诊断](./11-错误与诊断.md)。

## 7. 语法记法

本文档集使用扩展巴科斯范式描述语法：

```text
:=        定义
|         选择
[ x ]     可选
{ x }     出现零次或多次
( x )     分组
"x"       终结符
小写名称   非终结符
```

规则只描述语法结构，不表达类型约束、名称解析或求值顺序；这些规则分别在各主题文档中定义。
