# Coflow 语言总览

> 状态：语言设计
>
> 范围：CFT 与 CFD 的共同语言规则。

## 1. 基本原则

- CFT 定义类型、默认值、函数和 check；CFD 提供记录和函数实现。
- 两者使用同一套词法、类型检查、表达式和执行规则。
- CFT 编译为只读契约。CFD 依据契约编译和加载，不修改或重新优化契约。
- 配置数据只读；函数可以修改自己的局部变量。
- 普通字段读取已保存的值；`fstring` 读取时生成普通字符串。
- check 是可选的特殊函数。检查报告不决定 Runtime 是否可用。
- 求值顺序、集合顺序和数值规则由语言规定。Host 函数的结果和外部行为由宿主负责。

## 2. 编译与运行

```text
CFT -> 编译 -> 只读契约 -> 目标语言代码
                     |
CFD -> 解析、类型检查、默认值补齐、函数编译、引用链接
                     |
                   Runtime
                     |
              读取、函数调用、可选 check
```

CFT 编译时尽量把已知计算变成常量。无法确定或超出优化预算时保留计算。
CFD 只编译自己的内容，直接使用契约中的默认值和函数代码。

普通记录引用可以成环。动态 `fstring` 按函数执行，循环读取由执行预算和调用深度限制处理。

## 3. 字符串与函数

```cft
type Item {
  name: string;
  label: fstring = f"名称：{self.name}";
  price: int;

  total: fn(count: int) -> int => {
    self.price * count
  };
}
```

`string` 是普通文本；`fstring` 只能用 `f"..."` 初始化，编译为特殊文本函数。
读取 `item.label` 得到本次计算的 `string`，不需要括号。
普通函数通过 `item.total(2)` 调用，`self` 始终只读。

## 4. 结果与错误

| 结果 | 含义 |
| --- | --- |
| 编译或加载诊断 | 类型、语法、必填值、引用或链接存在错误，不能正常构建 Runtime |
| 普通返回值 | 函数产生的业务结果 |
| check 报告 | 规则不满足或检查执行出错；Runtime 仍可使用 |
| 执行错误（fault） | 除零、越界、预算耗尽或 Host 异常等，结束当前调用 |

可选类型使用 `None` 和 `?` 传播。具体规则见[错误与诊断](./11-错误与诊断.md)。

## 6. 文法记法

`:=` 表示定义，`|` 表示选择，`[x]` 表示可选，`{x}` 表示重复，
双引号内为固定符号。文法说明结构；类型约束和求值规则以对应章节为准。
