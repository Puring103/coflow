# 命名空间

> 范围：声明名称、导入和局部名称。

## 1. 文件命名空间

```text
namespace-decl := "namespace" qualified-name ";"
use-decl := "use" qualified-name ";"
qualified-name := identifier { "::" identifier }
```

CFT 文件最多一条 namespace，位于所有导入和声明之前。
没有 namespace 时声明属于全局命名空间；目录和文件名不决定名称归属。
多个文件可以使用相同命名空间。

```cft
namespace game::combat;

use game::items::Item;
use Coflow::Check::require;
```

CFD 不声明 namespace，可以在基础记录与覆盖块之前 use 所需名称。
命名空间不负责发现或加载源码文件。

## 2. 声明解析

- 类型、enum、常量、顶层 check 和系统声明使用完整限定名。
- 同一命名空间禁止同名声明；不同命名空间允许同短名。
- 本命名空间可以使用短名，其他命名空间通过完整名称或 use 访问。
- 全局声明的短名就是完整名称。
- use 可以导入声明或成员，既不匹配或同时匹配两种目标时报错。
- 短名歧义和导入冲突报错，不根据文件加载顺序选择。

enum 成员使用 `EnumName::Member`；已有明确 enum 期望类型的数据位置可以使用变体短名。
对象成员使用点号。

## 3. 局部名称和 self

- 同一作用域禁止重复局部声明和绑定。
- 内层块可以遮蔽外层局部变量。
- 对象字段使用 self.field，局部变量可以与字段同名。
- self 保留且只读，不能被声明或遮蔽。
- 字段和命名 check 在类型及其继承链中禁止同名。

## 4. 系统名称

Coflow 是保留命名空间，系统声明不能覆盖。
require、records 属于 Coflow::Check。
现行 check 使用 require 提交诊断，用 records 接受静态类型并查询记录。

维度名与变体名写在顶层覆盖块头部，使用 `维度名[变体名]`，不占用记录 key 或类型名称。
维度字段的可覆盖范围由 CFT 注解指定。

## 5. 引用与 record key

record key 不受 namespace 改名，在同一份数据 的整棵记录继承树内唯一。
唯一域由最上层父类型及其全部后代组成；父子类型和兄弟类型共享 key 唯一域，
互无继承关系且没有共同父类型的类型分别拥有自己的唯一域。

例如 Left 和 Right 都继承 Root，Other 与它们没有继承关系：

| 两条记录 | 是否允许同 key |
| --- | --- |
| Root 与 Left 的记录 | 不允许 |
| Left 与 Right 的记录 | 不允许 |
| Left 与其进一步派生类型的记录 | 不允许 |
| Left 与 Other 的记录 | 允许 |

唯一性检查覆盖全部输入文件，不因文件路径、导入方式或类型所在命名空间不同而分开。
类型查询范围仍为指定类型及其子类型。指定 Left 查询时，不会因为唯一域相同而返回 Right 的记录。

- `&key` 等价于使用源码所在静态对象上下文的类型写出 `&Type::key`。
- `&Type::key` 指定其他类型，Type 使用正常名称解析。
- 无本类型上下文时使用带类型写法。
- 不进行跨类型的裸 key 猜测。

本记录类型上下文由源码确定。字段默认值和记录 check 使用声明所属记录类型；
CFD 基础记录与覆盖记录体使用头部指定类型。继承默认值保持父类型上下文，
实际子类型不改变查找范围。data 自身字段没有本记录类型上下文，使用带类型引用。

例如 Item 的默认引用写 `&target`，Weapon 和 Armor 都继承 Item。
即使默认值用于 Weapon，仍按 `&Item::target` 查找，可以找到 key 为 target 的 Armor。
引用结果仍须符合字段声明类型。

```cfd
owner: &game::characters::Character::hero,
```

详细值规则见[CFD 数据](./05-CFD数据.md)。
