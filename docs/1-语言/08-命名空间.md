# 命名空间

> 状态：语言设计
>
> 范围：CFT/CFD 共享的文件级命名空间、名称解析和导入。

类型、枚举、常量和内置 Host 使用统一命名空间机制。完整限定名全局唯一，不同命名空间允许使用相同
短名。系统保留 `std` 命名空间。

## 1. 语法

```text
namespace-decl := "namespace" qualified-name ";"
use-decl       := "use" qualified-name ";"
qualified-name := identifier { "::" identifier }
```

`namespace` 语句必须位于文件的所有导入和声明之前，一个文件最多一条：

```cft
namespace game::combat;

use std::Check::require;
```

- 不声明时，文件的声明属于全局命名空间。
- 多个文件可以属于同一命名空间；目录和文件名不决定名称归属。
- 命名空间不使用块状声明，也不负责加载文件。
- `::` 是命名空间路径分隔符，同时用于 enum 静态成员和带类型的记录引用。

## 2. 名称解析

- 完整限定名全局唯一。
- 本命名空间内可使用短名。
- 其他命名空间的声明通过完整名称或显式 `use` 访问。
- 支持成员导入，例如 `use std::Check::require;`。
- 全局命名空间中的声明以其短名作为完整限定名，因此在其他命名空间中可用该名称直接引用，或通过
  `use` 引入。
- 导入冲突和短名歧义直接报错。

```cft
namespace game::combat;

use game::items::Item;

type Monster {
  drop: &Item;
}
```

## 3. 系统命名空间

- `std` 是保留的系统命名空间。
- `coflow::dimension` 是保留的维度生成类型命名空间；它不参与普通短名解析，但维度数据记录的类型名按短名解析到该命名空间。
- 系统内置能力由保留的系统 Host 类型组织，统一参与名称解析、签名声明和类型检查。
- 系统声明不可覆盖。
- 应用 Host 由宿主绑定，属于应用命名空间。

```cft
namespace game::combat;

use std::Check::require;

type Monster {
  level: int;

  check {
    require(level > 0, "等级必须大于 0");
  }
}
```

`Check.require` 的调用规则见 [07-Check校验](./07-Check校验.md)。

## 4. CFD 中的名称解析

CFD 使用与 CFT 相同的类型名称解析规则：

- record 声明和字段中的 type marker 可以使用短名或完整限定名。
- enum 成员和带类型的记录引用通过 `::` 限定。
- 命名空间不改变 record key；record key 仍使用普通标识符并在其查询类型域中唯一。

```cfd
monster: game::combat::Monster {
  level: 10,
}
```

```cfd
owner: &game::items::Item::sword,
```
