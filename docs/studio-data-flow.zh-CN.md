# Studio 数据所有权与编辑发布

## 项目加载与共享源码

`coflow-project` 统一执行首次加载、缓存重建、诊断归属与索引发布。读写会话通过公开包装类型限制能力，共用构建管线。

每个 Project 持有共享的 `CfdSourceStore`。磁盘基线与未保存覆盖分别保存不可变源码快照，快照包含 `Arc<str>`、CFD AST 和语法诊断。内容相同的读取复用解析结果；加载器将已有语法树交给 Engine 完成 schema 指导的转换。嵌入式 LSP 复用 Project 的源码存储和初始 schema runtime。

文件写入成功、文件监听事件和文档关闭会使对应磁盘基线失效。项目整体刷新清空源码与文件列表缓存。未保存覆盖不替换磁盘基线。磁盘读取与缓存更新在同一临界区完成，避免失效事件之后重新插入旧快照。

来源批次保存记录草稿与加载诊断。缓存重建只重新读取受影响来源，并继续保留其他来源的诊断。模型构建借用批次中的记录及维度草稿，避免在 Project 和 Engine 之间复制嵌套字段树。模型解析、索引构建和项目 checks 仍对完整候选执行，以保证引用和全局约束的一致性。

## 源码保存事务

源码保存分为准备与提交：

1. 准备阶段校验文件归属，读取预期磁盘内容并构造候选项目。CFD 使用受影响来源重建；CFT 先构建候选 schema，再加载数据。
2. 候选绑定原写会话身份和版本。
3. 提交阶段验证会话身份、版本和预期磁盘内容，通过共享 staging 发布文件。
4. 文件发布成功后，直接采用已经构建的候选并递增版本，失效共享磁盘缓存。

准备失败、版本冲突或磁盘内容冲突均保留原会话。编辑器以短写锁执行提交，并从新会话生成 bootstrap。

## 提交发布与 schema 代际

编辑器的 `publish_commit` 统一推进数据版本、刷新诊断与引用缓存、更新导航计数并使 LSP 输入失效。普通 mutation 提供受影响文件集合，只重算这些文件的记录计数。类型目录由会话共享。已经转换的行直接提供列统计摘要。

`ProjectBootstrap.schema_revision` 标识 schema 编译代际。普通数据提交保持该代际；CFT 保存及完整会话重建推进代际。前端按会话和 schema 代际缓存枚举与默认对象，schema 更新时清除旧结果并拒绝旧异步请求。引用缓存按数据版本失效。

变更集由 mutation 收尾函数直接返回，生命周期归属当前响应。会话只保存当前项目及其派生索引。

## 记录变更与前端缓存

Project mutation 按坐标一次比较前后记录的字段、维度与来源，并纳入诊断实际变化的记录。跨文件移动同时更新原文件和目标文件。写入文件即使只有顺序变化，也进入变更集。

编辑器将变更转换为 `EditorChangeSet`：包含基线版本、目标版本、文件元数据、变化行和权威记录顺序。mutation 响应只通过变更集携带行数据，操作结果保留撤销所需的旧值、删除快照和位置。行转换仅处理选中的记录。前端以权威顺序处理插入、删除和移动，并保留未变化行的对象引用。基线缺失或不匹配时，通过完整文件查询取得目标版本。无变化操作复用同版本缓存，字段操作直接从变更集中取得返回行。

TanStack Query 是文件与图数据的唯一缓存。文件查询以会话和文件为键，版本属于缓存值；投影索引按 QueryCache 数据事件更新单个文件或图，并仅通知对应会话。读取器直接返回稳定引用，不扫描全部查询；图查询删除时同步释放相应索引引用。版本控制器决定发布顺序，旧请求在投影写入前取消且不回滚缓存，避免迟到快照覆盖新结果。未受影响的缓存文件沿用记录引用并推进版本。

乐观字段编辑、重应用与条件回滚集中在 `useOptimisticProjection`。回滚同时检查会话版本和当前字段值，避免撤销后续编辑。

## 边界与转换

- 集合编辑语义归属 Project，编辑器负责请求和结果适配。
- schema 字段顺序按实际类型缓存，图查询仅为展开节点构建字段数据。
- 嵌入式 LSP 直接传递 JSON 值，stdio LSP 保留标准分帧传输。
- IPC 入站转换接管新响应并原地转换整数；出站转换仅复制含 BigInt 的分支，保持调用方状态不变。

这些边界减少重复解析、草稿深复制和缓存副本。跨进程 JSON 序列化以及完整模型校验仍是数据发布流程的一部分。
