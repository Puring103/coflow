# 路径与生成文本处理

## 路径身份

Runtime 提供项目路径的统一入口，CLI、编辑器和 LSP 共用这些入口。

- `canonicalize_path` 使用 `dunce` 解析已存在的路径，返回平台标准形式并保留文件系统错误。
- `resolve_existing_or_future_path` 解析已存在的祖先，再接回尚未创建的后缀，供输出目录验证使用。
- `normalize_path` 提供文件索引、监听和删除事件所需的尽力规范化；需要严格验证的操作使用返回错误的入口。
- `project_path` 输出项目内相对标识；项目外文件保留绝对标识。
- `path_to_slash` 仅做显示转换，保留 Unix 根目录、Windows 盘符和 UNC 共享身份。文件系统操作使用 `PathBuf`。

路径归属使用路径组件判断。Windows 扩展路径由 `dunce` 处理，长路径或特殊路径保留其访问所需的表示形式。大小写无关的所有权比较使用 `normalized_path_identity`。

## Git 比较

传入 `gix` 的忽略规则路径为仓库相对路径。仓库外源码被排除并附带诊断；仓库内源码继续比较。HEAD 的输入路径映射到提交快照，绝对配置路径也按该映射读取。HEAD 依赖仓库外输入时提供仓库内源码差异和诊断，语义比较不可用。

## 生成文本

生成状态和生成发布共用文本等价规则：CRLF 与 LF 等价，文件末尾换行数量不影响状态；正文、缩进、行尾空格和内部空行参与比较。

C# 生成器固定输出 LF 和文件末尾一个换行，模板检出的换行格式不影响产物。

未变化的输出组不重新发布。需要发布的输出组中，内容等价的文件沿用磁盘原始字节；发生实际变化的文件采用生成器输出。所有输出继续通过 staging 保持发布原子性。

这些比较规则仅用于生成产物。CFD 数据、源文件写入冲突检查和编辑器内容修订保留各自的文本语义。
