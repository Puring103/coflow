# 语言核心实现契约

本文描述语言、模型、规则执行、宿主和生成代码之间的协作。具体语法由 [语言规格](spec/01-总览.md) 定义；用户用法由网站维护。

## 1. 模块职责

| 模块 | 责任 |
| --- | --- |
| coflow-language | 共享词法、CFT/CFD AST、schema 编译、规则与依赖索引、结构预算 |
| coflow-model | schema 引导的数据构建、默认值、记录身份、引用、维度有效值、模板求值与数据诊断 |
| coflow-checker | 不可变模型上的规则表达式、内联对象目标、执行状态、工作与迭代预算 |
| coflow-runtime | 项目输入、CFD 读写、规则任务规划、增量失效、诊断整合、只读查询、事务修改与发布 |
| coflow-format / coflow-lsp | 无损源码格式化，以及诊断、补全、导航、语义标记等编辑服务 |
| coflow-codegen / coflow-codegen-csharp | 生成数据类型与加载描述，不执行业务规则 |
| CFD editor | 显式值编辑、文本/模板选择、变体来源、诊断展示、撤销重做与代次管理 |

CLI、LSP、编辑器统一通过 runtime 使用项目状态；C# Loader 消费应用提供的 CFD 源码和生成描述。

## 2. 值、缺省与来源

`Option<T>` 表示值可为空；字段是否能省略只取决于显式默认值。无默认值的 Option 字段缺失时产生必填诊断；`= None` 是允许省略的明确声明。

Rust 模型构建、C# 加载、默认值物化、候选修改及 unset 使用相同契约。编辑器创建初值可以明确写入 `None`，其来源为类型初值，不能标记为 schema 默认值。覆盖块省略字段表示没有覆盖；被覆盖的整个对象内部仍按其 schema 验证必填字段。

schema 只提供 `string` 类型，源码仍区分字面量与显式 `f"..."`。模型保存模板来源与渲染结果，规范写回保持表达式种类。模型读写中的普通字符串不会因为包含花括号或类似模板前缀的文字而自动转换。编辑器正文输入按合法插值路径自动选择普通字符串或显式模板源码，其他花括号保持为字面文本。CFD 单元格和 CLI 表达式采用共同的 schema 引导转换，直接保留模板节点。

## 3. 身份与名称

记录业务身份使用 `RecordId`、`id`、`--id` 和 `--new-id`。`RecordCoordinate` 由实际类型和业务 ID 组成，可跨模型代次保存；`CfdRecordHandle` 是模型内索引，仅在所属代次有效。字典键、缓存键和 UI 的元素 key 保留各自语义。

词法仅保护当前结构词和字面量词，内建操作名称不全局占用业务名称。类型声明不能覆盖内建类型名；table/singleton 的固有 `id` 不能由字段重复声明，data 可以定义业务字段 `id`。目标语言关键字由生成器转义，生成成员之间的实际冲突仍由生成器诊断。

## 4. 维度与模板上下文

求值上下文是维度到变体的映射。字段直接读取使用基础上下文；CFT `.for(variant)` 为字段绑定维度选择变体。引用、内联对象、Option 和集合中的模板值继承当前上下文。模板插值路径只沿非可选的对象和引用字段访问，不穿过 Option，也不索引集合；末端必须是可转为文本的标量。

求值顺序为：

1. 按字段所属维度与当前选择查找显式覆盖。
2. 缺少覆盖时选择基础源表达式，包括 schema 默认值。
3. 在当前上下文中求值所选表达式，依赖继续继承上下文。
4. 未被选择的维度使用基础值，同名变体不会建立跨维度关联。

例如基础 `title = f"购买 {self.name}"`、日语只覆盖 `name` 时，title 的日语有效值仍会变化。有效值变化与显式覆盖存在性分开建模。

Rust 维度字段分别保存显式覆盖与全部已发现变体的有效值。`.hasVariant()` 判断显式覆盖，显式 None、空字符串和同值覆盖均为真；`.variants()` 枚举完整已发现变体集合。不可变模型通过 `Arc` 共享记录和索引，模型快照与投影来源不复制数据树。CLI 多维投影保留源表达式，选择变化时按完整选择重新构建有效模型；相同选择复用已有共享结果。组合视图按调用求值，不预计算维度组合笛卡尔积。

模板解析节点、循环检测和缓存包含读取上下文，不能复用其他上下文的渲染结果。引用形成图可以成环；模板求值依赖的实际循环产生来源诊断。基础值和已发现变体均参与加载验证。

C# 生成记录的普通属性返回基础业务值。`item.For("language", "ja")` 创建独立的同类型记录视图，链式 For 组合维度，不改变原记录。引用与内联对象沿视图上下文读取，视图内引用保持身份。加载器保留支持后续视图求值的材料与缓存，详见 [C# 生成与加载](02-api-runtime-design.zh-CN.md)。

## 5. 规则与执行目标

类型字段之后可声明多个命名或匿名规则，项目级规则也可以省略名称。命名类型规则身份为 `Type::Rule`，匿名规则按源文件和位置生成身份；同一继承链内命名规则不能重名，不相关类型可以使用相同短名称。父类型规则先执行，本类型规则按源码声明顺序执行。

schema 为规则保存名称、整个块的位置、消息及根语句依赖。公开规则身份不依赖语句下标；CLI 列表、检查选择、源码定位与符号查询使用同一身份。内部根语句索引用于依赖分析和执行细节。

任务目标包括项目、记录及内联 data。data 目标含宿主记录、对象路径与维度选择。基础目标路径相对宿主记录；维度目标保存字段名、变体和字段内相对路径，诊断输出补回完整字段路径。任务枚举沿拥有关系递归，覆盖对象字段、数组元素、字典值及 Some；None 与空集合不产生内联任务。引用目标作为记录独立安排，枚举不沿引用重复展开。

维度字段中的内联对象检查基础值与该维度全部已发现变体的有效值，路径与上下文进入任务去重键及诊断位置。默认值中的对象在实际使用处检查，诊断定位宿主并关联规则来源。

命中某条规则的任一根语句依赖时，增量规划重跑整个规则，以保持规则内停止语义。内联 data 以宿主顶层拥有字段为失效边界：修改基础字段重建该树及其变体任务，修改已有变体只重建对应变体树；删除、数组重排、类型替换同步清理该范围的旧路径诊断。无关字段和其他宿主的诊断继续保留。对象路径和维度上下文均参与目标身份。

检查状态保留上一模型的共享快照；写入影响与两代基础值、有效变体值及显式覆盖存在性的变化合并，以捕获跨记录模板造成的间接变化。跨记录静态依赖命中的 data 规则在所有对应拥有实例上重新执行，多个依赖先合并再扫描拥有树。新增或删除已发现变体改变 `.variants()` 的全局集合，重新执行完整检查。规划预算失败保留已有范围诊断，并报告请求不完整；下一代全量恢复后再复用增量状态。诊断存储仅保留失败任务，成功任务删除对应诊断槽。

## 6. 消息、位置与执行完整性

断言保留冒号消息；规则、when 和量词在块前使用同一形式，如 `check Price: "价格规则" { ... }`。块级消息使用外围作用域，元素绑定在量词体中有效。整体消息补充子错误的表达式、实际值和位置。

| 状态 | 含义 |
| --- | --- |
| passed | 语句或规则已执行且通过 |
| not_triggered | 根 when 条件未触发，没有执行其主体；整条规则的全部根语句均未触发时，规则汇总也使用该状态 |
| failed | 业务条件不满足 |
| evaluation_error | 表达式无法完成求值 |
| budget_exhausted | 执行工作或迭代预算耗尽 |
| not_executed | 因规则中断或请求预算而未执行 |

普通业务失败继续收集诊断；求值错误停止当前目标的该规则剩余语句，其他规则继续。请求预算耗尽后剩余任务明确为未执行。完整性独立于是否通过，求值中断不能报告为完整通过，也不能归为预算耗尽。

诊断包括稳定规则身份、CFT 规则或语句位置、CFD 数据来源、记录 ID、完整字段路径，以及 when、量词元素和维度上下文。CLI `--explain`、编辑器和 LSP 消费统一诊断结构。

CLI `rule list` 与 `rule inspect` 汇总整条规则；`check --rule Type::Rule` 只执行指定规则。检查结果同时提供整条规则汇总与根语句执行状态。集合统计、唯一性、记录关联和维度覆盖由现有只读查询命令公开，共享 schema、模型和来源语义。

## 7. 验证与文档维护

语言测试覆盖名称位置、重复规则、继承次序、显式默认值和模板源码；模型测试覆盖上下文传播、基础表达式回退、显式覆盖与循环；checker 测试覆盖内联拥有关系、量词、消息、状态及预算。runtime 验证修改后的重新规划、来源写回、CLI 选择、整规则汇总与诊断缓存清理。

C# 测试验证生成代码、Option 省略、独立视图、引用身份、多维组合、模板和显式覆盖；编辑器测试验证公开 DTO、文本/模板编辑与记录坐标。

当前规格、开发设计、网站用法和 skills 参考保持一致。网站参考通过 `scripts/sync-skill-references.ps1` 同步到用户技能。普通开发的必需门禁为 `cargo check --workspace` 与 `cargo test --workspace`；发布遵循 [AGENTS.md](../../AGENTS.md)。

## 8. 数值位宽与枚举

schema 区分 Int、Long、Float、Double，C# 业务类型和值描述符使用对应的 int、long、float、double。语言常量保留声明类型，引用常量只允许提升；默认值按消费位置展开。模型和 wire 使用 i64 / f64 承载数值，字段及容器的 schema 决定合法范围，float 保存已舍入到 binary32 的数值。写入前递归规范化目标精度并校验范围。

检查器保留字段、常量、Option 解包、字典键及集合投影的数值类型。混合运算先求共同类型，再计算并检查目标位宽；32 位整数溢出不能隐式变为 long。C# Loader 的常量节点携带数值类型顺序，读取时拒绝隐式缩窄。

enum 保存 is_int64，默认 int，@int64 使用 long。位枚举在符号解析阶段合成 None 和 Everything，schema、检查、补全和代码生成共享这些成员。用户成员检查与合成成员分开，合成组合值允许同值。@idAsEnum 的稳定数值受声明位宽限制，代码生成按当前有效 ID 求 Everything；内建成员不进入稳定 ID 分配。
