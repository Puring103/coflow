# 维度

## 1. 声明

维度为同一个字段保存基础值和任意数量的变体值。`@localized` 等价于
`@dimension("language")`。

```cft
table Item {
  @localized
  name: string;

  @dimension("region")
  price: int;
}
```

一个字段只能绑定一个维度。维度字段声明在 table 或 singleton 字段上并由继承保留；
覆盖块定位已有记录。注解保留字段的原始值类型。

## 2. 基础记录与覆盖块

基础记录按普通字段语法提供基础值，也可以使用 CFT 声明的默认值：

```cfd
sword: Item {
  name: "Sword",
  price: 100,
}
```

维度覆盖使用独立的顶层块：

```cfd
language[ja] {
  sword: Item {
    name: "剣",
  }
}

region[jp] {
  sword: Item {
    price: 120,
  }
}
```

```text
dimension-block := identifier "[" identifier "]" "{" { record-override } "}"
record-override := record-id ":" qualified-name "{" [ field-list ] "}"
```

- 外层名称是维度名，方括号内是变体名，两者使用普通标识符规则。
- 顶层名称后接 `:` 表示基础记录，接 `[` 表示维度覆盖块；语法解析不依赖 CFT 名称查询。
- 覆盖块内用类型与记录 id 定位已有记录，不创建新的基础记录。
- 只填写需要覆盖的字段；未填写的字段使用该记录的基础值。
- 被覆盖字段必须通过 CFT 注解绑定到该维度，值必须符合原字段类型。
- 覆盖替换整个字段值；对象、数组和字典按完整值替换。
- 只有原字段类型为 `Option<T>` 时，覆盖值才可以显式写 `None`。
- 未知维度、记录、类型、字段及不匹配的字段维度均产生加载诊断。
- 同一维度、变体、目标记录和字段的覆盖在全部来源中只能出现一次；不同字段可分散在多个块或文件。

## 3. 文件组织与变体发现

基础记录与覆盖块可以放在同一文件，也可以分文件保存。一份 CFD 可以包含多个覆盖块。
文件名和目录不决定维度或变体，不产生覆盖优先级。

项目加载 `data` 指定的来源，以及 `dimensions.<名称>.dir` 配置目录中的 CFD；重叠来源按路径去重。
例如基础记录放在 `items.cfd`，日语覆盖放在 `localization/ja.cfd`。将后者纳入项目 CFD
来源即可提供 `language` 的 `ja` 变体。变体名称由覆盖块声明。

变体集合由全部已加载 CFD 的覆盖块汇总。基础记录与覆盖块的来源顺序不影响覆盖结果；
目标记录在全部来源中解析。

## 4. 读取与回退

```cft
name
name.for("ja")
name.hasVariant("ja")
name.variants()
```

普通字段读取返回基础值。`.for(variant)` 在字段绑定的维度中选择变体；有显式覆盖时选择覆盖表达式，没有覆盖时选择基础表达式，再按该维度和变体上下文求值。可选字段显式写入的 `None` 是有效覆盖，不触发回退。

`.hasVariant(variant)` 判断该字段是否显式提供该变体，不比较值是否相同。显式 None、空字符串和与基础值相同的值都返回 true；基础值回退和模板生成的结果不建立显式覆盖。

`.variants()` 返回该字段所属维度在整个模型中发现的全部变体，按名称排序，并为每项提供与 `.for(variant)` 相同的有效值。空覆盖块同样声明变体，基础值不作为字典项。维度声明不规定必需变体；需要保证某个变体存在时，规则显式检查其名称。

```cft
table Item {
  @localized name: string;
  @localized title: string = f"购买 {self.name}";

  check Translations {
    all variant, text in name.variants() {
      name.hasVariant(variant): f"名称缺少 {variant} 变体";
      text != "": f"{variant} 名称不能为空";
    }
  }
}
```

模板中的 `self` 始终绑定包含模板的业务对象，内联对象使用自己的 self。上下文沿显式记录引用、字段引用、内联对象、数组、字典和 Option 传播。每个依赖字段只选择自身维度与当前上下文匹配的覆盖；不同维度使用同名变体时不相互混用。

例如基础 `title = f"购买 {self.name}"`，只有 `name` 声明 `language[ja]` 覆盖 `"剣"`，则 `title.for("ja")` 为 `"购买 剣"`，`title.hasVariant("ja")` 仍为 false。求值缓存和循环检测节点包含记录、路径、维度与变体，基础文本不替代变体模板的求值。

Rust 模型保留显式覆盖来源和有效值两个集合。`dimension_value(record, field, variant)` 查询原始模型的指定单维有效值：只选择该字段所属维度，其他维度读取基础表达式；该字段查询不继承模型的投影选择。`has_dimension_variant(record, field, variant)` 查询显式来源；`dimension_variants(dimension)` 枚举已发现变体。来源查询 `dimension_field_value` 保留缺失、显式 None 和显式值三态，用于编辑与来源定位。

加载验证包括基础上下文和每个已发现变体的完整单维上下文。未标注维度的字段也参与验证，因为其模板可能引用受覆盖影响的字段。每条记录在每个上下文共享一次结构预算；诊断携带实际出错记录、字段路径、来源与维度/变体。多维组合在显式请求该组合时验证。

## 5. 应用读取、编辑与来源

C# 业务字段直接提供基础值；记录的 `For` 返回可随使用位置选择的视图。一个应用可以同时保留多个不同视图：

```csharp
item.name
item.For("language", "ja").name
item.For("language", "ja").For("platform", "mobile").name
item.HasVariant(nameof(item.name), "ja")
item.Variants("language")
```

`HasVariant` 从字段声明取得维度，检查显式覆盖；`Variants` 枚举指定维度的全部已发现变体。视图选择继承已有维度选择，引用和内联值读取传播上下文。未知维度或未绑定维度的字段产生参数错误；未知变体选择基础表达式。

Rust 使用 `project_dimensions(schema, selections)` 建立对应的组合视图，通过返回模型的 `record(...).field(...)` 读取组合有效值。连续投影保留其他维度的选择，并替换本次指定维度；所有投影共享原始基础来源并重新求值所选表达式。例如先选择 `language=ja` 再选择缺少覆盖的 `language=fr`，字段恢复原始基础表达式，同时保留已经选择的 `platform=mobile`。未知维度返回诊断；未知变体按同样规则回退。

编辑器保留每个覆盖字段的文件与源码位置。修改已有覆盖时写回原文件。首次增加覆盖时，
默认使用 `dimensions.<名称>.dir`，并在该目录下镜像基础记录文件相对项目根目录的路径：
例如主体位于 `data/items.cfd`，维度目录为 `localization/`，新覆盖写入 `localization/data/items.cfd`。
自动创建要求配置维度目录且主体文件位于项目内；CLI 也支持通过 `dimension set --file` 明确指定首次写入的文件。
清除覆盖只删除该覆盖字段，基础记录保持原值。

基础记录重命名时同步更新各文件中的覆盖目标；删除基础记录时同步删除对应覆盖。
基础记录移动文件不改变类型和 id，因此各覆盖块继续定位同一记录。
