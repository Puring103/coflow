# 源码格式化

> 范围：CFT、CFD、check 与基础插值模板的规范排版。

本篇规定源码的共同排版规则；格式化核心、LSP 编辑转换及项目事务写入见
[源码格式化实现设计](../04-source-formatting.zh-CN.md)。

## 1. 原则

格式化只调整空白和布局，保留非空白 token、注释内容与源码顺序。
不补默认值，不求值模板或执行 check。输出幂等，未完成源码也尽量保持稳定布局。
使用 LF、两空格缩进，文件末尾一个换行，连续空行最多一个。

## 2. 通用规则

二元运算符和 = 两侧留空格，冒号与逗号后留一个空格。
::、成员点号与一元运算符内侧无空格。
顶层声明、记录和维度覆盖块之间留一个空行。
注解单独一行并紧贴声明，注释内容保持原样。

## 3. CFT 与 check

类型和 check 的左花括号与头部同行，块体展开。
字段、常量和别名以分号结束，check 声明块不增加分号。格式化保留已有分隔 token；补齐缺失分隔符由源码编辑完成。

```cft
table Item {
  name: string;
  label: string = f"名称：{self.name}";
  price: int;

  check PositivePrice {
    price >= 0 : "价格不能为负";
  }
}
```

## 4. CFD 与维度覆盖

基础记录与覆盖记录展开，字段分行，保留已有分隔逗号。
维度名紧接左方括号，方括号内变体名不留空格，右方括号与左花括号间一个空格。

```cfd
sword: Item {
  name: "Sword",
  price: 100,
}

language[ja] {
  sword: Item {
    name: "剣",
  }
}
```

数组、字典和内联对象按源码的单行或展开布局排版。

## 5. 插值模板

f 与开引号相邻。模板作为完整字符串 token 保留，模板文本、转义、文本花括号和内部路径均保持原样。
编辑器写回原模板，预览文本不进入源码。

## 6. 调用入口

`coflow format` 处理项目配置输入，`--file` 选择其中的文件，`--check` 检查格式，`--dry-run` 预览变化。`coflow format --stdin --language cft|cfd` 处理独立源码。项目通过全局 `--project` 指定，命令参数与结果见[CLI 设计](../../runtime-design/cli.md)。
