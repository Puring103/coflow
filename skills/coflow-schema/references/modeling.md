# 按业务边界选择模型

建模前明确：对象是否独立维护、是否被多个地方共享、是否有稳定身份、是否允许缺失，以及哪些值需要按语言或平台变化。关键约束未明确时询问用户。

## 选择声明

| 需求 | 选择 | 例子 |
| --- | --- | --- |
| 有独立身份、共享引用、单独增删 | table | 物品、任务、技能配置 |
| 整个项目恰好一条设置 | singleton | 游戏全局设置 |
| 只属于父对象的结构 | data | 属性、奖励参数、条件 |
| 固定命名分类 | enum | 品质、阵营 |
| 多个独立开关组合 | @flag enum | 权限、能力标志 |
| 记录 ID 需要强类型代码入口 | 空 enum + table 的 @idAsEnum | ItemId |

table 字段用 `&Item` 引用记录，data 字段用类型名内联。共享对象用引用，拥有值用内联；不要用普通字符串代替需要类型与存在性校验的记录引用。

## 选择字段

- 多个有序值用 `[T]`；按键查询用 `{string: T}`、`{int: T}`、`{long: T}` 或枚举键字典。
- 可空用 Option；可省略必须给显式默认值。业务关键值没有合理默认时保持必填，见[默认值与 Option](defaults-and-options.md)。
- 内联结构有多种形态时用 abstract data 与具体子类；独立记录分组用 table 继承，见[引用与多态](references-and-polymorphism.md)。
- 文本统一为 string。动态插值显式使用 f 字符串，普通文本保持字面量。
- 文本、数值或完整对象需要变体时，在所属 table/singleton 顶层字段绑定维度，见[维度建模](dimensions.md)。

## 放置规则

data 的自身约束写在 data check 中，可复用到所有嵌套实例；同一记录字段间关系放在 table/singleton check；跨记录关系放在顶层 check，并用 records(Type) 读取集合。

类型的字段都放在 check 之前。长期需要单独查询或执行的规则使用名称；匿名规则适合局部断言，其标识从 rule list 获取。规则只校验，不修正或计算写回配置。

## 编辑与代码需求

`@label`、`@description` 提供业务说明，`@expand` 为具体内联 data 字段提供表格展开信息。`@struct` 仅用于无基类 sealed data 的结构体生成；先按数据语义确定边界，再选择代码表现形式。

设计完成后用真实代表记录验证：必填项、空态、引用、每个多态分支、覆盖及规则失败的业务原因。完整示例见[从零创建](new-project.md)，已有结构的调整见[结构变更](schema-migration.md)。
